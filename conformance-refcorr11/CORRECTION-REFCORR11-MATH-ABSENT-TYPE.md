General absent-type rule derived from all cached Math captures. I scanned every cached live Math capture under `conformance-*` and `coord-units/*` (round5/5b/5c/5d P2 and R2/S1/S2 families) and cross-checked the reference token stream with fresh local harness re-renders of the exact cached sources. The rule is: Wikidot recognizes a Math environment type only from an exact lower-case `type="..."` attribute key; a missing exact lower-case `type` key always selects the fossil `equation` environment, whether the key is genuinely absent (`[[math]]` at R5DP2-20, `[[math E]]` at REFCORR3 `basic`, `[[math foo="bar"]]` at REFCORR3 `attr-unknown`, `[[math typeeq="align"]]` at r2c-04) or present only as a case variant of the NAME (`TYPE`, `Type`, `tYpE`, `TyPe`, `tYpe`, confirmed by R5BP2-08/09, R5CP2-11..16, r2c-01/02, s2c-13/14/16, s2d-29). Only an exact lower-case `type` key selects a non-equation environment, and its value is kept verbatim for the renderer's `^[a-z][a-z0-9]*$` validity check (`type="align"` at s2c-15, `type="gather"` at R5P2-17, invalid `type="ALIGN"` at R5CP2-17 and r2b, empty value cases), with the counter advancing once per block regardless of validity (live `(1)` / id `equation-1` for a single block, ids 3/4 across rejected blocks in the REFCORR3 probes). The REFCORR8 upper-case and REFCORR9 mixed-case fixes were special cases of this general rule; REFCORR11 removes the last exception, the REFCORR3 absent-type `align` default, which is retired on the fresh C-R5D-P2-4 evidence. Earlier rounds explicitly declined this flip (the REFCORR8 draft called it `changing the absent-type default back to equation would break the REFCORR3 probes and the cleared absent-type row`), but those rows were adjudicated on the no-op PNG surface or on variant-name shapes, and the new bare-opener capture is the first valid/stable/source-matching token-level measurement of the genuinely absent path.

Mechanism. `Text_Wiki_Parse_Math::process()` in `ref-php/text-wiki/Text/Wiki/Parse/Default/Math.php` builds `$args` through the inherited `getAttrs()`, which keys attributes by raw case, and the opener regex carries the `/i` modifier. Post-REFCORR3 it used `array_key_exists('type', $args) ? $args['type'] : 'align'`; REFCORR8/9 added a `$typeKeyVariant` scan that mapped case-variant names to the fossil `equation` while leaving the genuinely absent default `align`. REFCORR11 generalizes this to the single expression `array_key_exists('type', $args) ? $args['type'] : 'equation'`, dropping the now-subsumed variant scan: any missing exact lower-case `type` key, absent or variant, takes `equation`, matching every cached live capture. The positional label group stays a label, the exact lower-case value still flows verbatim to `Render/Xhtml/Math.php`, and the `math_id` increment ahead of validation is untouched, so counter ids and invalid-value handling do not move. Rejected alternatives: (a) keeping the REFCORR3 `align` default contradicts the valid C-R5D-P2-4 capture; (b) lowercasing every attribute key would make `TYPE="align"` validate as `align` and break REFCORR8/9; (c) a render-side change cannot move the compared token `type` field and is unnecessary because `Render/Xhtml/Math.php` already builds `\begin{TYPE} ... \end{TYPE}` from the stored type.
