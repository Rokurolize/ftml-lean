General rule 1 — evidence-bounded lead class extension. Live tolerates the REFCORR10 lead run (Unicode White_Space plus U+FEFF BOM plus `*` new-tab marker) and, as the round-5d evidence newly shows, also two Unicode Cf format characters immediately adjacent to already-admitted class members: U+200B is the byte successor of the U+200A endpoint `E2 80 8A` and U+2060 is the byte successor of U+205F `E2 81 9F`. The class is therefore extended by exactly those two code points, written as `E2 80 [\x80-\x8B]` and `E2 81 [\x9F\xA0]` in PHP and as `0x2000 <= cp && cp <= 0x200B` plus `cp == 0x2060` in the mirror. It is deliberately NOT generalised to all of Unicode category Cf: the full inventory of 40 cached `[[[<lead>_default:x]]]` sources (BEFORE-AFTER-TABLE.md, lead-capture section) shows live evidence only for these two Cf code points, while sibling format characters U+200C ZWNJ, U+200D ZWJ and U+2061..U+2064 have no cached live capture and remain unadmitted, and byte-zero NUL remains excluded. The byte-oriented no-`/u` invariant of REFCORR8/10 is preserved, so a malformed UTF-8 tail cannot switch the strip off; the unevidenced White_Space members remain admitted only through the principled Unicode property, as recorded in CORRECTION-REFCORR10-FREELINK-GENERAL.

General rule 2 — uniform multi-hash rejection once a route is present. The REFCORR10-HASHROUTE correction added `/#/` route support and, with it, a `strpos($raw, '/#/') === false` exemption on both multi-hash guards (`##` and `substr_count($raw, '#') > 1`). The exemption was too broad: a single `/#/` route contributes exactly one hash byte and needs no exemption, while a second hash byte from a trailing anchor (`foo/#/bar#baz`) or from a second route separator (`a/#/b/#/c`) must be rejected on live. Removing the exemption from both guards makes rejection uniform on the raw target; the route peel below still produces the href and the `foo/` auto label for single-route targets such as `foo/#/bar`, `foo/#/` and `/#/bar`, all of which carry one hash byte and still link. No display-text, slug, `extra`, transliteration, option-map or token-shape code changes.
