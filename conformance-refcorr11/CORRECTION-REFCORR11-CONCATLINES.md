# CORRECTION-REFCORR11-CONCATLINES — one general continued-div-block-boundary rule (2026-11-23)

This is a mechanism-unit draft for the coordinator to place under conformance-refphp/ after adoption; it changes no canonical file itself. It fixes C-R5D-P4-1 from REPORT-ROUND5D-P4.md using the cached captures and reference outputs of conformance-round5d-p4 (no new live probe was fetched). The decisive evidence is C07, source `alpha\\\n[[div]]\nbravo[[/div]]`, live_norm `alpha <div><p>bravo</p></div>` versus ref_norm `<p>alpha</p><div><p>bravo</p></div>`; the C17 plain-newline control normalizes identically on both sides, so the rule is specific to the backslash-continuation branch. The ftml source confirms the mechanism: preproc/whitespace.rs keeps the continued-div-opener line break and paragraph/mod.rs calls mark_wikidot_continued_block_boundary, which appends one LF to the current inline run and sets current_unwrapped so the text before the opener is emitted bare rather than inside a <p>.

The general rule. A backslash-newline whose next line is a standalone div opener (`/^\[\[div_?(?:[ \t].*)?\]\]$/i` applied to the space/tab-trimmed line) is a continued block boundary. The pair is joined with one space instead of the retained LF, so the opener no longer inherits a blank-line boundary from Div::process's doubled leading newline; the leading text of that line is left unwrapped by the paragraph stage while the opener still forms its own block. Ordinary continuations still drop the pair outright and join with nothing, and an authored same-line opener (no continuation) keeps its pinned paragraph wrapper. The lead text is carried in a non-compared side channel — PHP `$wiki->vars['continued_div_leads']`, Lean `ParseState.continuedDivLeads` (serState deliberately omits it as it omits `fatal`) — and Paragraph/paraProcess suppresses the wrapper only for a run that both holds a Div token and whose placeholder-stripped trimmed bytes equal a recorded lead. No compared token field or DocState field is added.
