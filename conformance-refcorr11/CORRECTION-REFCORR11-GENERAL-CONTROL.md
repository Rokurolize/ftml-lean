# CORRECTION-REFCORR11-GENERAL-CONTROL — make the live C0-control filter unconditional across footnote and bibitem bodies (2026-11-23)

This is a mechanism-unit draft for the coordinator to place at `conformance-refphp/notes/CORRECTION-REFCORR11-GENERAL-CONTROL.md` after adoption; it changes no canonical file itself. It follows the adopted REFCORR10 general token-aware footnote rule. Round 5d confirmed C-R5D-R3-1 and C-R5D-R3-2 (REPORT-ROUND5D-R3.md and conformance-round5d-r3/): REFCORR10 applied its C0-control filter only on the single-authored-break branch, so a form feed (0x0C) survives in the footnote body before a double-LF run or with no authored LF, and Bibitem's strip-and-retrim keeps a form feed and emits a separator space, where live purifyHtml purifies both. The evidence is the cached round-5/5b/5c/5d and suspect4c captures; no new live probe was fetched.

The general control-byte rule. Let D be the set of C0 control bytes that live's `purifyHtml` removes: every byte below 0x20 except TAB 9, LF 10 and CR 13, i.e. `[\x00-\x08\x0B\x0C\x0E-\x1F]`. D is dropped unconditionally from a footnote body or a bibitem body at parse time, on EVERY branch of the authored-break decision and in BOTH rules, before the break predicate and the empty-Raw visible projection are evaluated. PHP `trim` (and the Lean `isTrimByte`) exclude form feed 12, so relying on trim leaves FF in the fallback body; the filter must be explicit and branch-free. The REFCORR10 single-authored-break predicate still decides only whether empty-Raw placeholders (`\xFF<id>\xFF`) are retained so that the Newline rule emits `<br />`: a lone LF with a non-LF byte on each side keeps the control-pure placeholder-bearing body, while double-LF runs, bare or edge LFs and no-LF bodies take the control-pure re-trimmed visible path. Bibitem applies the same filter before its empty-Raw strip and re-trim, so an entry that is only empty-Raw placeholders plus a control settles as empty and emits no separator space. The stored `vars['bibitems'][$label]` state and the emitted token wire shape are unchanged; only the emitted body and the pre-existing `empty` flag value move. No compared field is added. The render-side separator logic in Footnoteitem.php and NotesRender.lean is unchanged and remains correct because the stored body is already control-pure.
