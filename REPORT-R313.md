## The pairing shape all five share

Each rule is a single preg_replace_callback pass (the shared pregScan combinator): the leftmost match wins, a match is fixed by the regex alone before process() sees it, and scanning resumes after the consumed match, so a callback returning its match unchanged still advances past the whole match and a callback returning the empty string still consumes it. Making PCRE's search order explicit is the whole modelling task. Strong, Underline, and Strikethrough share one body grammar, [^\s](?:.*[^\s])? under the /U modifier; /U inverts every quantifier's greediness, so the optional group is lazy (absent before present) and the inner .* is lazy, which makes the body candidates lengths 1, 2, 3, ... in increasing order, each requiring a non-whitespace first and last byte and no newline anywhere, with the first length whose following two bytes are the marker pair winning. That is the mirror's pairBodyLen scan, shared by all three rules through pairClaim. Colortext's groups are explicitly lazy instead, and Emphasis's rejection lives in process() after its match is fixed; both are stated per rule below.

## Per-rule mechanism and byte-form analysis

All five rules run on the byte-form view (the R3.2 obligation). None of the five patterns excludes the delimiter byte 0xFF from its dot or edge classes, so a pair's body (and Colortext's color) can span an earlier rule's placeholder whole: the placeholder's bytes are delimiter, digits, delimiter, all dot-matchable and non-whitespace, and a placeholder contains no newline byte, no |, no #, and no marker pair, so it can neither open nor close a pair nor end a color by itself. The one hard barrier is the newline byte: every dot in the five patterns excludes it and every edge class excludes it, so a literal newline in the byte form (one the Newline rule left in place, as at paragraph boundaries) blocks pairing across it, while a newline the Newline rule claimed is a placeholder and no barrier at all. Edge bytes are read as bytes: a body whose first or last byte is a placeholder's 0xFF is non-whitespace and claims, and an empty pair adjacent to a placeholder is consumed exactly as in plain text.

Colortext (/\#\#(.+?)\|(.+?)\#\#/): the search is a nested first-fit. Color candidates end at each | in increasing order (a | at distance zero is color content, the group requiring at least one byte), and for each candidate the body ends at the first ## at distance at least one; the first complete parse wins, and a failed body search extends the color to the next |, which the mirror's matcher loop reproduces by accumulating the pipe into the color on failure. A ## at distance zero in the body is content (its first # is consumed and the search continues from the second), and a newline anywhere in either group ends the match attempt at that position. The process claims a start and an end token, each carrying type then color in the reference's order; the color value crosses as a $bytes value when it spans a placeholder (the fuzz differentials carry such records, below), exactly as the reference's byte string does.

Strong (/\*\*([^\s\n](?:.*[^\s\n])?|)\*\*/U): the shared pairBodyLen search is the alternation's first branch and wins wherever it parses; the empty alternative (correction C1, the bare ****) is tried only after every non-empty length fails, and consumes the four markers with no tokens. The corpus carries the placeholder-spanning shape directly: battery case s33's restricted record shows a Strong pair whose body spans two Newline placeholders inside one paragraph (the same case is the stage's one consistency exclusion, for the full-pipeline reason stated below).

Emphasis (/\/\/(.*)\/\//U): the lazy body ends at the first // at distance at least zero (the mirror's emphCloseScan), and the match is fixed by that search alone; process() then decides the replacement: an empty body is consumed with no tokens (correction C1), a body opening or closing on a whitespace byte returns the whole match unchanged (the scan still advances past it, so a padded first-fit pair is never retried against a later closer), and any other body is claimed as a start/end pair carrying only type. The URL-collision shapes need no special case: Url runs earlier in the pipeline, and an unpaired //example.com/a has no closer and stays literal, while a paired one claims, as the R2 section recorded on all three sides.

Underline (/____|__([^\s](?:.*[^\s])?)__/U): the deletion alternative stands first in the pattern (correction C1), so four underscores at a scan position are consumed with no tokens before any pair is attempted there; the pair form is the shared pairBodyLen search. The C1 headline shape __a____b__ is two pairs, not a deletion: the first pair's closer takes the first two of the four middle underscores and the second pair opens on the last two, which the stage's scan-level worked example pins byte for byte; the deletion fires where four underscores stand at a position no earlier match consumed (a bare ____, the ____x____ run form in the fuzz set).

Strikethrough (/--([^\s](?:.*[^\s])?)--/U): the pair form alone, no correction and no extra alternative. The R2 section's recorded behaviors fall out of the shared scan: a padded closer is skipped because a body ending on the space before it is not a candidate and the scan continues to a later -- whose preceding byte is non-whitespace, and a real newline stops the pair because the scan ends at the newline byte.
