# Mirror consequence summary — R5F-S1 (source reading only, no elaboration)

Unit R5F-S1 ran no Lean invocation under the serial wrapper; every statement below is an inference from reading the canonical mirror source at `lean-ftml/LeanFtml/`, not a claim of elaboration. The four-adjacent U+FFFD digit class, the parity Email index family, Stage 2 frames and serving surfaces were treated as standing owned or cleared classes.

C-R5F-S1-1 (Div attribute control bytes, witnesses S07 ESC and S08 DEL). `ContainRules.lean::normalizeValue` at line 582 filters `!(b < 32 || b == 127)`, the exact byte twin of the PHP wide C0/DEL drop at Div.php line 58. The mirror therefore carries the same two-byte defect for `type`, `style`, `role`, `data-*` and the `class` caller. A narrowed filter that keeps TAB, LF, CR and ESC below 0x20 and stops dropping DEL is the symmetric repair; `rtrimAttrWs` (line 567) and the retained class caller `rtrimSpaceTab` must stay unchanged. Confidence in the transcription is high; confidence in the exact live byte set outside the two witnesses is derived, not observed.

C-R5F-S1-2 (Span attribute whitespace normalization, witnesses S09 data-* and S10 class). `ContainRules.lean::spanProcess` (line 273 onward) builds `restArgs` with `textVal v` directly from `getAttrsBytes`, and `InteractiveRules.lean::spanAttrFragment` (lines 974-981) emits the raw value with only the 0xFF clear arm. Neither path calls `normalizeValue`, so the mirror reproduces the raw leading and trailing spaces. The symmetric repair is to route each kept Span value through the same `normalizeValue` pipeline while preserving the authored-nonempty data-* key record (`spanAuthoredNonEmptyEq`, line 255) and the id branch. Confidence in the transcription is high.

C-R5F-S1-3 (Image technical attribute interior C0, witness S13 FF in class). `ParaRules.lean::imageTrimAttr` (lines 286-288) only calls `rtrimImageAttrWs` (line 277), which strips a trailing W run and nothing else. The mirror keeps an interior FF. The symmetric repair is to filter the live-discarded C0 set D from the same three technical values, reusing the already-narrowed `NotesRules.isLiveDroppedControl` predicate (NotesRules.lean line 213) so the notes and attribute families share one predicate. Confidence in the transcription is high.

Cross-mechanism note. All three candidates live in the attribute-value family and two of them are caused by the same underlying asymmetry: REFCORR12-NOTES narrowed the live-discarded control set for notes bodies but the attribute path in both PHP and Lean still uses the wider C0/DEL class, while the Image path uses no control filter at all. A single shared live-control predicate used by notes, Div, Span and Image would close C-R5F-S1-1 and C-R5F-S1-3 together; C-R5F-S1-2 additionally needs the Span consumer to actually call the normalizer. The coordinator should decide whether to correct these as one general attribute-family mechanism or as narrow per-rule patches, and should require one wrapped elaboration per pin before adoption.
