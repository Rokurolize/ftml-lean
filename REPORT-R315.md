## Per-mechanism byte-form analysis

Shared facts. All five rules are plain `preg_replace_callback` rules in the reference, so each mirror is a single left-to-right pass over the byte form with no rescanning of replacements, claiming tokens as it goes (the R3.2 discipline). Prefilter, the first pipeline rule, converts DOS and Mac line endings to Unix, so the working string a middle rule sees never contains a carriage return; a line start is exactly the subject start or the byte after a `\n`, and a line end is exactly a `\n` or the subject end, and the mirrors need no `\r` case for the multiline anchors. A placeholder's bytes are `\xFF`, digits, `\xFF`, none of which is a space, an underscore, a newline, or a run character, so no match of Horiz, Separator, Clearfloat, or Break can span or partially overlap a placeholder; Center's body can contain whole placeholders and the scanner splices them verbatim because it works on the byte form throughout.

Horiz (`/^([-]{4,})$/m`) and Separator (`/^([=]{4,})$/m`) share one scanner, `lineScan`, parameterized by the run byte: at a line start (a flag threaded through the scan, the Heading mirror's idiom: true at the subject start, after any newline byte, and after a claim, since the replacement ends in newlines), a run of at least four run bytes (the count is greedy, the whole run consumed) followed by a line end is replaced by `"\n"`, the token, `"\n\n"`, with no options. A failed ending steps one byte, after which the rest of the run is not at a line start and cannot start a match, as in the reference.

Clearfloat (`/^([~]{4,})(>|<)?$/m`) is the same scanner with the side-aware ending and a two-newline replacement head: after the tilde run, an optional single side byte (`>` or `<`) and then a line end. Trying the side byte first is the pattern's own greediness, and no backtracking case exists: when a side byte is present but no line end follows it, the bare ending cannot match either, because the side byte is not a newline (the `~~~~>>` defeat is a worked example). The replacement is `"\n\n"`, the token, `"\n\n"`, with the `side` option as settled by the probe.

Break (`/ _\n/`) is the literal three bytes space, underscore, newline, replaced by the bare token with no options (`breakScan`). The pattern needs no line-start condition, and the doubled shape `a _ _\n` claims exactly one token, at the second space (a worked example), because the first candidate's third byte is a space, not a newline.

Center (`/\n\= (.*?)\n/`) is the one rule of the five whose match is not line-anchored in the `^`/`$` sense: the pattern opens with a literal newline, so a Center line at the subject start cannot match, and the trailing newline is consumed, so a directly following Center line cannot match either (its leading newline is gone, and replacements are not rescanned; the consecutive-lines shape is a worked example, and the blank-line-separated shape, where both lines match, is in the authored corpus). The body is lazy and the dot excludes `\n`, so the body ends at the first following newline; `centerScan` splits the remainder at the first `\n` (`splitAtByte`) and splices the body verbatim between a start token and an end token (options `type` start/end, claimed in that order), the whole match replaced by `"\n\n"`, start, body, end, `"\n\n"`. When no closing newline exists after an opening, no later opening can match either; the scan steps byte by byte and finds nothing, as in the reference.
