## 1. Claim set (written before modelling, per BRIEF-G16.md step 1)

### 1.1 Input space and harness

The check enumerates all words `pick` of length `len = 0..=5` over `choices = TOKENS.len() + 1 = 12` symbols, so `sum(12^i, i=0..5) = 271,453` inputs. `TOKENS` is, in order, `"`, `'`, `a`, ` `, `.`, `...`, `<`, `>`, `<<`, `>>`, `é`; index 11 is the seam token. A pick is split at each seam index; consecutive non-seam tokens are concatenated into a segment, starting with one (possibly empty) segment. Thus a pick is exactly a finite list of segments over the token alphabet. Every seam falls between whole characters, so passing from UTF-8 byte offsets to character positions is an order isomorphism on this alphabet (`é` is two bytes but one character, all other tokens are ASCII); the model uses `List Char` with seams as zero-width markers and the conformance slice confirms the two views agree on all inputs.

For a pick the harness forms `with_blocks = segments.join(BLOCK)` where `BLOCK = [[iftags +zz-no-such-tag]]x[[/iftags]]`, preprocesses with `substitute_wikidot_deferring_conditionals`, splits back on `BLOCK` into pieces, wraps each join with a `DelayedElement::typography_boundary()`, calls `resolve_static_suppressions(.., true)`, concatenates the resulting `Element::Text` payloads into `got`, and compares with `expected = substitute_wikidot(segments.concat())`. The difference class is the character multiset difference `got - expected`, printed as `text-differs:` plus signed counts, with a `right-angle:` prefix when the pick contained `>` or `>>`.

### 1.2 The typography replacement function modelled

For this alphabet the general pass reduces to three replacements plus one deferral rule. All literal, link, math, block-attribute, date, number-unit and head-value protection ranges are empty on these tokens (no `[`, `@`, digits, `="`, etc.); the `iftags` block only supplies conditional edges. The surround-quote regexes require backticks, which are absent from the alphabet, so no quote branch fires either. The pass, in `substitute_wikidot_impl` order, is: left angle quotes, every non-overlapping `<<` to `«` (`LEFT_ANGLE_QUOTES`, typography.rs:74-77, 1211-1243); right angle quotes, each maximal `>` run of length n >= 2 to `floor(n/2)` copies of `»` plus one `>` if n is odd, but only when eligible (typography.rs:1257-1308); ellipsis, left-to-right non-overlapping `...` or `. . .` to `…` with `...` preferred at a tie (typography.rs:101-105, 1506-1535). Deferral (`conditional_deferral_spans`, typography.rs:808-869) marks the maximal run immediately after each `iftags` opener or closer when it starts with `<`, with `>`, or with a dot-containing `.`/` ` run; only the closer edges matter here, so the deferred runs are exactly the leading runs of segments after the first. The model's `leftAngleM`, `rightAngleZM` / `rightAngleNaiveM`, `ellipsisM`, `deferPrefix` and `segmentTypoM` are these rules one-to-one.

### 1.3 The seam join modelled

`flush_group` (seam.rs:199-278) concatenates preprocessed pieces, sorts and de-duplicates seam offsets, and asks `wikidot_seam_edits` (typography.rs:1011-1119) for edits. The model represents this join by interleaving `none` markers between the piece texts; markers are transparent to runs and cannot move under replacement, which is byte-offset-equivalent for this alphabet. The edit rules relevant here are: a `<<` match becomes `«` when its maximal `<` run touches a seam; a `>` run becomes paired `»` when touched by a seam, with the touch test `any seam < run_end` at position zero and `previous char != newline && some seam in [run_start, run_end]` elsewhere (this is the only place a leading `>` run can become eligible); an ellipsis match becomes `…` when its dot/space run touches a seam; and a space run of length at least two crossing a seam is replaced by one space (`collect_space_edits`, seam.rs:362-382). Edits are sorted by `(start, end)` and applied with a cursor; on this alphabet their ranges are disjoint. No dash, quote or control-element edit can arise.

### 1.4 The corrected expectation, precisely

Let `S = segments.concat()`. The corrected expectation `E(S, seams)` is the naive joined-string typography of 1.2 with exactly two amendments. **Rule Z (position-zero `>>` eligibility):** a `>` run starting at index zero is eligible for pair conversion iff a seam lies strictly before the end of that run; the naive oracle treats index zero as a line start and never converts such a run. Every other run keeps the oracle's eligibility test. **Rule S (seam space-run collapse):** every maximal run of spaces of length at least two with a seam strictly inside it is replaced by one space; the naive oracle retains the full run. The model's `correctedM` is exactly this composition, and `seamResolveM` is the seam join with `correctedM` applied to the joined marked stream.

## 2. Model and theorems (built and audited)

The model is `lean-ftml/LeanFtml/SeamTypography.lean` (302 lines), imported from `LeanFtml.lean`. It separates the faithful ftml path `ftmlSeamResolveM`, which preprocesses each piece and then resolves the seam, from the model's seam resolution `seamResolveM`, which is the seam-aware typography of the joined marked stream. The distinction is deliberate: the piecewise deferral/recover pass is an implementation detail of ftml, and its output is proved equal to the model's seam resolution by the exhaustive conformance slice rather than by a separate general induction; the model itself is the seam join plus the corrected expectation. The theorem `seamResolve_eq_corrected` states the model's resolution equals the corrected expectation, and holds by `rfl` because the corrected expectation is the definition of the resolution.

The headline theorems are `seamResolve_eq_corrected`, `position_zero_eligibility`, `seam_space_run_collapse`, and `seam_rules_compose`. `position_zero_eligibility` proves on the shortest run-at-zero witness that the corrected right-angle pass converts the leading `>>` while the naive oracle leaves it literal; `seam_space_run_collapse` proves on the shortest whitespace witness that the seam-crossing space run collapses while the oracle retains both spaces; `seam_rules_compose` proves both rules acting in the same stream produce the combined class's text. General preservation lemmas `charsOf_append`, `charsOf_map_some` and `charsOf_markPieces` establish that erasing seam markers is homomorphic and recovers the joined text, which connects the marker model to the harness's byte-offset view. The two rule theorems are stated on the shortest witnesses rather than quantified over all run lengths; the exhaustive conformance slice supplies the full quantification over the harness space. This scoping is recorded as an honest remainder, not presented as a broader theorem than was proved.

Every G1.6 theorem audits as `[propext]` only: no `Quot.sound`, no `Classical.choice`, no `sorryAx`. The only `sorry` occurrences in the project are the words in older comments.
