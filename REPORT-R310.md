# REPORT R3.10: the TABLE family mirrors (Table, Tableadv)

Stage R3.10 extends the mirrored pipeline from thirty-three rules to thirty-five, adding Table and Tableadv in reference order after Deflist, with a ConformanceR310 driver over `pipelineR310`. Both mirrors work on the byte-form view (`applyByteRule`), neither rule reads or writes document state (the R2 inventory stands: no counter is observable in either family's token options, so no compared-state extension and no canonicalization was needed), and the stage closes with the corpus, both fuzz seeds, and every R3.1 through R3.9 regression slice green.

## Per-mechanism byte-form analysis: Table

Table's pattern is `/\n((\|\|).*)(\n)(?!(\|\|))/Us`, and the mirror states the scan directly (`tableMatchAt`, `tableEndScan`): a newline, an opening `||`, then the lazy extension to the first following newline not followed by `||`, which makes every internal row line open with `||` and leaves a table whose last row line is unterminated at end of subject unmatched. The placeholders of the thirty-three earlier rules are `\xFF`, decimal digits, `\xFF`, so a placeholder contains no newline byte and no pipe byte: it can sit inside a row line (the normal case, an earlier rule's claim inside a cell, spliced back verbatim after PHP trim) but can never start a row, end a row, or split a `||` separator, which disposes of the brief's sharp edge by byte inventory. The Prefilter's frame padding supplies the boundary newlines the pattern needs at document start, which the mirror inherits from the frame stage (`framePad`) rather than restating. The process mirror (`tableProcess`) reproduces the reference's explode-and-loop step for step, including the row and cell token creation order with `table_start` and `table_end` claimed last (their placeholders wrap the rows in the replacement), the per-row span accumulation over exactly-empty cells, the two-byte alignment prefixes (`> `, `= `, `< `, `~ ` for header), and correction C2: a row with no content cell emits exactly one empty cell pair with span one and the accumulated span discarded. Two worked examples are proved in Lean (`tableMatchAt_example`, `tableProcess_example`), the latter pinning the full claim order and replacement bytes of a one-cell table.

## Per-mechanism byte-form analysis: Tableadv

Tableadv's pattern is `~\[\[table((?:"[^"]*"|[^\]])*)\]\]((?:(?R)|.)*?)\[\[/table\]\]~si`. The head group admits any byte but `]` (or a quoted string, which may carry `]]`), so a placeholder can stand inside a head, where the byte-form `getAttrs` mirror sees its bytes exactly as the reference does: a value spanning a placeholder is not valid UTF-8, so `normalizeValue`'s `/u` replacement fails and the value normalizes to the empty string, and a key carrying a placeholder byte fails the key grammar and is dropped. Bodies are lazy byte spans and routinely carry placeholders (a nested table's placeholder is the normal content of an outer cell); the nested-match recursion consumes a complete nested match, opener through its own closer, as one unit, and never splits a placeholder because the recursion is over the byte form, where the placeholder is bytes like any other and the nested pattern's own bytes are not among them. The attribute mirror (`buildAttrsAdv` over `getAttrsBytes`) reproduces the reference's `buildAttrs` with its owner argument: the case-sensitive key grammar (uppercase keys are dropped, not folded, which differs from List's filter), the safe-attribute allowlist of about one hundred names plus the `data-` prefix and the `aria-` prefix with a non-empty suffix, `title` and `hidden` always dropped, `colspan` and `rowspan` confined to cells and dropped at the exact value `0`, empty raw values dropped, `id` values passed through `isolateId` (the `u-` prefix, with the separating space exactly when the raw value does not start with a byte-mode whitespace byte) and every value through `normalizeValue`, with PHP array assignment semantics and a final byte-wise key sort. The process mirror reproduces the reference's failure shape exactly: the body is first rescanned for nested tables by the same scanner (the nested pass of `preg_replace_callback`), whose claimed tokens stay claimed even when the outer table then fails validation and returns its original matched text, leaving the nested tokens as orphans; the row grammar must consume the rescanned body with residue trimming to empty, each row's cell grammar likewise, a row that fails after earlier rows claimed their tokens leaves those tokens claimed, and header-ness is taken from the closer tag's name, not the opener's (correction C1). Token order per row is the reference's: every cell's start and end tokens first, then the row's start and end, and after all rows the table's start and end.

The matcher is a first-parse depth-first search (`tableadvMatchFirst`, `tableadvBodyFirst`) in PCRE priority order rather than the Code stage's outright parse enumeration, for a measured reason: a body holding k closed sibling tables has 2^k parses ending at later closers, all with equal rests, and an enumeration materializes every one (the stage's first fuzz run was OOM-killed at 6 GB on such shapes, and per-case bisection showed properly closed sibling sequences growing exponentially while the PHP reference walks the same cases in milliseconds). The search returns the enumeration's first member by one subsumption, recorded in the mirror's header: if some continuation succeeds after a nested match's later parse, the same continuation, reached by consuming the parse gap bytewise (which the body's `.` always permits, the pattern carrying /s), succeeds after the nested match's first parse and is explored earlier in the shared order, so a body search never needs a nested match's second parse. After the change the same fuzz shapes run in at most 0.2 s per case with linear scaling, and the corpus and both fuzz seeds confirm the equivalence empirically. The family's theorems are the two Table examples above plus five literal-pair theorems for the attribute step (`advAttrStep_id_example`, `advAttrStep_title_example`, `advAttrStep_span_owner_example`, `advAttrStep_span_zero_example`, `advAttrStep_data_example`): whole-rule Tableadv examples are not stated, because the attribute composition over `getAttrsBytes` output and the scanner's backtracking search do not reduce in the kernel at document scale (the compiled driver runs the same functions over the corpus in 0.12 s), so for Tableadv exhaustive conformance is the evidence, stated plainly as the brief allows. One mirror-internal bug was caught by the Table worked example before any differential ran (`tableEndScan` double-counted the opening `||`) and fixed in the mirror; no reference or oracle change came out of this stage.
