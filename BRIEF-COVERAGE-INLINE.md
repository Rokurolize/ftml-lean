# BRIEF-COVERAGE-INLINE — bring the INLINE render family to the coverage-tier standard

This codebase is yours: what it's for and how it's built are your call, and you'll keep building on it.

## Standing method (every lane in this programme)

Live Wikidot behavior is definitionally correct. Evidence order: (1) ftml corpus and integration pins, (2) frozen parity captures, (3) fresh live sandbox probes; fetch once, cache, reuse. Never edit ftml. Never run cargo. Never set a repository-local git identity, identity environment variables, or -c user.* overrides. Every Lean build runs through the serial queue wrapper: ~/.local/state/wikijump/muse-bhl/tools/lean-build.sh <workdir> lake build ... (never call lake directly for a full build). Write deliverables to disk as each part completes. Prose in files flows in single-line paragraphs, never hard-wrapped. Your tree is a full copy of the canonical programme tree at the post-REFCORR4, post-TABLEADV-FIX state; LeanFtml/CoverageProse.lean, LeanFtml/CoverageNotes.lean, REPORT-COVERAGE-PROSE.md, and REPORT-COVERAGE-NOTES.md are your pattern and your context.

## Mission

The coverage tier's standard, as established by the prose and notes families: state the family's input classification formally from the grammar and decision structure, prove in Lean that the classification is complete (a decidable predicate over the family's inputs, soundness, exhaustiveness, per-rule exclusivity), pin each class with live probe evidence validating the reference or with a retained battery pin, and fuzz within classes against the reference. Bring the INLINE render family to that standard: the render rules Url, Interwiki, Email, Freelink, Image, Span, Size, and Colortext, whose branch structure the R4 tier mirrored and the suspicion rounds then corrected (HTMLCHARS escaping, the X44 label bound, the Email ENT_SUBSTITUTE correction queued in REFCORR5, the Div-adjacent attribute behaviors). Your classification works from the CURRENT mirror in this tree; where a queued REFCORR5 correction will move a branch (Email's escaping, Colortext's parse-time validation is parse-side and out of this family's scope), classify the branch as it stands and name the queue item in the class's record rather than waiting for it. Name the module LeanFtml/CoverageInline.lean, as an imported library module like its two predecessors (append the import in LeanFtml.lean and stage your audit lines for Main.lean in a separate file the coordinator can merge, exactly as the earlier coverage lanes did; do not edit Main.lean yourself). Watch for the classify name collision the notes lane hit: check the existing modules' top-level names before choosing yours.
