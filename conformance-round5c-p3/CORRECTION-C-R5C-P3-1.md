# CORRECTION-C-R5C-P3-1 — Tableadv data-* key with a dot

Candidate `C-R5C-P3-1`, family Tableadv, confirmed by unit R5C-P3 on post-REFCORR9 ground (canonical commit `cfb792e86b3e4914a5761fe163929fda9d1b09fe`). The capture is valid, stable and saved-source-matching; decisive live bytes are `<table data-foo.bar="UB">\n<tr>\n<td>CELLX</td>\n</tr>\n</table>` at html_sha256 `a6cc4bc39427f6a4f878a356442556675d801f09180e7def17090cb22efb3cf8` and source_sha256 `dc8e5d32113db7bbf09673b27293d035c8c05143a1f46df0f425af6a6e08911d`. The canonical reference render, reproduced both through the include-aware scratch driver (`ref-render.jsonl` row 5) and through `harness/batch.php render` (`ref-batch.jsonl` row 5) with exit 0 and zero-byte stderr, is `<table>\n<tr>\n<td>CELLX</td>\n</tr>\n</table>`. The live table carries the folded `data-foo.bar` attribute while the reference drops it. This is a rule-level attribute presence and key value, not a serving surface.

Owning reference file is `ref-php/text-wiki/Text/Wiki/Parse/Default/Tableadv.php`. REFCORR9 C-R5B-P3-2 replaced the shared block-head gate for lower-case-prefixed data keys with the data-specific `preg_match('/^data-[a-z0-9_-]*$/', $key) !== 1` at line 158; the `.` byte (46) is absent from `[a-z0-9_-]`, so `data-foo.bar` folds at line 157 and is then dropped at line 159. The boundary siblings in this pass fix the mechanism: a trailing underscore, a digit-initial suffix, a mixed underscore-and-dash suffix, and the same underscored key on a cell head all survive on both sides, so the fold, owner sharing and prefix recognition are correct and only the data-* suffix character class is too narrow for live. The mirror transcribes the same mechanism: `lean-ftml/LeanFtml/TableRules.lean` lines 381-390 define `advDataKeyOk` with `.all` over `(97 ≤ x && x ≤ 122) || (48 ≤ x && x ≤ 57) || x == 45 || x == 95`, which rejects byte 46, and `advAttrKeyOk` routes folded data keys through it. Source reading therefore infers the same mirror divergence; this hunt unit ran no Lean elaboration. A fix owner must keep `advKeyOk` unchanged for non-data keys (the CoverageTable key-shape pin depends on it), keep the lower-case prefix recognition and the safe-allowlist, and relax only the data-* suffix grammar to the live character set without reviving aria-* or `align`, which remain dropped.
