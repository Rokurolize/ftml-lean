## The mirror (LeanFtml/Inline3Rules.lean, 650 lines)

Tt is the family's only parse()-overriding rule and the mirror's one structural departure from the shared `pregScan` plumbing: the reference collects all matches of `/{{({*?.*}*?)}}/U` over the original byte form with preg_match_all and calls process() per match with the original neighbouring bytes (`before`, `after`) and the original remainder (`tail`), so `ttScan` walks the original bytes itself, tracking the previous original byte; a matcher over the rewritten source would see a hoisted separator space where the original has the previous match's closing brace, which flips the next match's leading-separator decision on adjacent matches. The pattern's enumeration order under /U was settled by direct probes of the reference before mirroring (thirteen probe cases run through state-restricted.php with the single rule Tt): the opening `\{` run is greedy (lengths descending), the dot is lazy (lengths ascending, never crossing a newline), the closing `\}` run is greedy (lengths descending), and the first combination followed by the literal `}}` wins; the probes pin `{{a}}b}}` to body `a`, `{{a}}}}` to body `a}}`, `{{{a}}` to body `{a`, and `{{a}b}}` to body `a}b`. `ttMatchAt` enumerates exactly that order over candidate lists. `ttProcess` strips the body's space/tab padding, collapses interior space/tab runs to one space, suppresses an empty or exactly-"0" body (a padding-only empty body still emits one space, and a "0" body with padding emits nothing, dropping the padding), and otherwise claims the start/end pair and re-emits one separator space per stripped edge exactly when the original neighbour exists and is not whitespace, the trailing edge also yielding when the original tail opens with a padded `{{`. Superscript and Subscript are the Underline shape of R3.13: each pattern's deletion alternative stands first (`^^^^` consumed silently, the refcorr correction of the x87 crossing; `,,,,` likewise), then the shared first-fit pair scanner `pairClaim` of Inline2Rules is reused unchanged. Typography's parse() is a hand-written sequence of ten statements in which every addToken call is evaluated before its replacement runs, so the rule registers exactly thirteen constant character tokens in every document in statement order (``, '', ,,, '', `, ', <<, >>, space, space, ..., --, ---) and every match of a statement uses that statement's pre-assigned placeholder; the mirror claims the thirteen tokens up front (`typographyRule`) and rewrites the byte form statement by statement with those placeholders: three lazy quote-pair replacements whose bodies never cross a newline, the two guillemet literal replacements, the digit-space-digit replacement decided on the statement's input bytes (the pattern's lookbehind and lookahead), the number-space-unit replacement, the sequential str_replace of "..." then ". . ." (the placeholder contains neither dots nor spaces, so the second pass cannot match inside the first's output), and the two dash replacements (a run of n dashes becomes floor(n/2) placeholders plus n mod 2 dashes; the `---` statement is then dead and is implemented faithfully). The units alternation is modelled as candidate enumeration in PCRE depth-first order (`UMatch` matchers returning consumed lengths: literals, character classes, the decimal and hexadecimal entity forms whose `0*` is deterministic since no entity tail begins with '0', sequences, and optionals yielding present forms before the absent form); the first candidate whose following byte is absent or not [a-zA-Z0-9] wins, which is PCRE's backtracking through the alternation against the trailing negative lookahead. The money branch's last alternative is a bare `$` in the pattern text, an end-of-subject anchor rather than a literal dollar, modelled as `anchorM`: it matches the empty string at the end of the subject or immediately before a final newline, so a trailing "5 " (or "5 M") claims its space with an empty (or "M") unit group. Tighten performs the reference's five steps over the byte form (delete every newline byte, fold space/tab runs to one space, the per-token Colortext space hoist/eject pass in table order, fold again, the per-token Newline/Paragraph edge-trim pass in table order), reading rule and type from the token table at each token's list position; it writes no tokens. No compared-state extension was needed: none of the five rules reads or writes document state beyond the token table, and Tighten only reads it.
