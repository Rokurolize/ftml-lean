# CORRECTION-REFCORR13-FOOTNOTE-BREAK-WITNESS — evaluate the authored-break predicate before dropping discarded C0 bytes (R13-MATHNOTES, 2026-11-23)

This is a mechanism-unit draft for the coordinator to place at conformance-refphp/notes/CORRECTION-REFCORR13-FOOTNOTE-BREAK-WITNESS.md after adoption; it changes no canonical file itself. It is the symmetric reference-and-mirror response to confirmed C-R5F-R3-3 (REPORT-ROUND5F-R3.md, suspicion R3F-16, capture muse-probe-round5f-r3-r3f-16, source sha256 f4e529ffa287caada4910a059a6ffe9030f74fe96f61c0363e58d7cd9eb96934, html sha256 bb432df8890d2135f36163703e8b29bf527f6b078573f2347366a0182ff74311). Source `[[footnote]]<FF>\nX[[/footnote]]\n[[footnoteblock]]` serves the live footer `>1</a>.<br />\nX`, with a rule-level `<br />`; the post-REFCORR12 reference serves `>1</a>. X`. Both sides drop the FF from emitted text, so this is not an owned raw-control surface: it is the rule-level break value. No new live probe was fetched; the decisive capture and the cached REFCORR12 union are the evidence.

The general rule. Live stores the raw trimmed footnote body and lets Stage 2 purifyHtml remove discarded C0 bytes from emitted text only after the render pipeline has run. A discarded C0 byte immediately before a single authored LF is therefore a real inline witness for the Newline rule and must produce `<br />`. REFCORR11/12 dropped the live-discarded set D = [\x00-\x08\x0B\x0C\x0E-\x1A\x1C-\x1F] unconditionally BEFORE the authored-break predicate `/[^\n]\n(?!\n)/`, erasing the sole non-LF witness and losing the `<br />`. The fix reorders the two steps: evaluate the predicate on the control-bearing trimmed body; keep that control- and placeholder-bearing body verbatim in the single-break branch; drop D from the visible projection only in the fallback branch (double-LF runs, bare/edge LFs, no authored LF), exactly as under REFCORR11/12. A second, necessary render-side consequence is the separator decision: once a discarded byte is retained as a witness, it must not count as visible lead text. Live excludes the whole set D plus TAB/LF/CR/space from the separator class while keeping ESC 0x1B verbatim, so Fossil's `[^ \t\n\r\x0B\x0C]` is widened to `[^\x00-\x1A\x1C-\x20]`; this also settles the cached SOH witness R3E-03. No compared field is added and no count, id or token wire shape moves.

Mechanism. ref-php/text-wiki/Text/Wiki/Parse/Default/Footnote.php removes the unconditional line-71 D-drop and applies it only inside the `if (!preg_match('/[^\n]\n(?!\n)/', $content))` fallback, replacing `$visible = $stripEmptyRaw($content)` with an inline `trim($stripEmptyRaw(preg_replace(D, '', $content)))`; the single-break branch now stores `$content` unchanged. ref-php/text-wiki/Text/Wiki/Render/Xhtml/Footnoteitem.php changes its separator regex as described. The mirror is symmetric: lean-ftml/LeanFtml/NotesRules.lean `footnoteProcess` computes `hasSingleBreakByte preStrip` on the control-bearing trimmed body and applies `stripLiveDroppedControls` only to the fallback projection; `isLiveDroppedControl` itself is untouched. lean-ftml/LeanFtml/NotesRender.lean `footnoteLeadVisible` filters lead bytes by `b == 27 || b > 32` (ESC or above 0x20), the byte-class mirror of the revised PHP regex. Three pins that encoded the old order are restated with REFCORR13 names and the retained-witness value; all REFCORR9/10/11/12 fallback and ESC pins are unchanged and re-elaborate.
