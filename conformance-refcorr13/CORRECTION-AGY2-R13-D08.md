# CORRECTION-AGY2-R13-D08 — Math environment validation: strip `*` then apply the measured AMS allowlist (R13-AGY2, 2026-11-23)

This is a mechanism-unit draft for the coordinator to place at conformance-refphp/next/math/CORRECTION-AGY2-R13-D08.md after adoption; it changes no canonical file itself. It is the reference-and-mirror response to the hunt's confirmed divergence D08 in REPORT-AGY-HUNT.md, and it deliberately SUPERSEDES the acceptance decision of the already-adopted R13-MATHNOTES correction while composing with it only in the shared rejection of the round-5f `align2` witness. All evidence is frozen captures (agy-proof-policy/conformance-agy-hunt batch1/batch2/batch3, conformance-round5f-p2, conformance-round5b-r2, conformance-refphp/next/math); no new live probe was fetched.

The reconciliation, stated explicitly. R13-MATHNOTES narrowed `ref-php/text-wiki/Text/Wiki/Render/Xhtml/Math.php` from REFCORR3's `/^[a-z][a-z0-9]*$/` to `/^[a-z]+$/` to fix C-R5F-P2-2 (`align2` was accepted by the reference but rejected on live). D08 shows that a plain lowercase regex is wrong in BOTH directions. It still accepts arbitrary digit-free names that live rejects (`foobar`, `flalign` in m14a/m14b), and it still rejects starred AMS names that live accepts (`align*`, `gather*`, `equation*` in m06a/m06b/h08a). Therefore the live rule is not a regex over the authored name: live first removes every `*` character, then checks membership in a fixed AMS/LaTeX environment allowlist. The measured valid set is `equation`, `align`, `gather`, `eqnarray`, `multline`, `split`; `foobar`, `flalign` and `align2` are rejected; `a*b` is stripped to `ab` in the rejection text. The D08 rule SUPERSEDES the R13-MATHNOTES acceptance semantics rather than composing as a second regex: a name must be in the allowlist after stripping, and every allowlist member happens to satisfy `^[a-z]+$`, so the new predicate is a strict refinement that implies the old rejection of digits, uppercase, empty and trailing-space values. It COMPOSES with R13-MATHNOTES only in the sense that `align2` stays rejected — as a consequence of allowlist membership, not because the old regex is layered on top. No cached case distinguishes a larger allowlist from this six-name set, so the set is the measured minimum; extending it needs a fresh live probe, which this unit does not permit.

Mechanism. The parse side is untouched: `Parse/Default/Math.php` keeps the verbatim `type` value and the counter advance, and the mirror `NextRules.mathProcess`/`mathAttrs` keep the same wire shape. In `Render/Xhtml/Math.php` the validator becomes `$env = str_replace('*', '', (string) $type); $amsEnvironments = array('equation','align','gather','eqnarray','multline','split'); if (! in_array($env, $amsEnvironments, true)) { ... unsupported with $env ... }`. There is no trim and no case folding, matching the cached `align ` and `ALIGN` rejections. The LaTeX envelope name also uses the stripped `$env`, which is the value live puts in `\begin{...}`; the MathJax/PNG wrapper shape itself is the known external LatexRenderer boundary and is explicitly NOT changed — the harness still takes its fossil no-op failure block for the valid arm. In the mirror, `ServingRules.mathAmsEnvironments`, `mathStripStar` and the rewritten `mathTypeValid`, plus `renderMath`'s stripped error name, are the one-for-one definitions; `CoverageCodemath.lean`'s prose descriptor is updated, and all pre-existing pins in `ServingRender.lean` and `SpecRefcorr13.lean` still hold by rfl (their only digit-bearing case is `align2`, still rejected with the same message).
