# CORRECTION-AGY2-R13-D10-D11 — Button and Tabview falsy/absent guards plus the strict-empty sibling audit (R13-AGY2, 2026-11-23)

This is a mechanism-unit draft for the coordinator to place at conformance-refphp/next/CORRECTION-AGY2-R13-D10-D11.md after adoption; it changes no canonical file itself. It responds to hunt confirmations D10 (`Button` `set-tags` rejects `text="0"` and `text=""`) and D11 (`Tabview` renders a literal `0` label for `[[tab 0]]` and `[[tab title="0"]]`). All witnesses are frozen agy-hunt captures; no new live probe was fetched.

D10 rule and mechanism. `Render/Xhtml/Button.php` tests `if ($type === 'set-tags' && !$text)` at line 100, which rejects every PHP-falsy `text`. Live guards only a MISSING `text` attribute, so `text="0"` and `text=""` pass the guard, then the later falsy default `if (!$text) $text = $defaultText[$type]` finds no `set-tags` entry and leaves an empty label: live serves `<a class="wiki-standalone-button" href="javascript:;" onclick="WIKIDOT.page.listeners.updateTagsByButton(event, '')"></a>`. The minimal patch changes that one guard to `!isset($text)`; the later falsy default is left intact because it is what reproduces the empty anchor. Verified firsthand: pristine harness renders the error block for m08a/m08b, patched harness renders the anchor; the 472-source sweep changed exactly three Button rows (m08a, m08b and the combined h16a source), all D10 witnesses. The PHP warning for the absent `set-tags` default is pre-existing harness stderr noise, not emitted HTML, and is not part of the comparison.

D11 rule and mechanism. `Parse/Default/Tabview.php::_tabTitle` used `if ($text === '') return 'untitled';` after trimming, so the string `"0"` survived as a visible label. Live uses a PHP falsy test: after trim, both `""` and `"0"` default to `untitled`. The minimal patch changes that one test to `if (! $text)`. Verified firsthand: pristine harness renders `<em>0</em>` for m09a/m09b, patched harness renders `<em>untitled</em>`; the sweep changed exactly three Tabview rows, all D11 witnesses. The raw-code/placeholder and whitespace-collapse arms of `_tabTitle` are untouched.

Strict-empty sibling audit. `evidence/AUDIT-STRICT-EMPTY.md` inventories all 134 active `=== ''` sites under `ref-php/` after the patch (fossil-era `.before-*` backups excluded) plus the one site removed by D11. The only strict check with a measured falsy-zero divergence is the Tabview `_tabTitle` site. `Parse/Default/Tt.php:143-144` explicitly tests `$body === '0'` alongside `$body === ''`, so its strict handling of zero is intentional and is NOT relaxed. Cached C23 (`muse-probe-agy-hunt-h20c-toc-greedy-title0`, `title="0"`) is byte-equal on live and ref, confirming that strict handling there is correct. The remaining sibling sites have no cached falsy-zero witness; because no new probe is permitted, they are left unchanged and are explicitly recorded as audited-but-unmeasured rather than silently cleared.

Mirror. `InteractiveRules.renderButton` changes its `set-tags` guard from `!phpTruthyBytes text` to `(omGet opts "text".toList).isNone`, and `CoverageServe.buttonModeOf` makes the same change so the coverage classification agrees; `btPrimary`/`btClasses` no longer route a present-but-falsy `.setTags` to the empty-text class, and the `bt_ok_nonempty` witness for that shape is updated. `ContainRules.tabTitle` changes `t.isEmpty` to `t.isEmpty || t == litBytes "0"`.
