# CORRECTION-REFCORR13-MATH-ENV-ALPHABET — Math environment alphabet rejects digit-bearing names (R13-MATHNOTES, 2026-11-23)

This is a mechanism-unit draft for the coordinator to place at conformance-refphp/next/math/CORRECTION-REFCORR13-MATH-ENV-ALPHABET.md after adoption; it changes no canonical file itself. It is the symmetric reference-and-mirror response to confirmed C-R5F-P2-2 (REPORT-ROUND5F-P2.md, conformance-round5f-p2/CANDIDATES.md, suspicion R5FP2-11, capture muse-probe-round5f-p2-r5fp2-11). Source `[[math type="align2"]]\nx\n[[/math]]` serves the live rule-level block `<div class="error-block">Unsupported math environment "align2"</div>`, while the post-REFCORR12 reference accepts the name through `^[a-z][a-z0-9]*$` and requests the `align2` LaTeX envelope; the harness PNG stub's generic failure block is a serving surface and is not the basis of the confirmation. All evidence is the already-cached round-5f capture and the cached Math regression battery; no new live probe was fetched.

The general rule derived from all cached Math captures. REFCORR3 generalized the environment validator from a two-name whitelist to any lower-case name on digit-free evidence only (`align`, `gather`, `equation`, `eqnarray`); every cached valid name since has been digit-free, and `align2` is the first measured digit-bearing name. Live rejects it, so the accepted alphabet is one-or-more lower-case letters, `^[a-z]+$`, and the decimal digit is removed from the tail class. The rule is deliberately minimal: no name whitelist is introduced, because no cached case distinguishes a digit-free arbitrary name from a standard environment, and no new probe is permitted to settle it. An empty value, an upper-case value and every case-variant attribute NAME keep their REFCORR3/8/9/11 dispositions, and a missing exact lower-case `type` key still selects the fossil `equation` fallback under REFCORR11.

Mechanism. The parse side is unchanged: ref-php/text-wiki/Text/Wiki/Parse/Default/Math.php keeps the verbatim `getAttrs()` value (`array_key_exists('type', $args) ? $args['type'] : 'equation'`), the math_id counter still advances before validation, and the mirror lean-ftml/LeanFtml/NextRules.lean `mathProcess`/`mathAttrs` keep the same wire shape; neither file is touched by this correction. The decision moves only in the validator: ref-php/text-wiki/Text/Wiki/Render/Xhtml/Math.php line 46 changes `'/^[a-z][a-z0-9]*$/'` to `'/^[a-z]+$/'` with the REFCORR13 comment; the symmetric mirror lean-ftml/LeanFtml/ServingRules.lean `mathTypeValid` changes its tail predicate from `(97 <= c && c <= 122) || (48 <= c && c <= 57)` to `97 <= c && c <= 122`. The prose descriptor in CoverageCodemath.lean is updated, and ServingRender.lean gains the rfl pin `math_unsupported_digit_bearing`. No compared field is added, no spec or gate file changes, and the render branch for every cached digit-free value is untouched.
