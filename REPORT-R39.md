## Byte-form analysis: the native mechanism

The base-class pass is a single left-to-right scan whose matches are never rescanned; the mirror is an explicit line scanner (`nativeScan`, `nativeRunAt`, `nativeRunExtend`), so the byte-form obligation binds by construction. The outer pattern is '/^((\*|#).*\n)(?!\2 |(?: {1,}((?:\*|#) |\n)))/Usm'. Three facts shape the scanner. First, a run can only start at a line start with marker plus exactly one literal space, and its first line must be newline-terminated or the match fails outright (the pattern's `.*\n` cannot be satisfied), including when a would-be extension line is unterminated: extension is forced line by line, and the candidate ends of the run are exactly the successive line ends, because the ungreedy group must stop at the first end where the negative lookahead succeeds. Second, the lookahead at a run end succeeds (the run ends) unless the next line repeats the run's **first-line** marker at column 0, or is indented by at least one literal space and then starts with either marker or is blank; an indented line therefore continues the run regardless of its marker, a column-0 marker switch ends it, and a continuation line ends it (case b03's restricted behaviour). Third, blank-line handling falls out of the same lookahead: a blank line at column 0 ends the run (the z04 shape, where an all-empty run's replacement is empty and the surrounding newlines are all that remain).

`process()` is mirrored as a collector plus a stack machine. The collector applies the inner pattern '=^( {0,})(\*|#) (.*)$=Ums' per line: depth is the leading-space count (the split point is forced, since the marker must be the first non-space byte), the body is the text after marker and one space, left-trimmed of spaces and tabs. The filter drops an item whose PHP-trimmed body is empty unless the **next raw** item is strictly deeper. Counters are assigned after dropping, per depth, resetting when the machine unwinds past a level. The stack machine's asymmetries are pinned by the corpus and stated in the mirror: when depth skips, `sublist_start` carries the **new** (deeper) level while `sublist_end` carries the **parent** level being closed (case d04); the first newly opened level has `in_sublist` false and deeper ones true; every level opened by one item takes that item's marker type, while a level's `list_end` takes the type of the item that opened the level, and item tokens always take the current item's type. A run with no surviving items replaces with the empty string; any other run is wrapped in `"\n\n" ... "\n\n"`.

## Byte-form analysis: Deflist

The outer pattern is '/\n((: ).*\n)(?!(: |\n))/Us': the match **includes the newline before the run**, the run's first line must start with `": "`, and the run extends line by line while the next bytes start a further definition line or are a blank line — blank lines and separator-less `": "` lines are consumed into the run rather than ending it (def07 is one run across a blank line; def30's second line is consumed and vanishes). The mirror is a byte scanner over the same forced-extension argument as the native mechanism. The inner scan '/^(: )(.*)?( : )(.*)?$/Ums' is tried at every line start of the run, with PCRE's alternation order made explicit in `defItemAt`: the term group is first attempted **absent** (which requires `" : "` immediately), then present with the shortest dotall term followed by `" : "` — the term may span lines of the run — and the definition runs to the first position where the line can end (the first newline, or the end of the run). A run with no inner matches collapses to a single `"\n"` (the consumed newline is kept, the run text vanishes). Otherwise the replacement is `"\n"` ++ tokens ++ `"\n\n"`, each item emitting its term tokens only when the trimmed term does not render empty, where "renders empty" strips `\xFF<digits>\xFF` placeholders before trimming (`termRendersEmpty`, mirrored as `stripPh` plus `trimBytes`); the definition is emitted trimmed regardless. Token options are exactly `{type}` with the six types list_start, term_start, term_end, narr_start, narr_end, list_end, under the rule name **Deflist**.

## Byte-form analysis: the explicit block forms

`List::parse()` runs the native pass first, then, only if the source contains `[[ul` or `[[ol`, the explicit pass. The pass is a rescan loop (the reference's 500-iteration guard): scan all tags, walk a stack, pair the **first closer that has a partner** with the **topmost matching opener**, build that one block, splice, and repeat; then finalize boundaries. The tag pattern is case-sensitive (lowercase only): an opener is `[[`, `ul` or `ol`, an optional scored `_`, and an optional attribute group that requires at least one whitespace byte, a first capture byte that is neither whitespace nor `]`, and a capture running to the first `]` (a space-only argument region therefore stays literal, as does a scored `[[li_]]`, which the `[[li]]` pattern does not match either); a closer may consume a residual third `]`, which becomes the literal trail `"\n]"` appended after the end placeholder in the replacement text (it is not stored in the token; the end token's `trail` option starts as the empty string and is only ever mutated by item formatting and by finalize step (e)).

`buildExplicitListBlock` is mirrored operation for operation, including token creation order, which the corpus pins (in the `[[li]]` path the item tokens precede the wrapping list tokens in table order while the placeholder string order is start, items, end). Masking runs first: already-built nested explicit blocks occurring in the body are replaced by `\x02EXPLIST_<n>\x03` placeholders (per-build counter, consumed blocks leave the registry), then level-0 native list spans found by walking the body's placeholders against the global token table are replaced, right to left with counters assigned in reverse span order, by `"\n" ++ \x02NATLIST_<n>\x03 ++ "\n"` with surrounding newline runs absorbed. With `[[li]]` items present, text between items is discarded except that nested-block placeholders harvested from each between-segment attach to the previous item (or become pre-nested wrappers, emitted first with their end trails cleared, when they precede the first item); each item is shaped by `formatExplicitLiItem`, whose four branches are mirrored exactly, including the branch that inserts a token of rule **Newline** directly (List creating another rule's tokens is a reference behaviour, also seen in finalize), the unconditional appending of attached nested blocks with an `explicit_raw_nl` token and a `"\n"` end trail each, and the fact that only the fallback branch restores masked placeholders in the body itself while the other branches splice the masked span directly. A block with no surviving items and no pre-nested wrappers dissolves into one `explicit_empty` token behind a `\x02EXPDISSOLVED\x03` marker. Without items, an empty trimmed body dissolves the same way; a body of only masked lists and whitespace is wrapped in `explicit_inline_wrapper_start`/`end` (the `multi` flag — more than one list — drives the wrapper's `newline` and `lead_nl` options, the nested spans' `"\n"` end trails, and `explicit_raw_nl` separators before native spans after the first); any other body becomes one `explicit_none_item` around the restored trimmed body.

Attributes go through the reference's `buildListAttrs` (the F-R2-86 allowlist): only id, class, style, role, type, and `data-*` survive, emitted in that fixed order with `data-*` keys lowercased in insertion order; values are normalized (control bytes stripped, whitespace runs collapsed to one space, space-trimmed); id is `u-`-isolated (an empty or placeholder-bearing value unsets it, a value already starting with `u-` is kept, a raw value starting with whitespace becomes `"u- " ++ normalized`, otherwise `"u-" ++ normalized`); a placeholder-bearing class/style/role/type or `data-*` value becomes the empty string rather than unsetting the key.

Finalize (`finalizeExplicitListBoundaries`) first removes dissolved markers (keeping the empty token's placeholder, dropping one following newline), then per registered block, in registration order with positions re-searched in the current source: (a) after a single-newline-separated non-empty previous line containing no `||` and not ending in the token delimiter, an `explicit_br_no_nl` token plus `"\n\n"` is inserted before the block; (b) a following table-row tail (`[[/cell]]` or `[[/hcell]]`, `[[/row]]`, `[[/table]]`, case-insensitive, whitespace-tolerant) followed by a newline and a non-newline byte gains `"\n\n"` after the tail; (c) a newline run before another registered block's start placeholder is removed; (d) if only newlines (or nothing) follow, an unscored block gains a trailing `Newline`-rule token; (e) if exactly one newline follows before other content not starting with the delimiter or `[[`, the end token's trail is set to `"\n"` and the newline is dropped. Steps (b) and (c) end the block's processing, as does (d).

## State disposition

No compared-state extension and no harness change: List and Deflist keep no parse state beyond the token table. The explicit-block registry is internal to a single List pass (it is created empty at the start of `parseExplicitLists` and consumed by finalize), and the two counters it uses (the masking counters) are per-build locals; unlike Collapsible's and Tabview's class statics at R3.8, nothing here persists across documents or rides outside the compared segments and tokens, so compare.py needed no change at all this stage. The end-token `trail` mutations are ordinary writes to the compared token table, performed by the mirror through a table update (`setTrail`) at exactly the points where the reference mutates its stored token.

## Theorems and the honest remainder

Seven worked examples are kernel-checked in ListRules.lean and audited in Main.lean, all at [propext, Classical.choice, Quot.sound]: a two-item native run match; a one-item native process (the full token lattice and wrapping); a definition item match; a one-item Deflist process; the attribute allowlist example (id isolation, a dropped non-allowlist key, a lowercased `data-*` key, fixed emission order); an explicit block's complete token sequence under `listRule` (item tokens before list tokens, the finalize `Newline` token last); and the Deflist no-claim identity on plain text. As with the earlier stages' fuel-based scanners, the general equivalence claim for this family is the exhaustive differential conformance over the corpus and the two fuzz seeds, not a general inductive theorem; the report states this plainly rather than dressing the examples up as more than they are.

Two modelling boundaries, both inherited from the reference's own design and unreachable on this corpus by construction: the masking placeholder byte strings (`\x02EXPLIST_<n>\x03`, `\x02NATLIST_<n>\x03`, `\x02EXPDISSOLVED\x03`) appearing literally in user text (the reference itself would misread them; the fuzz generator therefore never emits raw `\x02` bytes), and a masking-map lookup miss inside item formatting (the reference would emit PHP notices and null-derived bytes; no corpus or fuzz case reaches it, since every masking placeholder in a body is created by the masking step itself).
