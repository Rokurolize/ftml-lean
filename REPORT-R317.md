## Per-rule mirror notes and oracle probes

Anchor is the only one of the six that overrides parse(): it runs parseNamedAnchors, then parseAnchorElements, and the mirror keeps that shape (namedAnchorScan, then anchorElemMatches plus anchorElemFold over the named pass's output, with the fold's registrations written back to the document state). The named pass's pattern decomposes uniquely (exactly one space or tab after `[[#`; the name group forced maximal over bytes that are neither newline nor `]`; then `]]` and an optional residual `]`), and its four outcomes are mirrored in the reference's order: a name trimming to empty leaves the whole match literal with no token; a valid name ([-_A-Za-z0-9.%]+) claims the {name} token with the residual `]` re-emitted; an invalid name with the residual closer and no preceding `[` claims the {type: 'literal', text: whole match} token with no re-emission; any other invalid name claims {type: 'invalid_named', lead, text, trail} with the leading and trailing space/tab runs split off. The scan threads the previous input byte because the literal branch tests whether the match is preceded by `[` in the pass input. The element pass enumerates its matches preg_match_all-style (non-overlapping, each search resuming after the previous match; a position whose opener matches but has no closer is not a match) and folds them with the reference's cursor, so a match starting before the cursor is skipped. The opener decomposes uniquely: `[[a`, an optional `_` (the scored flag), and an attribute segment ending at the first `]`, which must be followed by a second `]`; the segment is either empty (group absent) or a whitespace run plus a remainder starting with a non-whitespace byte (an all-whitespace or non-whitespace-led segment cannot match). Per match, the mirror follows the reference's branch order exactly: the nested path first (non-scored only, the body containing an opener: start, end, start, end claimed in that order, outer and inner bodies spliced, then a trailing same-line `[[/a]]` consumed with its prefix when that prefix holds no opener), then the scored adjustments (the join strip on the output so far, one leading and one trailing newline off the body, the forward join in the cursor advance), then the boundary space movement shared by both forms (leading and trailing space/tab runs leave the body; a single space is emitted outside the pair when the neighbor byte on that side exists and is not a newline, space, or tab), then the paragraph split (non-scored only, a body containing a blank line and no `[[`: preg_split on maximal runs of two or more newlines with the delimiters captured, every text part, empty ones included, wrapped in its own start/end pair with the same attributes) or the simple pair, which for a scored anchor also registers its (end, start) pair. buildAnchorAttrs is mirrored as a fold over getAttrsBytes' pairs into a fixed map, the data-* pairs, and the held-back href, with PHP array assignment semantics (omSetB) so a data-* key repeated under a different case keeps its first position and last value; assembly emits id, class, style, role, type, the data-* pairs in authored order, href always, and target. The normalization pieces reuse ListRules' normalizeAttrValue (the same reference helper) and add the verbatim class (a leading `#` or `/`, or one of thirteen case-sensitive scheme prefixes), the starred form (a leading `*`; a verbatim href with no authored target earns target="_blank", where an authored target that was emptied by the placeholder branch still counts as authored), the percent-encoding of a verbatim href's spaces and non-ASCII bytes, and the unsafe href's slug scan (colon-aware separator state, pending separators dropped at the end). Oracle probes run against the reference during the stage settled the questions the code left open, and the corpus records carry them: Button's type group preserves case under the case-insensitive flag (`[[button EDIT]]` claims type EDIT); getAttrs' numeric-string keys become PHP integer keys and are skipped by buildAnchorAttrs (`[[a 123="x" href="/y"]]` claims an anchor whose only attribute is the href, while `data-9` is emitted), a distinction the byte map cannot observe because the fixed lookups name only non-numeric keys and a numeric key never starts with `data-`; the id normalization branches (`id=" u"` claims u- u, `id="u-x"` claims u-x, `id="x"` claims u-x, an empty id is omitted); a class spanning a placeholder is emitted as the empty string; and the boundary cases of the scored join (two trailing newlines stripped, three left alone) are pinned both as corpus cases and as theorems.

User is the base preg_replace_callback scan with a uniquely decomposing pattern (an optional `*`, `user` case-insensitively, exactly one literal space, the name group forced maximal to the first `]`, then `]]`); process() claims {userName} verbatim (no trim) plus {image: true} for the starred form, the boolean crossing as a JSON true in the record. Button's pattern tail is the one genuine backtracking enumeration among the five callback rules, and the mirror enumerates it in PCRE's order: the group present first with `\s+` lengths descending and group lengths ascending (the shared lazyGroupToClose), then the group absent; the type group and the leading `\s+` are both forced maximal. The enumeration's corner cases are pinned in the corpus: `[[button edit]]` matches with the group absent, `[[button edit ]]` does not match at all, and `[[button edit  ]]` matches with the group a single space (whose getAttrs is empty). process() keeps only text, class, and style from getAttrs (in that order, isset semantics so an empty text is kept) and appends the type last, underscores replaced by hyphens. Embed's opener and closer suffixes are independent (no backreference): each is tried audio, then video, then absent, the choice is deterministic, and the body is lazy to the first position at which any closer matches; the corpus pins the mismatched pair (`[[embedvideo]]body[[/embed]]` claims the body). Social claims no tokens: its callback returns the þ-delimited module string (bytes C3 BE, the reference's utf8_encode("\xFE")) with the urlencoded `sites="..."` parameter spliced in when the trimmed sites are nonempty, and the mirror reproduces the pattern's decomposition exactly (the group content excludes `]`, so a match ends at the first `]` byte, which must start a `]]` pair; the group is present exactly when the content has at least two bytes and starts with whitespace, so `[[social ]]` does not match while `[[social  ]]` matches with empty sites) and PHP's urlencode byte for byte (space to `+`, `~` to %7E, uppercase hex). File's pattern has no dotall flag, so neither group can cross a newline, and the mirror enumerates PCRE's order over the newline-bounded segment: `\s+` lengths descending, first-group lengths ascending, the pipe alternative present (second group grown lazily) before absent at each length; the traces are pinned in the corpus (`[[file a.txt|]]` claims file `a.txt|` with the anchor defaulted, `[[file a|b|c]]` claims anchor `b|c`, `[[file |x]]` claims file `|x`), and process() trims both groups and defaults an empty anchor to the file.

## The one exclusion class: dissolved placeholder digits

One corpus case and five fuzz cases disagree with their batch fixtures, all by the same mechanism, which is a property of the fixture route rather than of any mirror. Text_Wiki::addToken numbers tokens from a process-static counter that never resets (its own comment says so), so in a 365-case batch a placeholder's digits are the token's position in the whole batch, while the Lean side numbers per document, as the canonicalization protocol assumes everywhere else. A placeholder normally survives as a unit and is renumbered by the comparison; but two transforms in this stage's family dissolve it: Anchor's unsafe-href slug scan deletes the delimiter bytes and keeps the digits as slug text, and Social's urlencode percent-encodes the delimiter bytes and keeps the digits as literal text. Where a dissolved placeholder lands in a compared value, the batch record therefore contains the batch position's digits (803 in the corpus case) where the per-document behavior has the document position's digits (0). The corpus case is a34 (`[[a href="@@a@@"]]...`, the href dissolving a Raw placeholder); its disposition is recorded in corpus-provenance.json, and its per-document agreement is demonstrated, not asserted: the reference run on a34 alone in a fresh process produces href 0, and the Lean record matches that record exactly under the canonicalization (comparison-a34-fresh.txt: a34 PASS). The five fuzz disagreements (fz317-20261121-0027, -0237, -0370, fz317-7-0251, fz317-7-0405) are Social sites groups spanning Math placeholders, identical in every other byte including the placeholders' relative order, and each was likewise demonstrated to agree per-document (fuzz-fresh-check.txt: all five fresh-process comparisons true). No other case in the corpus or the fuzz disagrees, and no disagreement of any other shape was found.
