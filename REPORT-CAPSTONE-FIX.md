Bisection with scratch modules containing the file's definitions truncated at the Theorems marker showed the components are individually cheap: lookupPage over the full page map, htmlSpecialChars, the DocState component of the refFetch result, and the href append chain each check in roughly three to four seconds of wall time including toolchain startup, while the assembled output-string component alone times out, and the raw output expression without refFetch also times out; halves of the expression pass but are already expensive. The mechanism is per-character defeq cost over one large literal: the example stated the expected output as a single ~190-character literal, and checking the assembled append expression against that one literal goes through the expensive general path (String.toList is noncomputable in Lean 4.36, Init/Data/String/Basic.lean line 243), blowing the 200000-heartbeat whnf budget while every segment reduces quickly on its own. The fix is the brief's preference (i): the example's expected output is restated in the definition's own append-segmented spelling, with the href as a single literal segment and htmlSpecialChars' result as its literal value; the theorem keeps its name and its pair shape and asserts the identical character list, and a comment at the theorem records why the segmented spelling is used. No definition's meaning changed, no budget was raised anywhere, and no global option was touched. `lake build LeanFtml.IncludeRule` is green under stock heartbeats, and the whole-project build (library, the main executable, and every conformance executable built explicitly by name, twenty-six targets) is green at 197 jobs in 2m30s with rc=0.

## Step 3: the Include mechanism corrections

Each correction rewrites the mirror to follow the corrected reference, ref-php/text-wiki/Text/Wiki/Parse/Default/Include.php, with GRAMMAR-INCLUDE.md as the settled rules. First, candidate scanning: refFindCandidate was rewritten to follow refFindCandidate (Include.php line 177): at each line start the lead run of blanks and `>` characters is taken, a lead containing `>` skips the line whole, and otherwise the tight case-insensitive `[[include` must stand at the line start itself followed by a PCRE whitespace character; the mirror's old scanPrefix-based prefix and depth bookkeeping is gone. Second, segment splitting: refSegments now follows refSegments (line 315) exactly, a raw `|` split via the new splitRawPipe (n pipes give n+1 segments, empties included) with refSegmentArg applied per segment (line 331, itself unchanged after verification against the PHP), returning a plain list that never fails; the comment-aware Option-returning split is deleted, per the AUDIT-G14B correction to G4/G5. Third, quoted consumption is removed entire: the quoted-candidates section (refStripQuotePrefix, refOrigOffset, refStripAllLines, refQuotedBound, refQuotedAttempt) and the depth > 0 branch in the expansion pass are deleted, following the G13 correction and F-G14-1; quoted include text now stays literal, and the helpers explodeNl and implodeNl, which served only that machinery, are deleted with it. Fourth, resolution: refResolveRef was rewritten to follow refResolveRef (line 419): a site pair fires only when the site part is non-empty, the page part is non-empty, the page part passes the target charset gate, and the site part passes the host gate [A-Za-z0-9.-] (the new isIncHostC), yielding the canonicalized site only (refCanonicalSite, line 487; no slug normalization of the site) and the normalized page with no empty-page rejection, so an empty-normalized pair page fires with the empty name; pair failure falls through to the whole-run page-name rule, unchanged. Fifth, resumption: the new refNextLineStart follows refNextLineStart (line 163), and refExpandPassWith now resumes at the next line start after the failed candidate's opener line on both parse failure and resolution failure, following the corrected refExpandPass (line 109, the F1 branch), appending the source span up to the resume point. Theorems were restated to match: refFindCandidate_quoted_example is replaced by refFindCandidate_quoted_skipped_example and refFindCandidate_quoted_then_plain_example; refSegments_comment_pipe_example is replaced by refSegments_raw_pipe_example with the comment contents split at the raw pipe, and refSegments_unclosed_comment_example now asserts the two-argument list instead of failure; four resolution examples were added (host-gate fallback for :foo_bar:other-page, an empty-normalized pair page firing for :sandbox:---, site case preservation, a dotted site); two pass-level examples were added (next-line resumption after a failed candidate, and a quoted include line passing through literal); the pre-existing resolution, fetch, substitution, and cycle examples are unchanged and still check.
