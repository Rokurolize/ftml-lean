# CANDIDATE C-R5G-S1-1 — Freelink external href leaves a raw ESC byte where live percent-encodes it

Status: CONFIRMED rule-level divergence on the post-REFCORR13, snapshot-37 ground. Suspicions S03. Capture id `muse-probe-round5g-s1-s03-fl-esc-in-url`, source sha256 recorded in captures.json, html_sha256 recorded in CAPTURE-INDEX.md; ref.jsonl row 3; ledger reason is the REFCORR13-GENERAL Anchor verbatim-href encoder versus the Freelink external-URL encoder cross-rule seam.

Minimal source: `[[[https://example.com/a\u001bb]]]` (an ESC byte 0x1B in the interior of a bare external URL path, no pipe label).

Decisive live bytes: `<a href="https://example.com/a%1Bb">https://example.com/a\x1bb</a>`. Reference bytes: `<a href="https://example.com/a\x1bb">https://example.com/a\x1bb</a>`. After the standard probe.norm and campaign frame mask the display text is identical (the raw ESC is masked out of the visible text on both sides), but the href attribute is a rule-level value and differs: live percent-encodes the interior C0 control byte as `%1B`, while the reference leaves the raw byte 0x1B in the href. The capture is valid, stable and saved-source-matching with zero stderr from the PHP harness.

Owning reference file: `ref-php/text-wiki/Text/Wiki/Render/Xhtml/Freelink.php` lines 67-76. The REFCORR13 bytewise encoder is `preg_replace_callback('/[^\x00-\x7F]/', ...)` over `$url . $anchor . $extra`, which rewrites only bytes >= 0x80 and therefore never touches an ASCII C0 control such as ESC. REFCORR13-GENERAL separately widened `Parse/Default/Anchor.php`'s verbatim-href encoder to every non-printable byte (so a preserved ESC becomes `%1B` in an Anchor href), which is the corrected sibling the Freelink encoder did not follow. A symmetric minimal fix is to widen the Freelink callback class to every non-printable byte (0x00-0x1F and 0x7F in addition to the current non-ASCII range), leaving the authored display text untouched, exactly as the Anchor verbatim-href path does.

Mirror consequence inferred by source reading (no elaboration run): `lean-ftml/LeanFtml/ServingRules.lean::renderFreelink` lines 355-357 calls `percentEncodeNonAscii (url ++ anchor ++ extra)`, transcribing the same narrow predicate. The mirror would need the same widening to a non-printable encoder to stay symmetric. No Lean invocation was performed; this consequence is a source-reading inference only.
