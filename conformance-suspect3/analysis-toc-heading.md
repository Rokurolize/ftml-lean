# analysis-toc-heading — pre-probe suspicion notes for the TOC depth/numbering and Heading static-state render seams (2026-11-22)

Read-only analysis lane: no live probe, no ftml edit, no cargo, no git identity, no commit; this file is the only deliverable. The reference is the tree the harness actually loads (ref-php/harness/batch.php:15-21 include path = ref-php/text-wiki), with ref-php/fossil/lib/Text_Wiki kept only as upstream context. Each suspicion below has P_code (what the reference as written predicts live will serve) and P_alt (the opposite), both written before any probe; no verdict is claimed here. Sources have no trailing newline because Wikidot strips one on save, and `\n` inside a source denotes one literal LF. The earlier C-SUSPECT-XRULE-4 correction replaced the authorable `üü` Toc sentinel with an unforgeable NUL pair in both Render/Xhtml/Toc.php:116-125 and Text/Wiki.php:1196-1198, so old-sentinel forging is closed and the sentinel itself is no longer a suspicion.

## Static reading that frames the seams

Toc is a post-parse collector, not a tree builder. Heading (rule 89) runs before Toc (rule 90) in Text/Wiki.php:89-90, so when Toc::process() calls getTokens('Heading') (Parse/Default/Toc.php:98) every heading in the document already has a token, regardless of where the `[[toc]]` marker sits; the filter is only `$val[1]['type'] != 'start'` (line 100), with no level predicate, no nesting and no max-depth clamp. The per-call `$count = 0` (line 76, incremented at 108) is attached to item_start tokens but the Xhtml renderer never reads it (Render/Xhtml/Toc.php:53-127), so the reference computes numbering and discards it. Depth is only a flat indentation string, `$pad = $level - $this->min` with `$min = 0` a never-reassigned instance property (Toc.php:38, 113-114). The renderer strips every tag inside an entry through the NUL sentinel post-pass (Wiki.php:1193-1206), so markup authored in a heading is rendered and then stripped in the TOC copy only.

Heading's anchor counter is instance state, not a static: `$this->wiki->vars['headline_id']`, null-tested and initialized to 0 in Parse/Default/Heading.php:91-106, incremented only for anchored headings. The only PHP `static` in the Heading family is `static $jsOutput = false` in Render/Xhtml/Heading.php:41, read only in the `startContent` branch (65-91) that no parse rule emits (precise grep: its sole occurrence in the tree) and never assigned, with `$collapse` pinned to null at line 40; it is process-global but dead. batch.php:60, 66, 82 constructs a fresh `new Text_Wiki()` per case and only resets the genuinely process-static Math label array at line 43, which is the R35-family artifact (REPORT-R35.md line 29: the batch oracle numbers placeholders with a process-global counter) rather than a Heading leak. The Lean mirror keeps the counter in per-document `DocState.headlineId : Option Nat := none` (TokenState.lean:220-222) consumed by `headingProcess` (BlockRules.lean:286-306); its neighbours Collapsible/Tabview have real class statics (TokenState.lean:229-234), which is the class of bug but outside this seam.

## T1 — TOC depth accounting is flat, includes level 1, and never clamps a skip

Mechanism refs: Parse/Default/Toc.php:98-122 (unfiltered 'start' loop), Render/Xhtml/Toc.php:38, 113-114 (margin = level); mirror `headingMatchLine` (BlockRules.lean:265-276), `tocItems` (402-427), `renderToc`/`toc_item_start_level` (RawHeadingRules.lean:251-285, RawHeadingRender.lean:381-387). P_code: every anchored heading appears as a flat entry with `margin-left: <level>em` and href `#tocN`, including a level-1 `+` and a level-6 `++++++`, and a missing intermediate level is only an indentation gap. P_alt: the docblock's "level-2 through level-6" is enforced (level 1 omitted), or levels are clamped/nested so a skip is normalized.

T1a `[[toc]]\n+ A\n++ B\n++++ D\n++++++ F` — P_code: four entries, margins 1em/2em/4em/6em, ids toc0..toc3, no nesting and no numbers; P_alt: A is omitted or D/F are clamped. Reachability: plausible (a page with a level-1 title and an intentionally skipped level).

T1b `[[toc]]\n+ A\n+++++++ X\n++ B` — P_code: the seven-plus line matches no heading (regex `\+{1,6}` at Heading.php:61, mirror theorem `headingMatchLine_seven_none` at BlockRules.lean:524-525), so it stays a literal paragraph and the TOC has only A (toc0, 1em) and B (toc1, 2em); P_alt: X becomes a clamped level-6 heading or a TOC entry. Reachability: adversarial-only, but it is the exact "deeper than max" shape named in the brief.

T1c `[[toc]]\n++ [!--x--]\n++ B` — P_code: Comment (rule 67, Parse/Default/Comment.php:44-93) deletes the comment body before Heading claims the line, leaving `++ ` with empty group 3, so the first heading renders `<h2 id="toc0"><span></span></h2>` and the TOC has an empty first entry with href `#toc0`, then B with `#toc1`; P_alt: the empty entry is suppressed, the ids shift, or the comment text is visible. Reachability: adversarial-only (comment as heading text), but this form avoids trailing whitespace so it should survive save read-back, unlike X5/X14.

## T2 — TOC ignores heading position, marker count, and duplicate text

Mechanism refs: Toc.php:98 (all tokens), 76/108 (per-call count), 113 (raw text copied); mirror `tocProcess` (BlockRules.lean:444-467) and `tocScan` (475-493). P_code: the marker is a collection point over the whole document, so headings before and after it are both listed in document order, every `[[toc]]` block emits the same full list with its own count starting at zero, and duplicate heading text yields duplicate entries with distinct ids. P_alt: only preceding headings are collected, a second marker is suppressed or incremental, or duplicates are merged.

T2a `+ Before\n[[toc]]\n+ After` — P_code: one TOC with two entries, Before (`#toc0`, 1em) then After (`#toc1`, 1em), even though After is below the marker; P_alt: only Before appears. Reachability: plausible (marker placed mid-document).

T2b `[[toc]]\n+ A\n[[toc]]\n++ B` — P_code: two TOCs, each listing A (`#toc0`) then B (`#toc1`) in the same order; the second `$count` restarts but no number is rendered, so the two blocks are byte-identical apart from surrounding newlines; P_alt: the second lists only B or shows different numbering. Reachability: adversarial-ish but authorable (two markers by accident).

T2c `[[toc]]\n++ Same\n++ Same` — P_code: two entries both reading `Same`, anchors `#toc0` and `#toc1`, no dedup; P_alt: one entry, a numeric suffix, or a repeated id. Reachability: plausible (repeated section names).

## T3 — attribute-tail greediness, a dead count, and no numbering at all

Mechanism refs: Parse/Default/Toc.php:52 (regex `( .*)?` greedy to the LAST `]]` on the line) and 78-79 (getAttrs), Parse.php:224-251 (getAttrs needs `="` and takes the last `"` in each segment), Render/Xhtml/Toc.php:88-93 (title) and 53-127 (count never read); mirror `tocTail`/`tocMatchAt` (BlockRules.lean:354-393, including the documented quoted-`]]` swallow) and `renderToc` (RawHeadingRules.lean:251-285). P_code: a `]]` inside the tail is consumed into the attribute group, so the marker closes at the last `]]` on the line and the resulting attr map is often empty; no attribute currently produces visible numbering, because the count is passed to a renderer that ignores it. P_alt: the marker closes at the first `]]` leaving stray literal text, or a `numbered` option produces numbered entries.

T3a `[[toc title="a]]b]]\n+ A` — P_code: one TOC consuming the whole line; `getAttrs(' title="a]]b')` splits on `="` into `title` and `a]]b` with no remaining `"` (strrpos false), yielding `title => ''`, so `<div class="title"></div>` and no stray `b]]`; P_alt: title `a]]b`, or a second marker / literal `b]]` left in the page. Reachability: adversarial-only (an embedded closer in a quoted attribute).

T3b `[[toc]] [[toc]]\n+ A` — P_code: the greedy tail takes `]] [[toc` as group 2 and the final `]]` closes it, so there is one TOC with no attributes and no literal `[[toc]]` remains; P_alt: two TOCs or a visible leftover marker. Reachability: adversarial-only.

T3c `[[toc numbered]]\n+ A` — P_code: `getAttrs` sees no `="`, returns an empty map, and the list is unnumbered exactly like plain `[[toc]]` (the dead `count` is the only numbering in the code); P_alt: entries render as `1. A` / `2. A`. Reachability: adversarial-ish, but a shape an author might try.

## T4 — heading text in a TOC entry is rendered and then tag-stripped by the NUL sentinel

Mechanism refs: Toc.php:113 (raw `$val[1]['text']` reinserted into the source, so later inline rules process it in both the heading and the TOC copy), Render/Xhtml/Toc.php:116-125 and Wiki.php:1193-1206 (NUL pair plus `strip_tags` post-pass), mirror NUL emission in `renderToc` (RawHeadingRules.lean:251-285), `tocStripDelim`/`postStripToc` (RenderCore.lean:516-560) and theorem `postStripToc_strips_tags` (RenderCore.lean:1179-1181). P_code: markup in a heading is fully formatted in the heading body but the TOC entry shows its plain text with all generated tags removed, and the NUL pair cannot be forged by authored text after C-SUSPECT-XRULE-4. P_alt: the TOC shows literal `**`/`<` markup, keeps the generated tags, or can be truncated by an authored `üü`.

T4a `[[toc]]\n++ A **bold** B` — P_code: the heading itself contains `<strong>bold</strong>`, while the TOC entry between the NUL pairs is reduced to plain text `A bold B` inside `<a href="#toc0">`; P_alt: the TOC entry keeps `<strong>` or shows the asterisks. Reachability: very plausible (markup in headings is common).

T4b `+ [[toc]]\n++ A` — P_code: Heading claims the line first, so the line begins with a token placeholder and the Toc regex cannot match `[[` at a line start; no TOC is emitted and `[[toc]]` stays literal inside `<h1 id="toc0"><span>`; P_alt: a TOC is generated (possibly inside the heading). Reachability: adversarial-only (a marker inside a heading).

T4c `[[toc]]\n++ Grüüße\n++ Normal` — P_code: after C-SUSPECT-XRULE-4 both entries are intact (`Grüüße`, `Normal`, ids toc0/toc1); P_alt: the pre-correction `üü` sentinel terminates the first entry early and merges or corrupts the two. Reachability: plausible (doubled umlauts in German text), and it doubles as the regression control for X31.

## H1 — Heading has no observable cross-document static state; the batch probe must be harness-side

Refs and analysis: Parse/Default/Heading.php:91-106 keeps `headline_id` on the wiki instance; batch.php:60/66/82 allocates a fresh instance per case; Render/Xhtml/Heading.php:40-41 and 65-91 has a process-global `static $jsOutput` that is never written and only read in an unemitted branch; REPORT-R35.md line 29 records the real process-global counter artifact for placeholders; mirror `DocState.headlineId` (TokenState.lean:220-222) and `headingProcess` (BlockRules.lean:286-306). P_code (reference as written): in one batch, document A numbers `toc0..toc2` and the later document B still starts at `toc0`, because the counter is per wiki instance; P_alt: B continues at `toc3`, proving a class-static or global anchor counter leaked A's final value.

H1a batch probe, two stdin lines to `batch.php render` in one process — A: `+ A1\n+ A2\n+ A3`, B: `+ B1` — P_code: A emits `<h1 id="toc0">`, `<h1 id="toc1">`, `<h1 id="toc2">` and B emits `<h1 id="toc0">`; P_alt: B emits `<h1 id="toc3">`. Reachability: harness-only construct; a saved page cannot place two documents in one oracle instance.

H1b isolation control — the same A and B as two separate `transform.php` runs (or two one-line batch.php invocations) — P_code: B emits `id="toc0"` in isolation too, so batch-B and isolated-B are byte-identical and the per-document rule is confirmed; P_alt: isolated-B differs from batch-B, which would be the signature of a real static leak. Reachability: harness-only control, but it is the only discriminating instrument for this item.

H1c saved-page oracle — two saved pages `muse-probe-suspect3-h1a` (A's source) and `muse-probe-suspect3-h1b` (B's source) — P_code: B's saved-page render shows `id="toc0"`; P_alt: it shows `id="toc3"` or any value that depends on A. Reachability: UNTESTABLE at a saved-page oracle, because live Wikidot serves each page in its own request and therefore its own Text_Wiki instance; the two pages can never share the counter, so this probe can only confirm the per-document rule, not discriminate a leak. The only same-request merge is `[[include]]`, which is within one document and legitimately shares the counter, so it is not a cross-document test. Verdict source is the harness/mirror comparison only.

H1d neighbourhood control — a heading containing a Collapsible/Tabview token (whose real class statics are listed at TokenState.lean:229-234) — P_code: any leaked counter in those families could appear in ids inside B's heading while Heading's own `tocN` stays per-document; P_alt: no such dependence. Reachability: adversarial-only and out of Heading scope; recorded so the coordinator does not mistake a neighbour's leak for a Heading leak.

## H2 — within-document numbering: a `+*` heading takes no id and consumes no number

Mechanism refs: Parse/Default/Heading.php:96 and 99-106 (`start-notoc`, null id, no increment), Toc.php:100-102 (skips exact type `start`), mirror `headingProcess` and `tocItems` (BlockRules.lean:286-306, 402-427), theorem `spec_heading_space_star_anchored` (SpecRawhead.lean:46). P_code: a `*` heading is emitted as a bare `<hN>` with no `id`, is absent from the TOC, and leaves the next plain heading's `tocN` unchanged. P_alt: the starred heading consumes a counter value (so the next heading shifts) or appears in the TOC.

H2a `[[toc]]\n+ A\n+* Skip\n+ B` — P_code: the TOC has exactly two entries, A `#toc0` and B `#toc1`; the middle heading is `<h1><span>Skip</span></h1>` with no id; P_alt: B is `#toc2` or Skip appears as a third entry. Reachability: plausible (authors use `+*` to hide a heading from the TOC).

H2b `[[toc]]\n+* Only\n+ A` — P_code: the first plain heading still gets `#toc0` and is the first TOC entry; P_alt: it gets `#toc1`, leaving a gap. Reachability: plausible, and it is the minimal discriminator for "star does not consume a number".
