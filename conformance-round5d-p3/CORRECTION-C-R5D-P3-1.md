# CORRECTION-C-R5D-P3-1 — Image link attribute value must not retain authored trailing whitespace (evidence-only intake, 2026-11-23)

This is an evidence-only candidate record for the coordinator. It changes no canonical file. The coordinator verifies the capture hashes and adopts or rejects after its own review.

Minimal source: `[[image IMG.png link="http://example.com/x "]]` (the single byte in dispute is the space immediately before the closing quote of the `link` value).

Decisive live bytes: capture `muse-probe-round5d-p3-p3d-11-image-link-trailing-space`, html_sha256 `62af6ab8ca808f9a3d9e15eb5c78cf8faea85921c9207a79280904b65b9dec52`, source_sha256 `48e38b2c30ecd0615a184599d8f2536c8d1b72295f7f1dfd47099ebcd9e1828c`, valid=true, stable=true, saved_source_matches=true. The `<img src>` host and page path are the documented owned gallery/file serving surface and are not part of the claim.

Decisive reference bytes: `ref.jsonl` line 11 and `ref-batch.jsonl` line 11: `<a href="http://example.com/x "><img src="/local--files//IMG.png" alt="IMG.png" class="image" /></a>`. After the same mask this is `<a href="http://example.com/x "><img alt="IMG.png" class="image" src="/local--files//IMG.png"></a>`; the href retains the authored trailing space.

Owning reference files and mechanism: `ref-php/text-wiki/Text/Wiki/Parse.php:224-247` `getAttrs()` splits on `="` and assigns `stripslashes(substr($val, 0, $pos))`, so every byte before the last double quote, including trailing whitespace, survives as the attribute value. `ref-php/text-wiki/Text/Wiki/Parse/Default/Image.php:136` calls `getAttrs()` on the option tail, lines 147-149 copy `link` into the emitted options, and the Xhtml image renderer emits that value verbatim as the anchor `href`. The round-5c leading-space sibling (P3C-18) cleared because the C3 guard at `Image.php:181-189` rejects a link whose first byte is whitespace; the trailing-space sibling passes that guard and exposes the untrimmed value. The reference therefore models live incorrectly for a valid URL link with trailing whitespace in the quoted value. Prior campaign precedent treats a rule-level attribute-value whitespace difference as confirmable: REPORT-ROUND5-R3 confirmed a retained trailing space in the footnote footer body, and REPORT-ROUND5B-R1 / REPORT-ROUND5C-R1 confirmed Div id attribute-value differences.

Inferred mirror consequence by source reading only (no Lean elaboration was run): `lean-ftml/LeanFtml/NextRules.lean:177-193` `getAttrsBytes` keeps the untrimmed value `stripslashesB (part.take i)` before the last quote, matching PHP; `lean-ftml/LeanFtml/ServingRules.lean:365-376` `imageAttrMap` and `attrLookup` pass the value through unchanged, and `imageHref` at lines 400-403 returns a link containing `://` at an index of at least one as-is. The mirror therefore also emits the trailing space in the Image href and inherits the same divergence. A correction must trim the Image `link` value the way live does while leaving the C3 leading-space rejection and the accepted-control cases unchanged.

Clearance controls that isolate the fault: P3C-18 (leading space) cleared on the same ground, P3D-03 and P3D-14 cleared all the Image/Tableadv parse-side boundaries, and P3D-13/P3D-15 cleared the same wdfiles host surface for File links, so the surviving difference is specific to retained trailing whitespace in a valid Image link value.
