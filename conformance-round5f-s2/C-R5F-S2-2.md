Decisive live bytes after probe.norm and the campaign frame mask: `<ul><li>A<sup ...>1</a></sup></li></ul><div class="footnotes-footer">...gap...</div><p>[[LI]]B[[/LI]]<br> [[/UL]]</p>` — the list ends before the footnote footer, which is emitted outside the list. Reference bytes, ref.jsonl line 32: `<ul><li>A<sup ...>1</a></sup><div class="footnotes-footer">...gap...</div>[[LI]]B[[/LI]]<br> [[/UL]]</li></ul>` — the footer is emitted inside the absorbing `<li>` and the list end token comes after it. The difference is the structural list-end versus footnote-footer placement, not the owned Stage 2 newline immediately before the footer div that R12-LIST clears for the S04 shape; it survives probe.norm and the campaign frame mask.

Mechanism. The REFCORR12 general rule scans `$leftover12`, the bytes after the last surviving `[[/ul]]` or `[[/ol]]` closer, for a Footnoteblock token and hoists only a marker found there. In this source the footnoteblock occurs before that final closer, inside the absorbed tail, so the reference does not hoist it. Live hoists a footnoteblock anywhere in the post-failed-closer region. The rule's own verification corpus did not contain this placement: coord-units/R12-LIST/evidence/RENDER-TABLE.md tests the round-5d shape `[[UL]]\n[[LI]]A[[/LI]]\n[[/UL]]\n[[footnote]]gap[[/footnote]]\n[[LI]]B[[/LI]]\n[[/UL]]\n[[footnoteblock]]` with the footnoteblock at the very end. Rendering that tested shape through the current canonical harness and comparing with its cached R5D-S1 live capture gives canon-equal bytes, confirming that the reference is correct for the end placement and wrong only for this earlier-marker sibling.

Owning reference file: ref-php/text-wiki/Text/Wiki/Parse/Default/List.php, REFCORR12 C1 fast path, the `$hoistPos12` scan of `$leftover12`.
