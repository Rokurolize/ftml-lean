# C-R5H-R1-4 — Uppercase nested list opener switches list-boundary pairing on live versus reference

Minimal source (R5HR1-C5): `[[ul]]\n[[li]]A[[UL]]\n[[li]]B[[/UL]][[/li]]\n[[/ul]]`. An outer lowercase ul with a first lowercase li, an uppercase nested UL opener/closer pair, and a second lowercase li inside the nested run.

Decisive live bytes, capture muse-probe-round5h-r1-r5hr1-c5 (valid=true, stable=true, saved_source_matches=true): `<ul>\n<li>A[[li]]B</li>\n</ul>\n<br />` — live opens the list at the first lowercase `[[ul]]`, keeps the second `[[li]]` as literal text inside the single item, and emits one trailing break. Decisive reference bytes (ref.jsonl line 16): `<p>[[ul]]<br />\n[[li]]A<ul>\n<li>B</p>\n\n<br />` — the reference leaves the outer `[[ul]]` and the `[[li]]A` prefix literal, opens `<ul>` only at the uppercase `[[UL]]`, and wraps the whole run in a `<p>`. The misnested `<p>` directly containing `<ul>` is the owned Stage 2 tidy frame and is not itself counted; after setting that frame aside, the surviving rule-level difference is the list-boundary pairing: which opener is recognized as a list and which fragments remain literal. No serving-layer id, host or counter digit is involved.

Owning reference files: ref-php/text-wiki/Text/Wiki/Parse/Default/List.php body-level regexp callback and its R13 symmetric nested-boundary rewrites (the `.before-refcorr13` companion records the added symmetry), with Render/Xhtml/List.php emitting the paired tokens. For this case combination the reference consumes the uppercase closer but fails to open the list at the lowercase outer `[[ul]]`, while live does the opposite. The cached round-5g C5 witness used the opposite case combination and CLEARED, so this is a fresh case-combination sibling that isolates the changed rewrite.
