## General rule

One uniform decision governs every stored Div attribute key. The allowlist is `id`, `class`, `style`, `role`, `type` and case-folded `data-*`; duplicate folded keys are last-wins on value and the authored-non-empty record is monotone, so an authored-empty last value survives when an earlier variant of the same folded key authored non-empty. `normalizeValue` drops control bytes and collapses whitespace, and an attribute is unset at the end of the pass iff its normalized value trims empty AND no occurrence of that folded key authored a literally non-empty value; this keeps a whitespace-only `class`/`style` as a real empty attribute while dropping a sole `class=""` or `data-foo=""`. `isolateId` is a per-id isolation applied before that test: an authored id body carrying a 0xFF token placeholder is preserved verbatim for ANY body, including one that already begins with `u-`, so the render's single 0xFF arm emits `id=""` with the key kept; a placeholder-free whitespace-only id isolates to the bare `u-` shell and is emitted verbatim; a valid placeholder-free id takes the standard whitespace collapse with the `u-` prefix unless already present. The renderer applies one uniform arm over all values: any 0xFF-bearing value clears to the empty string with its key kept, and every other value is ENT_COMPAT-escaped verbatim, including the literal `u-` shell. This restores agreement with the already-recorded intent theorem `SpecIntent.lean::divIntent_placeholder_clears_without_uprefix`; the REFCORR9 `u-`-prefix carve-out was the anomaly.

## Mechanism

In `Text_Wiki_Parse_Div::isolateId` the guarded arm `if (strpos($value, "\xFF") !== false && strpos($value, 'u-') !== 0) { return $value; }` becomes `if (strpos($value, "\xFF") !== false) { return $value; }`, with the comment restated for the general rule. Dropping the `u-` exclusion stops the invalid-UTF-8 `preg_replace('/\s+/u', ...)` collapse from returning null for a `u-`-prefixed placeholder id (which made the caller drop the id) and instead preserves the placeholder bytes for the unchanged render clear arm. No other parse statement changes: the authored-value map, the monotone REFCORR9 flag, the empty-value unset, `divArgsOrder`, the `vanished` flag, the lowercasing, `normalizeValue`, the class rtrim and the id/key allowlist are all untouched. The mirror `ContainRules.lean::isolateId` correspondingly changes the placeholder branch from `if (litBytes "u-").isPrefixOf v then none else some v` to `else if v.contains 255 then some v`, with its doc comment restated. The render files `Render/Xhtml/Div.php`, `InteractiveRules.lean::divAttrFragment` and `CoverageContain.lean::divValueCleared` are unchanged because they already test exactly the retained 0xFF byte; no compared token field is added or removed and `state-restricted.php` / `TokenState.lean::serToken` keep the `[rule, options]` wire shape.
