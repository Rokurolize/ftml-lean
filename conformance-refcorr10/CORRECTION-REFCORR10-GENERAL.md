The general rule. The stored footnote body is re-parsed as wiki source by `Footnoteblock::process`, so empty-Raw placeholders (`\xFF<id>\xFF` naming `['Raw', ['text' => '']]`) must be kept wherever an authored LF needs an inline witness byte for the Newline rule to emit `<br />`. One byte-local predicate decides storage: if the trimmed body carries a SINGLE authored break — an LF with a non-LF byte immediately before and immediately after it — store that placeholder-bearing body, dropping only C0 control bytes that live's purifyHtml removes (everything below 0x20 except TAB, LF and CR; form feed 12 is the round-5c witness); otherwise store the token-aware empty-Raw-stripped body re-trimmed as before. Double-LF runs, bare or edge LFs and whitespace-only bodies therefore still fold to empty. The separator space is decided from the SAME visible projection (the stored body with empty-Raw placeholders removed) by one test: emit the space iff a non-whitespace byte occurs before the first LF, so a body whose first line is empty (leading break) gets no space while literal and NBSP first-line text does. Both decisions are token-aware and shape-free; no compared field is added.
