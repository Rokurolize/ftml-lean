## Corrections (all in the worktree's `ref-php/`; each edited file keeps a `<File>.before-refval2.php` copy)

Button, `Render/Xhtml/Button.php`, six corrections: (1) type matching is now case-insensitive (the render lowercases the type; the parse already maps `_` to `-`), settled by `p14`, `sb06`, `bt-06`, `bt-36`; (2) the six live types the fossil lacked are added to the allowed-types, default-text, and onclick tables — `rename` (`renamePage(event)`), `delete` (`deletePage(event)`), `parent` (`parentClick(event)`), `edit-meta` (`editMetaClick(event)`, default text `edit meta`), `watchers` (`watchersClick(event)`), `set-tags` (`updateTagsByButton(event, '')`) — settled by `p06`, `p07`, `p08`; (3) the history onclick loses the fossil table's leading space, settled by `p03`; (4) the unknown-type error is now `<em>{type}</em> is not a valid button type` with the fully normalized type, replacing `The button type is not recognized`, settled by `p07`, `p08`, `sb07` (`LOCK` -> `lock`), `sb08` (`Foo_Bar` -> `foo-bar`); (5) `set-tags` without a `text` attribute renders `You need to set text for set-tags button.`, and its `tags` attribute is never rendered into the output under any shape, settled by `p06` and `sb01`..`sb05`; (6) the button text is escaped with explicit `ENT_COMPAT` so an apostrophe stays raw instead of becoming `&#039;` under PHP 8.5 default flags, settled by `p13` (the R2 Code-stage era-artifact class).

Embed, `Render/Xhtml/Embed.php`, two corrections inside the pattern-matched branch: (1) a `javascript:` or `vbscript:` scheme (case-insensitive, leading whitespace trimmed) in the `src` attribute makes the whole embed render empty, where the fossil passed the iframe through, settled by `p17`, `se02`, `se04`, `se06`; (2) a dangerous scheme in any other attribute value falls through to the no-match error block, settled by `se03`. A `data:text/html;base64` src passes through unchanged (`se05`), so the check targets the script schemes specifically.

File, `Render/Xhtml/File.php`, two corrections: (1) the file path is percent-encoded selectively, only spaces and non-ASCII bytes (uppercase hex over UTF-8 bytes), in both branches, settled by `p15`, `pf04`, and the negative controls `pf01` (`+` raw), `pf02` (`%` raw), `pf03` (`#` raw); (2) the href attribute value and the anchor text are escaped with `htmlspecialchars(..., ENT_COMPAT, 'UTF-8')`, where the fossil emitted both raw, settled by `p17`, `pf05`, `pf06`, `ff01`.

Gallery, `Render/Xhtml/Gallery.php`, three corrections: (1) the external-source branch no longer forces `$size = "original"`, so external items take the gallery's effective size class while keeping the URL as the image source, and the loop-carried poisoning of later items is gone, settled by `p14`, `p15`, `pg01`, `pg02`, `pg04`; (2) the item image emits the parsed `alt` attribute (ENT_COMPAT-escaped) instead of a hardcoded empty one, settled by `p19`, `ga-x15`, `pg03`; (3) the attachments branch's empty message now reads `Sorry, we couldn't find any images attached to this page.`, settled by `p01`, `p02`, `p20`, `p21` (that branch is environment-bound, so this string is verified against the captures and the rule source, not by an in-harness render).

User, `Render/Xhtml/User.php`, one correction: the not-found message is now `<em>%s</em> does not match any existing user name` with the name ENT_COMPAT-escaped, inside the fossil's existing `error-inline` span, replacing `User <em>%s</em> can not be found.` with the raw name, settled by `p05`, `p06`, `p14`, `p17` for the wording and `p15` for the escaping. The render's found-user path is environment-bound by design (it delegates to the user directory and `WDRenderUtils::renderUser`, neither present in the reference tree), and the parse rule agrees with live on every probed shape.
