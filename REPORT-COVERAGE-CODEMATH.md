## Named remainders

R-1 (reachability of a Code source span inside Mathinline): Code's regex is `^\[\[code...\](\s|$)` with the multiline flag, so `[[code]]` matches at line start. A newline that puts `[[code]]` at line start inside `[[$ ... $]]` is itself a Newline token, and Newline is in the suppress set, so the body empties before a Code source span would be expanded. The SUSPECT3 row m1-code is therefore `miPlain`. The retained reference render and the mirror render are `<p>A <span class="math-inline">$[[code]]x[[/code]]$</span> B</p>`. REFCORR6's note on m1-code is the Url described-pass yield of the `$]` fragment, which lets the math span form. `miSource` stays page-reachable through Url and Email, and `cm_mi_source_url` is the closed pin for the source-span arm. The fuzz row `mi-plain-code` expects `miPlain` and passed on both seeds.

R-2 (unpageable classes, byte column uncomparable): `miDepth`, `miUnknown` and `miCycle`. No saved page enters depth greater than 64, a placeholder whose id has no token, or an id already on the seen chain. The designed pins are `driver.php` direct mode plus `cm_mi_depth_beats_suppress`, `cm_mi_unknown_keeps` and `cm_mi_cycle_keeps`. Four cases per class per seed were generated. The PHP direct call returned ok on all 24. They are recorded as uncomparable, on the same pattern as the inline lane's `flSite` and `imFlickr`, because the mirror side of those three arms is the closed theorems.

R-3 (non-class, Text_Highlighter): a Code type in the fourteen-name list is the R4.7 external boundary (REPORT-R47.md, REPORT-R48.md). `codeShapeOf` returns `none` there (`cm_highlighter_nonclass`). `cm_code_langs_fourteen` proves the list length, and `cm_code_python_boundary` exhibits `Python`. Retained battery rows include code/arg-type-python, code/arg-type-PYTHON, code/arg-two-attrs, code/crlf-args, code/arg-type-css-inline, code/arg-tab-after, code/arg-multi-space, code/arg-newline-after and code/arg-type-name. The boundary is a disposition, and it has no constructor.

R-4 (non-class, Math PNG-exists path): `Render/Xhtml/Math.php` would consult the site temp directory, the filesystem and `LatexRenderer` when the PNG exists. The harness renderer is a no-op, so the PNG never exists and every valid type takes the fossil failure block, including the spelling "prabably" (REPORT-R48.md). `cm_math_png_nonclass` is the definitional equality of `renderMath` with that cascade: an invalid type is the unsupported-environment block, and every other option map is the fossil block. The real-LaTeX arm has no constructor.

R-5 (non-class, dead filename prefix): `Render/Xhtml/Code.php` prefixes a filename when the `css_filename` conf is set. The harness leaves that conf unset. `renderCode` does not read a filename option, and `cm_code_filename_dead` shows a token that carries `filename=a.txt` rendering as the same token without it.

R-6 (counter, and a dead read already recorded elsewhere): the equation id is absent from harness HTML, so the counter is a pair of closed theorems (`cm_counter_starts`, `cm_counter_on_invalid`, `cm_counter_on_fatal`) plus the fuzz comparison of PHP `math_id` and the r34 token state, and it is a property of the four Math classes. On a fatal guard the token is absent, `mathId` is `some 2`, and `equations` stays empty. `equationsArray` is written only after the guard. Footnote's read of that map is the dead read the notes lane already recorded, and it is a property of that family.
