# CORRECTION-C-R5E-P3-1 — right-trim trailing whitespace of the Image `width` attribute (round 5e)

Evidence. Candidate `C-R5E-P3-1` was confirmed on a valid, stable, saved-source-matching live capture `muse-probe-round5e-p3-p3e-08-img-width-trailing` (html_sha256 `5ba9cb3bf1de4861fc1bf970c573b191d89482e3b84a9bf4b266e880f13d150e`): source `[[image IMG.png width="10 "]]` serves `<img src="https://sandbox-for-codex.wdfiles.com/local--files/muse-probe-round5e-p3-p3e-08-img-width-trailing/IMG.png" width="10" alt="IMG.png" class="image" />` while the canonical reference at `ref.jsonl` line 8 emits `<img src="/local--files//IMG.png" width="10 " alt="IMG.png" class="image" />`. The decisive rule-level byte is the `width` attribute value: live `width="10"` against reference `width="10 "`. The wdfiles host and page path on `src` are the documented owned serving surface and are masked in `comparison.json`, not part of the claim. P3E-10 independently confirms the same width trim in a multi-attribute context (record C-R5E-P3-3).

Mechanism. `ref-php/text-wiki/Text/Wiki/Parse/Default/Image.php:144-167` copies only the whitelisted attributes into the option map, and the REFCORR11 fix at `Image.php:216-219` applies `rtrim($options['attr']['link'], " \t\n\r\f\v")` to the `link` value only, immediately before token emission. Every other whitelisted value, including `width`, is carried from `Parse.php::getAttrs` verbatim. The Xhtml renderer `ref-php/text-wiki/Text/Wiki/Render/Xhtml/Image.php:207-219` emits `class`, `alt`, `style`, `width`, `height` and `title` through `htmlspecialchars` with no trim, so the authored trailing space survives into the served `<img>` tag. The fix is to right-trim the `width` value over the rule's own ctype_space / PCRE `\s` byte set {space 0x20, tab 0x09, LF 0x0A, VT 0x0B, FF 0x0C, CR 0x0D} at the same attribute-consumer point as the existing link trim, applying it to `width` in addition to `link` and leaving `title` and `alt` byte-identical (P3E-06 and P3E-07 are byte-clear). The trim is at the consumer, not in shared `getAttrs`, so no other rule's attribute values change.

Mirror consequence. `lean-ftml/LeanFtml/ParaRules.lean:294-300` builds `attr2` from all whitelisted keys verbatim, and the REFCORR11 twin at `ParaRules.lean:321-322` maps `rtrimImageHrefWs` over only the `link` pair into `attr4`; `ServingRules.lean:411-420 imageAttrEmit` emits the `width` value through `htmlSpecialCharsCompat` with no trim. The mirror is therefore inferred by source reading to emit `width="10 "` and to carry the same divergence; no Lean elaboration was run in this evidence-only unit.

Scope. No canonical file, ftml file or source file was edited by this unit; no cargo, git identity override or git stash was used. Canonical adoption, the mirror patch and gate regeneration remain coordinator actions outside this unit's write set.
