# CORRECTION-C-R5-P3-2 — Tableadv upper-case data- attribute key

Candidate `C-R5-P3-2`, family Tableadv, confirmed by unit R5-P3 on the post-REFCORR7 ground. Minimal source is a one-row advanced table whose head is `[[table data-Foo="UP"]]` (case id `p3-13-tableadv-upper-data`, page `muse-probe-round5-p3-p3-13-tableadv-upper-data`). The capture is valid, stable and saved-source-matching (`captures.json`, html sha256 `9ab15922b3aa5f5873a21f03646467deab6126758dbf4025cf56e95df04d1442`). Decisive live bytes are `<table data-foo="UP">` followed by the ordinary row and cell tags; the canonical reference render is `<table>` with no attribute (`ref-render.jsonl`, line 13). Live lower-cases the `data-` suffix spelling and keeps the attribute; the reference drops the pair. This is a rule-level attribute-filtering value, not a serving surface: the rest of the table is byte-identical after the owned newline mask.

Owning reference file is `ref-php/text-wiki/Text/Wiki/Parse/Default/Tableadv.php`, where `buildAttrs` at line 152 applies the case-sensitive key grammar `^[a-z][a-z0-9-]*$` before `isSafeAttr` at lines 136-144; `data-Foo` fails the grammar and is silently dropped even though the `data-` prefix is allowlisted. The mirror transcribes the same gate in `lean-ftml/LeanFtml/TableRules.lean`: `advKeyOk` at lines 368-373 rejects any upper-case byte, and `advAttrStep` at line 388 drops a key that fails it. Source reading therefore infers the same mirror divergence; no Lean elaboration was run by this unit. The adopted List and Div behavior in `REPORT-SPEC-INTENT-RECLASS.md` rows 7 and 15 already pins `data-Foo` to become `data-foo` while `DATA-foo`, `CLASS` and `ID` are dropped, so the fix owner should align Tableadv's key handling with that established live rule without widening the safe-attribute allowlist or re-enabling `aria-*` / `align`.
