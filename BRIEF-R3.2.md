## The design point this stage must get right

This is the first stage where the obligation recorded in REPORT-R31.md binds: Form, Raw, and Rawold run after Code, so when they scan, the working source can already contain Code placeholders. In the reference, those placeholders are byte text (\xFF, digits, \xFF) inside the string the rules' patterns match against, and a pattern can in principle interact with them (a raw run starting before a code block and ending after it is the shape to think about). Your mirrors must therefore operate on the byte-form view of the state (TokenState.lean's byteForm) wherever the reference's rule operates on the whole current source, and the report must state, per rule, whether the byte-form view was needed and what evidence settles it (a fuzz family that places code blocks inside and around raw and form shapes is the minimum evidence). Reproducing the R3.1 segment-only shortcut for these rules without that analysis is a stage failure even if the corpus passes.
