# REPORT-ADOPT-CORR: adoption of the HTMLCHARS and X44 reference corrections into the Lean mirror, with gate regeneration

This lane discharged the Lean mirror consequences of the two reference corrections the coordinator had already adopted into the canonical reference PHP (the HTMLCHARS correction of REPORT-HTMLCHARS.md: six fossil renderers' bare `htmlspecialchars()` calls made explicit as `ENT_COMPAT, 'UTF-8'`; and the X44 correction of REPORT-X44.md section 4: the described Interwiki label pattern narrowed from the lazy `(.+?)` to the class `[^\]\[\n<delim>]+`). The worktree's reference PHP was taken as given and no PHP file was edited (a full-tree diff against the canonical tree at the end of the lane shows the worktree `ref-php/` identical to canonical except the pre-existing absence of the `fossil/` directory). ftml was not touched. All gate artifacts named below were regenerated on WSL (PHP 8.5.4) from this worktree's corrected reference, with the pre-regeneration files kept beside each artifact under the suffix `.pre-adoptcorr`.

## 1. The six mirror changes

Five escape switches, each replacing the mirror of PHP 8.5's bare-call defaults (`htmlSpecialCharsQuotesSubst`, ENT_QUOTES | ENT_SUBSTITUTE) with the mirror of the corrected explicit call (`htmlSpecialCharsCompat`, ENT_COMPAT) at exactly the sites the HTMLCHARS lane corrected, and one parse-side guard for the X44 correction.

1. `lean-ftml/LeanFtml/InlineSimpleRules.lean`, `renderUrl`: the href escape, the text escape, and the target-attribute escape now use `htmlSpecialCharsCompat` (Url.php's four corrected calls; the fourth, the image-branch filename, belongs to the harness-disabled branch and has no mirror site). The doc comment records the correction and its probe basis.
2. `lean-ftml/LeanFtml/InlineSimpleRules.lean`, `renderInterwiki`: the text escape now uses `htmlSpecialCharsCompat` (Interwiki.php's corrected call; the file's second corrected-era call escapes the constant target `_blank` inside what the mirror emits as a template literal, so no Lean site exists for it).
3. `lean-ftml/LeanFtml/RawHeadingRules.lean`, `renderRawold`: the body escape now uses `htmlSpecialCharsCompat` (Rawold.php's single corrected call).
4. `lean-ftml/LeanFtml/InteractiveRules.lean`, `renderButton`: the class and style escapes now use `htmlSpecialCharsCompat` (Button.php's two corrected calls; the text call was already ENT_COMPAT in the fossil and its mirror already used the Compat helper).
5. `lean-ftml/LeanFtml/ServingRules.lean`: `renderFreelink` (all seven corrected calls across its URL, site, and local branches), `imageAttrEmit` (key and value; the key side is inert because the emitted names are a fixed whitelist), and `renderImage` (src, fallback alt text via `phpBasename`, and href) now use `htmlSpecialCharsCompat` (Freelink.php's seven and Image.php's five corrected calls). The module header's escape paragraph was updated to match.
6. `lean-ftml/LeanFtml/Inline1Rules.lean`, `interwikiDescrMatch`: the described-form label is no longer scanned by the lazy `lazyTail`; it is scanned by the existing class-bounded `descrTail` over a new predicate `iwLabelB` (every byte except `]`, `[`, newline, and the token delimiter byte 255), which is exactly the corrected PHP class `[^\]\[\n<delim>]+` followed by the closing bracket. On the brief's parenthetical: the newline is excluded by the class itself, and the closing bracket is excluded in the strong sense that no `]` may appear anywhere in the label; this is one place where the corrected pattern is stricter than the old lazy scan's construction, which treated a `]` in the first label position as content (the fossil's `(.+?)` claimed the text `]` for the input `[site:page]]`; the corrected class claims nothing there), so the class-run scan was chosen over merely filtering `lazyTail`'s result on the delimiter and `[`, because it mirrors the corrected pattern byte-for-byte on that edge as well. `lazyTail` itself is unchanged and still serves Email's described form, whose reference pattern remains a lazy `.+?`. The module header's recorded-remainder paragraph (which carried the x44 remainder as mirrored-as-is since R3.12) was rewritten to record the correction's adoption, and the matcher and helper doc comments were updated to say which scan serves which rule and why.

## 2. Theorem consequences

Three theorems asserted the old escaping on an apostrophe-bearing value and were restated; each restated doc comment records that the change is the HTMLCHARS correction of the reference, on the probe evidence of REPORT-HTMLCHARS.md, and not any change in live behaviour. `url_text_apostrophe` (`LeanFtml/InlineRender.lean`): the expected label is now `it's` raw, previously `it&#039;s`. `interwiki_text_apostrophe` (`LeanFtml/InlineRender.lean`): the same restatement. `rawold_apostrophe` (`LeanFtml/RawHeadingRender.lean`): the same restatement. These were the only theorems in the tree asserting `&#039;` for the six corrected functions; the `&#039;` expectations that remain (Tableadv attributes in `ListTableRender.lean`, the Bibliography documentation in `NotesRender.lean`, Collapsible's separate `htmlSpecialCharsQuotes` helper) belong to files the HTMLCHARS lane did not correct and are untouched.

Proof repairs where the statement was unaffected but the proof routed through the old helper: the three Button theorems carrying a `wiki-standalone-button` class characterization (`button_edit_default`, `button_upper_type`, `button_settags_text` in `LeanFtml/InteractiveRender.lean`) now prove that characterization for `htmlSpecialCharsCompat` via `htmlSpecialCharsCompat_ascii`, and `button_edit_full`'s one-byte class/style facts were switched to the Compat helper (they still close by `rfl` at one byte); the Freelink and Image theorems in `LeanFtml/ServingRender.lean` (`freelink_exists_anchor`, `freelink_new_anchor`, `freelink_title_missing_fallback`, `image_plain_local`) had their rewrite lists switched from `htmlSpecialCharsQuotesSubst_ascii` to `htmlSpecialCharsCompat_ascii`, statements unchanged. The eleven `renderUrl` theorems and the two known-site `renderInterwiki` theorems in `InlineRender.lean` were previously plain `rfl` proofs, which was safe only because the old helper carries no UTF-8-validity guard; the Compat helper guards on `utf8Valid`, whose kernel reduction is prohibitively expensive (the programme's standing R4.4/R4.6 finding), so those thirteen proofs were converted to the programme's standing pattern (option lookups and branch facts as `rfl` haves, each escape discharged through `htmlSpecialCharsCompat_ascii`, assembly closed by `simp only` and a final literal `rfl`), and the two other Rawold theorems (`rawold_plain_spaces`, `rawold_angle`) were converted to the same pattern for uniformity. Two new worked examples pin the X44 guard at the matcher level, with axiom-audit lines added to `Main.lean` beside the existing interwiki examples: `interwikiDescrMatch_placeholder_label_none` (a label carrying an earlier rule's token placeholder, the x44 shape, fails the described match) and `interwikiDescrMatch_bracket_label_none` (a label containing an opening bracket fails the match); the pre-existing `interwikiDescrMatch_example` passes unchanged.
