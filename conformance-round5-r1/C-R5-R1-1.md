# C-R5-R1-1 — Div whitespace-only id keeps the bare u- shell on live

Minimal source: `[[div id="   "]]\nbody\n[[/div]]`.

Decisive live bytes: `<div id="u-">\n<p>body</p>\n</div>`.

Reference bytes (ref-php harness batch.php render, ref.jsonl line for R5R1-D1): `<div id=""><p>body</p>\n\n</div>`.

After the standard mask the live form is `<div id="u-"><p>body</p></div>` and the reference form is `<div id><p>body</p></div>`; the surviving difference is the rule-level attribute value `id="u-"` versus `id=""`, not an ordering, newline, entity-spelling, tab-id or Stage 2 frame surface.

Mechanism: `Text_Wiki_Parse_Div::isolateId` maps a whitespace-only id to the bare `u-` shell, and `Text_Wiki_Render_Xhtml_Div::token` (ref-php/text-wiki/Text/Wiki/Render/Xhtml/Div.php lines 59-62) clears any `id` whose value is exactly `u-` to the empty string while keeping the key. Live does not clear it: it serves `id="u-"`. The REFCORR4 Batch C correction therefore over-generalises from the placeholder-consumed case to the whitespace-only-id case; this probe establishes the divergence only for the bare-`u-` arm and does not re-examine the 0xFF placeholder-byte arm.
