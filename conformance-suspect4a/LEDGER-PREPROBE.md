# LEDGER-PREPROBE — SUSPECT4-A, written before any live probe (2026-11-22)

Method: the standing method of the programme. Live Wikidot behavior is definitional; every entry below was written before the create/capture run. Evidence order is ftml corpus and integration pins, then frozen parity captures, then fresh live sandbox probes fetched once and cached. No ftml file was edited, no cargo was run, and the reference harness was used only locally to understand the code paths. The sources in cases.jsonl are generated by this script from the same table as this ledger, so the ledger's construct text and the probed source cannot drift. Live bytes are compared with the reference after masking the already-owned Stage 2 frame surface (inter-tag newlines, trailing paragraph newlines and the saved-page wrapper); a difference that survives that mask is a divergence.

## S4A-L1 — List (post REFCORR5 batch 1)

Construct: A nested explicit list whose inner opener is uppercase and whose inner closer is lowercase: [[ul]] / [[OL]] / [[/ol]], plus a three-level UL>ol>ul variant.

Why it looks wrong: Batch 1 stores the opener's raw case on the pairing stack while lowercasing the closer, so an uppercase inner opener never pairs; the reference then absorbs the tail into an unclosed list and leaves [[li]]b literal. The frozen pinned sibling lc-sib-nested-lower-ul-upper-ol used an uppercase inner closer and served live-clean; the lowercase-closer variant was never probed, so the asymmetry the fix introduced is only half measured.

Confirm byte: Live serves a clean nested list containing <li>b</li> with no literal [[li]] residue, while the reference leaves [[li]]b inside a swallowed <ul> (or emits a differently shaped list).

Clear byte: Live also leaves the inner item literal / swallows the tail exactly as the reference does.

Probe sources: s4a-l1a, s4a-l1b

## S4A-L2 — List (post REFCORR5 batch 1)

Construct: A cross-type uppercase closer in the reverse direction and with trailing prose: [[ol]]...[[/UL]] and [[ul]]...[[/OL]]trailing.

Why it looks wrong: The closer gate compares the raw-case stack tag to a lowercased closer and also requires the same tag, so a cross-type uppercase closer fails and the reference leaves the whole block literal in a <p>. The pinned lc-sib-cross-ul-ol-upper shape recorded live producing a clean list; the reverse type and the trailing-text variant were not pinned.

Confirm byte: Live serves a clean <ol>/<ul> list (with or without the trailing text) where the reference serves literal wikitext inside <p>.

Clear byte: Live also keeps the block literal exactly as the reference does.

Probe sources: s4a-l2a, s4a-l2b

## S4A-L5 — List (post REFCORR5 batch 1)

Construct: Duplicate case-variant attribute keys on [[li]]: CLASS/class, ID/id, data-FOO/data-foo, DATA-FOO/data-Foo in one item.

Why it looks wrong: getAttrs preserves key case and buildListAttrs drops uppercase keys and lowercases only the data-* suffix, so the reference emits class="d" id="y" data-foo="2"; live's treatment of duplicate case-variant keys on an item was never probed, and HTML attribute names are case-insensitive, so live may keep a different key or order.

Confirm byte: Live's emitted attribute set or order at the <li> surface differs from the reference's class="d" id="y" data-foo="2".

Clear byte: Live emits exactly the reference's attribute set and order.

Probe sources: s4a-l5a, s4a-l5b

## S4A-R1 — Raw composite / Deflist (post REFCORR5 batch 6)

Construct: A run of four @ (one empty Raw token) in the definition narrative: : term : @@@@, : term : def@@@@ and : @@@@ : @@@@.

Why it looks wrong: Deflist's termRendersEmpty strips an empty Raw placeholder only from the term; the narrative is emitted as trim($val[4]) with the placeholder left in. The pinned dl-empty4 probe covered only a whole-term empty Raw, so the <dd> side and both-sides shapes are unmeasured.

Confirm byte: Live's <dd> bytes differ from the reference's (a visible placeholder residue, a dropped <dd>, or a different trim), or the two sides disagree about whether <dt> is omitted.

Clear byte: Both serve the same <dl> bytes at the <dt>/<dd> surface.

Probe sources: s4a-r1a, s4a-r1b, s4a-r1c

The pinned raw-empty proof was the inline 'a @@@@ b' shape; the newline-boundary shapes were not probed, so the order of deletion versus break emission is unmeasured.

Confirm byte: Live's <p> bytes (space count, <br /> placement or paragraph split) differ from the reference's <p>A<br />B</p> shape.

Clear byte: Live serves the same space and break bytes as the reference.

Probe sources: s4a-r3a, s4a-r3b

## S4A-P1 — Prefilter (parse-side first rule)

Construct: Whitespace-only lines made of NBSP, form feed, vertical tab, and a run of space-only lines: a/NBSP/b, a/FF/b, a/VT/b, a/space/space/b.

Why it looks wrong: Prefilter strips whitespace-only lines with /^\s+$/m and compresses (\n[ ]*){3,} to two newlines; PCRE \s includes form feed and vertical tab but not NBSP. Live's save filter may normalize or reject these bytes, and no frozen capture isolates the rule on exotic whitespace lines.

Confirm byte: Live's <p> structure (paragraph split or preserved line) differs from the reference's render.

Clear byte: Live serves the same structure as the reference; if the saved source drops a control byte the case is UNTESTABLE rather than a clearance.

Probe sources: s4a-p1a, s4a-p1b, s4a-p1c, s4a-p1d
