## Byte-form analysis (per rule, before mirroring)

Concatlines is a hand-written `parse()` with no pattern and no token claims: a single left-to-right pass over the source that drops each backslash immediately followed by LF, except that when the line following the pair, trimmed of spaces and tabs, matches `/^\[\[div_?(?:[ \t].*)?\]\]$/i` (the R2 correction C1), the pair is replaced by a kept LF instead. The pair it looks for is two literal bytes (0x5C, 0x0A). A placeholder is the byte sequence 0xFF, ASCII digits, 0xFF; the pair can neither start nor end inside a placeholder, because a placeholder contains no backslash and no LF, so the rule's matches never overlap placeholder bytes and its output segmentation relative to earlier tokens is the same on both sides. The div-opener test, however, reads the bytes of the following line, which may contain whole placeholders (a `[[code]]` opener claimed earlier on that line, for instance); the test then fails on both sides identically, because the placeholder bytes are not `[`, `d`, `i`, `v`, or space/tab. The mirror reproduces the scan byte-for-byte, including the single-pass property (a dropped pair never creates a new pair across the join: the R2 battery's cascade cases, and the fuzz family's backslash runs, pin this).

Freelink's pattern is `/\[\[\[([^\]\[]+?)(\|[^\]\[]*)?\]\]\]/`: its classes exclude only `[` and `]`, so a claim can span a whole placeholder in the target or the label (0xFF and digits are admitted), and cannot start or end inside one (a placeholder contains no bracket bytes, and the closing `]]]` cannot be formed from placeholder bytes). The claimed token's options are derived from the captured bytes by `process()`, transcribed step for step in the mirror: the literal no-claim returns (empty target, target starting with `|`, target matching `/^#[^ \t]/`, target containing `##` or more than one `#` without `/#/`), the `/#/` hash-route and `#` anchor peeling with their exact trimming and reassembly, the URL branch (a case-insensitive prefix test against the reference's 29 schemes, requiring no leading space, leaving the target untouched as `url` with the page emptied), the transliteration gate, the `_default:` strip, the slug via `WDStringUtils::toUnixName`, and the display-text rules ending in `textFromTitle`, set true exactly when the label part trims to exactly `|`. Because option values are derived from the target bytes, a placeholder inside the target flows through `toUnixName` as bytes: 0xFF is not a slug byte and becomes a dash, and the placeholder's digits survive as slug digits (see the protocol-boundary note below). A placeholder inside the label flows into the `text` option unchanged and is compared by content under the protocol's `$bytes` wire encoding (74 fuzz tokens per seed carry such values; the corpus's placeholder interactions are in the Equationreference family, next paragraph). Transliteration can never fire on a placeholder-spanning target: the gate's `/u` probe fails on the 0xFF byte, so the mirror's UTF-8 validity check rejects it identically.

Equationreference's pattern is `/\[\[eref (.*?)\]\]/`, case-sensitive (a deliberate contrast with Math's case-insensitive opener, pinned in R3.4), with `.` excluding LF, so a label can span whole placeholders (the corpus cases x-free-math-label and x-eref-nested-freelink carry labels that are exactly one Freelink placeholder's bytes, compared as `$bytes` on both sides) and cannot start or end inside one or cross a newline. The token's only option is the PHP-trimmed label.

## The equations map at parse: what is pinned, and a correction to the brief's premise

The brief asked for the Equationreference mirror to read the equations map pinned in R3.4, including the render side's head-fallback behavior. Reading the reference's parse file shows the premise needs correcting, and the correction is recorded here plainly: the Equationreference **parse** rule reads nothing. Its `process()` returns the trimmed label as the token's only option; the equations map is never consulted at parse time. The lookup lives in the Equationreference **render** rule (`Text_Wiki_Render_Xhtml_Equationreference`), which resolves the label against the render-time copy of the map, rendering an empty number for an undefined label and the last registration for a duplicated one; rendering is outside R3's parse-only scope (R3-SCOPE.md), so no part of that lookup is mirrored in this stage, and the head-fallback behavior the brief mentions is an ftml-side behavior with no counterpart in the reference's parse rule at all. What this stage pins about the map is its write side and its carriage: the map and the counter are written only by Math (R3.4's mirror, last-registration-wins via the ordered-map overwrite), they are part of the compared parse state (`equations` and `mathId`, serialized by the state driver since R3.4), and all three LINK rules leave them untouched, which the 221-case corpus comparison verifies on every case, including the interaction battery's duplicate-label, forward-reference, and case-mismatch shapes. A future render-equivalence tier will need the render rule's resolution semantics; they are recorded here so that tier does not have to rediscover where the lookup lives.

## The Freelink helper tables

`WDStringUtils::toUnixName` is a five-step byte pipeline (trim of space, tab, LF, CR, NUL, VT; `strtr` with the CONVERT_ARRAY table, longest key first, replacement values not rescanned; ASCII lowercasing; replacement of every non-slug byte with `-`; the leading-underscore and post-colon underscore passes, where the colon exception is the regex's one-byte lookbehind on the subject; leading/trailing dash stripping; and the ordered `str_replace` passes `---` to `-`, then `--` to `-`, then `:-` to `:`, then `-:` to `:`), and the mirror transcribes each step as a byte function, with the final `str_replace` passes modeled as single left-to-right non-overlapping replacements exactly as PHP performs them. Both character tables were extracted from the reference behaviorally rather than transcribed from source: the transliteration map was probed per codepoint from U+0080 to U+3000 through `WDStringUtils::transliterate` itself on the WSL scratch copy, yielding exactly the 468 mapped codepoints the R2 LINK section records (unmapped codepoints become a single space), and the CONVERT_ARRAY was dumped as PHP resolves it, 191 entries with duplicate keys already collapsed to their last value, keys of one or two bytes. Probing also confirmed the R2 section's sharpest quirk firsthand: when transliteration fires (target contains a non-ASCII byte and is valid UTF-8), the reference's separator branch turns even ASCII letters into spaces, so `café` transliterates to ` e` and its slug is `e`; the mirror reproduces this because it applies the same per-character case split, and the fuzz family's mixed ASCII-and-accent targets pin it differentially.

## Conformance, fuzz, and the one protocol boundary

The stage corpus (221 cases, `conformance-r3/link-all-cases.jsonl`) was run through the restricted seventeen-rule oracle (`harness/state-restricted.php` with Prefilter, Delimiter, Code, Form, Raw, Rawold, Modulepre, Module, Module654, Iftags, Comment, Iframe, Date, Math, Concatlines, Freelink, Equationreference) on the WSL scratch copy and through the Lean R3.5 driver, and compared with this stage's `compare.py` (copied unchanged from the R3.4 stage; it already carries the equations state and the PARSE-FATAL class): **221/221 cases match, zero fatal records, zero error records on any side** (`comparison-link.txt`). No harness change was needed in this stage: the R3.4 state driver already serializes everything the LINK family requires. The fuzz differential (`fuzz_r35.py`: backslash-newline runs and div-opener variants; freelink targets and labels across pipes, anchors, hash routes, malformed multi-hash forms, URL schemes with and without a leading space, `_default:` and colon forms, whitespace and empty targets, bracket runs, and non-ASCII targets in Latin, Cyrillic, and CJK; eref labels against generated math blocks in defined, forward, duplicate, and case-mismatched arrangements; and placeholder-spanning mixtures with continuations inside and around code, raw, and math spans and claims inside iftags bodies under both polarities) passes **500/500 on seed 20261120 and 500/500 on seed 7**, with 74 tokens per seed carrying placeholder bytes inside option values, all compared by content.

One boundary deserves its own paragraph because a future stage will meet it again. An ad-hoc probe set (`conformance-r3/adhoc/`, four cases) included a Freelink whose target is exactly one Raw placeholder (`[[[@@span@@]]]`). In batch mode the two sides diverge on that one case: the oracle's `page` option is the string `2` where the mirror's is `0`. The cause is not in either implementation of the rule: the oracle numbers tokens with a process-global counter cumulative across the batch, so in that run the Raw token was number 2, the placeholder bytes in the source were 0xFF `2` 0xFF, and `toUnixName` turned them into the slug `2`; the mirror numbers per document, as production does, giving placeholder 0xFF `0` 0xFF and slug `0`. The conformance protocol's renumbering canonicalizes placeholder references in segments and in `$bytes` option values, but a slug is a derived plain string in which the placeholder no longer exists as a placeholder, so renumbering cannot reach it. Run one case per process (the per-document numbering production parses under), all four ad-hoc cases match, including the target-spanning one (`adhoc/adhoc-comparison-isolated.txt`; the batch transcript is kept beside it). The stage corpus contains no target-spanning case (its placeholder interactions keep placeholder bytes inside values that stay placeholders: labels and eref labels), so no corpus case is affected; the boundary is recorded here as a property of the batch oracle, in the same family as the token-numbering canonicalization R3-SCOPE.md already documents, and any future corpus case whose derived string consumes placeholder digits must be run in isolation to be meaningful.
