# REPORT R3.4: the NEXT family mirrors (Iftags, Comment, Iframe, Date, Math)

Stage R3.4 extends the R3 pipeline from nine mirrored rules to fourteen, adding Iftags, Comment, Iframe, Date, and Math in reference order, together with the stage's three new protocol elements: the per-case page construction in the state driver (the tags construction), the compared-state extension (Math's equations map and math_id counter), and the PARSE-FATAL agreement class for Math's ProcessException guard. Every gate the brief lists passes. The final corpus is 382 cases (iftags battery 80, comment battery 62, iframe battery 83, date battery 60, math battery 76, interactions 12, smoke 9) with zero exclusions; the Lean model matches the restricted reference on all 382 (with the five fatal cases agreeing in the PARSE-FATAL class), on 1,000 seeded fuzz cases, and on the full R3.1, R3.2, and R3.3 regression slices re-run with their own drivers. The mandatory consistency check agrees on all 382 cases. No live probing was done in this stage, and nothing outside this worktree was edited (the canonical record was only read, for the R3.2 fuzz inputs).

## The disclosed driver and protocol changes

The tags construction (state driver). `ref-php/harness/state-restricted.php` hardcoded `new RefPage('', 0, array())`, an empty tag list for every case, which cannot reproduce the 77 tag-carrying cases in the Iftags battery (a positively tagged body would be dropped no matter what the case's tags say). The driver now constructs the per-case page exactly as `harness/batch.php` does (lines 51 and 61 of that file): `$caseTags` is the case's "tags" array when it is an array and the empty array otherwise, and the page is `new RefPage('', 0, $caseTags)`, always injected. The Lean driver reads the same field: ConformanceR34's `jsonTags` extracts the case's "tags" array of strings (sought after the "source" value, so tag-shaped text inside a source cannot be mistaken for the field) into `DocState.page.tags`. The inventory of what Iftags' parse actually reads, from the corrected rule file, is exactly one thing on the harness path: `vars['page']`, and from the page only `getTagsAsArray()`. The fallback branch (vars['pageName'], `$GLOBALS['site']->getSiteId()`, `DB_PagePeer::selectByName`) runs only when no page object is set, which the harness never does since the page is always injected, and the second guard (a still-falsy page returns null, dropping the body) is likewise unreachable; the model therefore models the tag list and nothing else, and `DocState.page` already carried it. The same construction was applied to the one-off prefix tool (`ref-php/harness/prefix-source.php`), which R3.4 uses as the consistency surrogate exactly as R3.3 did; without it the prefix run would disagree with the tags-honoring fixtures on tag-gated bodies for driver reasons, not reference reasons. Both files disclose the change in their own comments.

The compared-state extension. Math's process() maintains two pieces of observable document state besides the token table: `vars['math_id']` (the counter, initialized to 1 on first use and incremented per call) and the process-static `Text_Wiki_Parse_Math::$equationsArray` (label to id, written per successful call, read later by the LINK stage's Equationreference). Both are now part of the compared state, serialized identically on both sides: each state record gains "equations" (the label/id pairs in insertion order) and "mathId" (the counter, or null before the first Math match). The PHP driver emits them from the live objects; the Lean serializer (`serState` in TokenState.lean) emits them from `DocState.equations` and `DocState.mathId`, which the Math mirror maintains. One serialization subtlety is handled on the PHP side: a purely numeric label becomes an integer array key in PHP, so the driver casts each key back to string on emission, matching the model's string keys exactly (labels are drawn from `[a-z0-9_]` plus trimmed whitespace, so only plain numerals are affected). Per-case isolation for the static map follows the batch.php precedent: the driver resets `Text_Wiki_Parse_Math::$equationsArray` per case, since a process-wide static would otherwise leak one case's equations into the next case's record. The extension's effect on earlier stages is confined to the wire shape: the R3.1 through R3.3 drivers, rebuilt against the extended serializer, emit the same two fields at their empty values (empty map, null counter, since Math never runs there), and their comparison copies ignore fields they do not read; the R3.3 slice was nevertheless verified against its own recorded outputs, as the brief requires, and passes there too (see the regression section).

The PARSE-FATAL protocol. Math's process() throws `ProcessException("Invalid LaTeX expression(s) found.")` when the trimmed body matches `/include\s*\{|input\s*\{/is`, and the throw aborts the whole parse (the enclosing `preg_replace_callback` never returns, so the rewritten source is never assigned). The restricted driver catches ProcessException per case and emits the fatal record `{"id": ..., "fatal": "ProcessException: Invalid LaTeX expression(s) found."}` — the same shape the pre-seeded full-pipeline fixtures carry — while other Throwables keep the error record. The Lean side reproduces the throw decision in the mirror: `mathProcess` returns no token when `mathGuard` (the byte-level mirror of the guard regex over the trimmed body) fires, `mathScan` aborts the pass, `ParseState` gains a `fatal` flag, the runner applies no further rules to a fatal state, and the driver emits the identical fatal record. The comparison (conformance-r3/compare.py) gains the PARSE-FATAL class: a fatal record passes only against an identical fatal record on the other side (verdict PASS-FATAL, counted separately in the summary), and a fatal on exactly one side, or two with different messages, fails as FAIL-FATAL. The mirror reproduces the pre-throw mutations exactly, as the brief requires: process() initializes and increments the counter BEFORE the guard is tested, so a throwing call still moves mathId (from a fresh document, to 2), and the equations-map write happens only after the guard passes; on abort the state keeps the rule's input source (PHP's assignment never happens) while the token claims and document mutations of the calls that already ran persist. The stage's fatal counts: the corpus carries exactly five fatal cases, all in the Math battery (include-brace, input-brace, include-in-word, include-uppercase, include-in-label-block), and all five agree (SUMMARY-FATAL: 5 parse-fatal agreements, 0 fatal mismatches); the fuzz runs add 13 agreements on the default seed and 18 on seed 7, with no mismatches anywhere.

## Per-rule byte-form analysis

All five rules run after token-producing rules, so all five mirrors work on the byte form (four through `applyByteRule`; Math by hand, since it also moves document state and can abort). Iftags: a match can neither start nor end inside a placeholder, because its boundaries are the ASCII opener and closer literals and a placeholder holds no `[` or `]` byte; the spec run `[^\]]*` and the body can span whole placeholders, the body is spliced back as bytes, and the gate reads only driver state (the page's tags), never source bytes. Comment: matches are found over the byte form exactly as `preg_match_all` finds them; the opener `[!--` and closer `--]` are ASCII and cannot fall inside a placeholder, but the dot-all body can span one, so a claimed Comment text can be `OptVal.bytes`; the line-start and line-tail computations run over the same bytes PHP's `strrpos`/`strpos` see, and a placeholder holds no newline, space, or tab byte, so it breaks an indented line's whitespace prefix exactly as it does in PHP. Iframe: the URL group can never contain a placeholder, since both segment classes exclude the delimiter byte, so a placeholder ends the URL's final segment like any other excluded byte; the attribute tail `.*?` is dot-all and can span placeholders, so attribute values can be `OptVal.bytes`. Date: the three patterns are case-sensitive and their `.` excludes the newline byte; a placeholder can end the numeric group's digit run, sit inside pattern 2's lazy group, or inside an attribute value (values can be `OptVal.bytes`). One shape is a genuine protocol boundary, recorded here: a Date attribute KEY spanning a placeholder cannot be serialized by the PHP driver, because the wire encoding does not transform array keys and `json_encode` fails on such a record; the shape did not arise in this stage — every corpus and fuzz output on both sides is free of error records (zero in all six output files), and were it to arise it would surface as a FAIL-ERROR, not a silent pass. Math: the pattern is anchored at line starts and no line start falls inside a placeholder (it holds no newline); the label and attribute groups exclude the delimiter byte by their character classes; the body is dot-all and can span placeholders, so a claimed content can be `OptVal.bytes`, and the guard predicate scans the trimmed body bytes exactly as PHP's byte-level `preg_match` does. The evidence settling these points is the corpus itself (382/382 by content, including the interaction battery's placeholder-spanning shapes and the smoke set), the two fuzz seeds (500/500 each, with 40 and 39 PHP-side records carrying `$bytes` values compared by content), and the single corpus case whose value crosses under the encoding, d40-raw-format, whose Date `format` value is a Raw placeholder's bytes on both sides.

Three mirror defects were found by the corpus during this stage and fixed in the mirror (the reference was never at fault; the consistency check below had already validated the oracle before the Lean runs, which is what localizes each defect to the model). First, Iframe's URL was assembled from the mirror's own lowercase scheme literal instead of the subject bytes, losing the scheme's original case; the URL is now the subject span. Second, Iframe's two segment classes excluded the backslash byte, following the rule file's own comment; the built regex admits backslashes in both classes (in the PHP string, `\'` contributes an escaped quote, not a backslash), as the battery's backslash cases and a direct oracle probe of a backslash in an intermediate segment both confirm, and the classes now admit it. Third, Math's process() received the whole group-2 concatenation; group 2 is a repeated capture, so `$matches[2]` holds only its last chunk, and with `type="eqnarray" foo="x"` the visible group is ` foo="x"` alone, the type key is absent, and the type defaults to equation — confirmed against the oracle in both orders before the fix (type last yields eqnarray, type not last yields equation). The mirror now carries each chunk count's last chunk through the head enumeration to process(). A fourth defect, an offset bug in the chunk enumeration's second and later chunks, was caught by the same two battery cases and fixed with it.

On theorems: where a rule admits a clean characterization the stage proves it, and seven new theorems are recorded in Main.lean's R3.4 audit block, each depending on exactly [propext, Classical.choice, Quot.sound] and none on sorryAx: `iftagsRule_tokens` (Iftags claims no token), the gate's keep and drop examples, a worked match for Comment, Iframe, and Date pattern 1, and `mathProcess_guard_example` (the guard fires and the counter has still moved to 2). The two recursive matchers, Iftags' and Math's, carry no worked-example theorems: their enumerations are fuel-based mutual recursions, which do not reduce in the kernel at usable cost (a build attempting them exhausted memory; R3.1 states no codeMatch example for the same reason), so for those two matchers exhaustive conformance is the evidence, as the brief allows, and it is stated plainly here.

## The consistency check

The checker (conformance-r3/consistency_check_r34.py) compares, per case, the restricted fourteen-rule oracle's claim sequences for the stage family (Iftags, Comment, Iframe, Date, Math — Iftags' sequence empty by construction, since it claims nothing) against the full-pipeline side, under the R3-SCOPE canonicalization, with a full-side fatal agreeing only with a restricted-side fatal on the same case. The full side is the pre-seeded fixtures where they exist and the prefix run (Include plus the fourteen rules under the full configuration, page map, and the R3.4 tags construction) where they do not. Two corpus-assembly facts are recorded. First, the id "stray-closer" names two different cases, one in the Iftags battery (a stray iftags closer) and one in the Math battery (a stray math closer); the assembled corpus renames the Math case to "stray-closer-math", with the same rename applied when the Math fixture is loaded, and the battery and fixture files themselves are untouched. Second, the fixtures cover 372 of the 373 battery and interaction cases: the Date fixture file's sixty lines carry fifty-nine case records, and d40-raw-format (`[[date 0 format="@@a@@"]]`, a Raw span inside a Date attribute value, whose full-pipeline record the fixture probe could not serialize — the same gap R3.3 Part 1 closed in the state driver) is the one absence. The prefix surrogate covers it and the nine smoke cases (ten surrogate cases in all), and the surrogate was validated before use: its family claim sequences agree with the fixtures on all 372 cases the fixtures carry (summary A: 372/372, fatal records included). The consistency verdict proper: the restricted oracle agrees with the full side on all 382 cases (summary B: 382/382 consistent, including the five fatal agreements), so the stage corpus has zero exclusions; as supporting evidence, the restricted and prefix runs also agree on the earlier rules' claims (Code, Form, Raw, Rawold, Module, Module654) on all 377 non-fatal cases (summary C: 377/377, the five fatal cases skipped), so on this corpus Include's upstream presence perturbs nothing the stage compares.
