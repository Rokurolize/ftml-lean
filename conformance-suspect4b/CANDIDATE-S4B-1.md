# Candidate C-SUSPECT4B-1 — a leading-whitespace _default: prefix is stripped on live but kept in the reference slug

Status: CONFIRMED divergence, recorded for routing to a later correction round; this lane changes no code. Declared by suspicion rows S4B-08 and S4B-27; the decisive live bytes are in conformance-suspect4b/captures.json (case fl-default-nonascii) and captures-f2.json (cases f2-def-space-label, f2-def-tab, f2-def-2space, f2-def-space-cafe, f2-def-space-upper). The reference bytes are in ref-render.jsonl and ref-render-f2.jsonl from this tree's `php ref-php/harness/batch.php render` over exactly the same sources (zero stderr on both runs). All supporting captures are valid=true, stable=true, saved_source_matches=true.

The construct is in ref-php/text-wiki/Text/Wiki/Parse/Default/Freelink.php lines 190-199. REFCORR5 Batch 5 moved the category strip ahead of transliteration as `if (preg_match('/^_default:/i', $slugSource)) { $slugSource = substr($slugSource, 9); }`, and it is anchored to the start of the raw target before WDStringUtils::toUnixName trims that raw target. A target whose first byte is a space or a tab therefore never strips, and toUnixName's own later trim leaves `_default:` as the leading segment of the slug (its `preg_replace('/^:/','',...)` only removes a colon, not the underscore-prefixed word).

Minimal discriminating source: `[[[ _default:x]]]` (one leading ASCII space inside the triple brackets, LF-only, no trailing newline; probe page muse-probe-suspect4b-fl-default-nonascii's third form and its single-form siblings in the F2 batch). Live serves `<p><a href="/x">x</a></p>` after campaign-standard masking (the raw capture also carries class="newpage", a deliberately masked page-existence surface). The reference serves `<p><a href="/_default:x">x</a></p>`. The decisive difference is one byte string in the href path: live `/x`, reference `/_default:x`; the display text is `x` on both sides.

The F2 controls bound the defect tightly. With the prefix at byte zero (`f2-def-bare`, `[[[_default:x]]]`) both sides serve `/x`, so the REFCORR5 batch-5 strip itself is correct. With any leading whitespace the reference keeps `_default:` while live strips it: one space with an authored label (`f2-def-space-label`: ref `/_default:x`, live `/x`), one tab (`f2-def-tab`: ref `/_default:x`, live `/x`), two spaces (`f2-def-2space`: ref `/_default:x`, live `/x`), a non-ASCII suffix (`f2-def-space-cafe`, `[[[ _default:Café]]]`: ref `/_default:cafe`, live `/cafe`) and an uppercase prefix (`f2-def-space-upper`, `[[[ _DEFAULT:X]]]`: ref `/_default:x`, live `/x`). A prefix that is not at the start (`f2-def-mid`, `[[[x _default:y]]]`) agrees on both sides at `/x-default:y`, and a generic colon prefix (`f2-colon-bare` and `f2-def-colon-space`, both `foo:bar`) agrees on both sides at `/foo:bar`, so the divergence is specific to `_default:` plus leading whitespace, not to colon-prefix stripping in general.

Classification: this is a reference defect, not a serving-layer difference. The href path is a rule-level value computed in Freelink::process and serialized identically by both sides of the harness; the masked surfaces in these captures are only class="newpage" and the outer paragraph wrapper. The minimal reference-side repair for the correction round is to make the strip tolerate leading whitespace before it runs, for example trimming the candidate prefix position rather than anchoring at byte zero, while keeping the non-leading and generic-prefix cases unchanged; this lane does not apply it. The mirror consequence for the coordinator is LinkRules.lean's freelink transliteration/prefix path, which transcribes the anchored strip and will disagree with live on the same shapes.
