# Pre-probe suspicion ledger — SUSPECT4-B (written 2026-11-22 before any muse-probe-suspect4b-* page was created)

Territory and method follow BRIEF-SUSPECT4-B: render-side and inline families on the post-REFCORR4/5/6 ground. A suspicion here is always the claim "the odd construct in this reference rule is a genuine divergence from live Wikidot." P_code below is the exact byte string the tree's own ref-php harness produced for that source (`php ref-php/harness/batch.php render`, copied into ref-render.jsonl with empty stderr); P_confirm is the live byte shape that would uphold the suspicion; P_clear is the live byte shape that would clear it. Frame surfaces already settled by the programme (outer <p> wrapping, CRLF→LF, <br /> versus <br>, collapse of newline runs, trailing-blank strip, the live serializer's &nbsp; spelling, Stage-2 inter-block newlines, the +1 token-index convention in leaked placeholders) are not divergence: a row is CLEARED when live agrees with P_code at the rule level modulo those surfaces and CONFIRMED only when the rule-level bytes differ. Every source is LF-only with trailing newline stripped; the case file is cases.jsonl and the page prefix will be muse-probe-suspect4b-. Reachability is noted per row; nothing here edits ftml, runs cargo, sets a git identity or invokes Lean.

S4B-01 (em-dquote, em-quote-only) — Email render escapes with ENT_NOQUOTES|ENT_SUBSTITUTE while every sibling renderer (Url, Freelink, Span, Interwiki, Gallery alt) uses ENT_COMPAT; a described label carrying both quote kinds is the seam a batch-3-only escaping change would miss. Suspicion: live escapes the double quote (and possibly the apostrophe) in the reversed label, so the ENT_NOQUOTES choice is a divergence. P_code for `[a@b.com say "hi" 'ok' & <x>]` is `<p>X <span class="wiki-email">moc.b|a#&gt;x&lt; &amp; 'ko' "ih" yas</span> Y</p>` and for `[a@b.com a'b"c]` is `<p>X <span class="wiki-email">moc.b|a#c"b'a</span> Y</p>` — &, <, > escaped, both quote kinds raw. P_confirm: live spells a double quote as &quot; (or an apostrophe as &#39;). P_clear: live leaves both quote kinds raw exactly as P_code. Reachable: a quoted phrase in a described email label on an ordinary page.

S4B-02 (dt-g, dt-gmid, dt-rawfmt) — Date's encodeFormat applies `str_replace('%g','ago',$format)` before the generic bytewise percent loop; this is the same fabricated-looking class of branch as the `@@<digits>@@` rule batch 4 removed, and it was left in place. Suspicion: live does not substitute the literal text "ago" for %g in the format class. P_code for format="%g" is class `odate time_0 format_ago`, for "x%gy" it is `format_xagoy`, and for "%%g" it is `format_%25ago`. P_confirm: live emits `format_%67` or `format_%25g` or any class without the literal letters ago. P_clear: live carries `format_ago`, `format_xagoy` and `format_%25ago`. Adversarial-only: no author writes %g in a date format class by accident, but it is exactly a no-human-would-write-it reference branch.

S4B-03 (dt-pctres, dt-nonascii) — the same encoder keeps only unreserved A-Za-z0-9-_.~ and percent-encodes every other byte; reserved ASCII and multibyte UTF-8 are the untested neighbours of the removed @@ branch. Suspicion: live's format class uses a different escape set (for example keeping '+' or '/', or uppercasing differently). P_code for "a+b/c@d" is `format_a%2Bb%2Fc%40d` and for "café" is `format_caf%C3%A9`. P_confirm: any class differing in those encoded bytes. P_clear: both classes byte-identical to P_code. Adversarial-only.

S4B-04 (dt-zeros, dt-negzero) — canonicalTimestamp does ltrim($raw,'0') and maps a zero-only or -0 timestamp to `0`, so the authored leading zeros vanish from the class. Suspicion: live preserves the authored digit run in the class. P_code for `[[date 00000123]]` is `time_123` and for `[[date -0]]` is `time_0`. P_confirm: live `time_00000123` or `time_-0`. P_clear: live `time_123` and `time_0`. Adversarial-only but a surviving fabricated-looking branch.

S4B-05 (dt-clamp, dt-clampneg) — canonicalTimestamp clamps a digit run beyond the signed 64-bit bound to 9223372036854775807 / 9223372036854775808 and formats the proleptic calendar at that extreme. Suspicion: live clamps at a different bound or lets the value overflow. P_code positive is class `time_9223372036854775807` with text `04 Dec 292277026596 15:30`, negative is `time_-9223372036854775808` with text `27 Jan -292277022657 08:29`. P_confirm: any different class or date text. P_clear: both byte-identical to P_code. Adversarial-only.

S4B-06 (fl-mixed) — freelink_transliterate passes ASCII alphanumerics plus #:/space_- through before the table and maps unmapped non-ASCII to a separator space; mixed-script slugs are the seam beside the pure-Cyrillic/pure-CJK battery. Suspicion: live transliterates a mixed slug differently (drops ASCII, or drops unmapped characters rather than separating them). P_code hrefs are /cafe123, /aeoeueabc, /ab-cd (the © becomes a separator) and /cafe-naive with the authored display text kept verbatim. P_confirm: any href differing from those. P_clear: all four hrefs and labels byte-identical to P_code. Plausible: a mixed-language page name on a wiki.

S4B-07 (fl-digit) — a slug beginning with digits goes straight through to WDStringUtils::toUnixName; leading digits are the untested edge beside the ASCII pass-through. Suspicion: live prefixes, strips or otherwise rewrites a leading digit. P_code hrefs are /123abc, /3-14 and /007. P_confirm: any different href. P_clear: all three byte-identical to P_code. Plausible: a page named with a leading year or number.

S4B-08 (fl-default-nonascii) — the _default: strip runs before transliteration, and the leading-space variant does not strip at all; this is the seam where the batch-5 reorder meets non-ASCII and a leading blank. Suspicion: live strips a category prefix after transliteration, or strips it even with a leading blank. P_code hrefs are /cafe (from _default:Café), /aeoeue (from _DEFAULT:ÄÖÜ) and /_default:x (leading blank keeps the prefix, display text "x" after the first colon strip). P_confirm: any different href or display text. P_clear: all three byte-identical to P_code. Adversarial-ish but reachable in a category-prefixed page name.

S4B-09 (fl-target-quote, fl-star-local) — the flTarget repair emits target="_blank" before href on a starred external triple link and escapes the label with ENT_COMPAT; a quoted label and a starred local page are the seams beside the pinned plain starred URL. Suspicion: live emits the target differently (different clause, different order, or keeps the star in a local slug). P_code for the quoted starred URL is `<a target="_blank" href="http://example.com">say &quot;hi&quot;</a>` and for the starred local page is a newpage anchor href="/local-page" with display text `*Local Page`. P_confirm: target clause or star handling differs. P_clear: both byte-identical to P_code. Reachable: a starred external link with a quoted label.

S4B-10 (iw-case-standalone, iw-case-descr) — Interwiki::process checks the configured site map with the authored case and bails to literal when absent, while processDescr lowercases the site and never checks the map at parse time; the render map itself has only lowercase keys. Suspicion: live applies one case policy to both forms (both link, or both literal) rather than this asymmetry. P_code is literal `[Wikipedia:Test] [GOOGLE:q]` for standalone but two real links for described (`https://en.wikipedia.org/wiki/Test` and `https://www.google.com/search?q=q`, each with an onclick window.open clause and label "Label"). P_confirm: the standalone forms link, or the described forms stay literal. P_clear: the exact asymmetry in P_code. Plausible: mixed-case interwiki site names are common in authored text.

S4B-11 (iw-pagechars) — the interwiki page class admits '+', ':', ';' and doubled hyphens, and the href is interpolated without escaping. Suspicion: live bounds the page at one of those characters or escapes it in the href. P_code hrefs are `https://en.wikipedia.org/wiki/a+b:c;d` and `.../a--b` with identical visible text. P_confirm: any truncated or re-spelled href. P_clear: byte-identical to P_code. Adversarial-only.

S4B-12 (ct-pct) — the batch-2 parse-time admission class `[A-Za-z0-9#(),\- \t]` and normalizeColor's identical class both reject '%', so an rgb percentage spec stays literal. Suspicion: live's normalizeColor admits '%' and forms a color span (a real CSS colour form). P_code is the literal paragraph `##rgb(50%,0%,0%)|x##`. P_confirm: a span with style color for that spec. P_clear: the literal form of P_code. Plausible: authors really do write rgb percentages.

S4B-13 (ct-emptybody, ct-dot, ct-slash) — the same admission class rejects an empty body (lazy .+?), a dot and a slash, so three near-miss specs stay literal; these are the neighbours a parse-time validation change could over- or under-validate. Suspicion: live forms a span for one of them. P_code is literal `##red|##`, `##red.5|x##` and `##red/2|x##`. P_confirm: any color span or partial claim. P_clear: all three literal as P_code. Adversarial-ish, except the empty body which a writer can produce by deleting text.

S4B-14 (ct-hex6) — control for the normalizeColor hex fold: an uppercase six-digit spec must lowercase and gain a '#'. Suspicion: live preserves case or omits the '#'. P_code is `<span style="color: #aabbcc">x</span>` with no trailing semicolon. P_confirm: any different style string. P_clear: byte-identical to P_code. Plausible: uppercase hex colours are common.

S4B-15 (sp-upper-u, sp-u-upper2) — the batch-8 guard suppresses doubling only when id already starts with the exact lowercase `u-`; an uppercase U- or a doubled UU- prefix therefore gets a second u-. Suspicion: live treats the prefix case-insensitively and leaves the authored id unchanged. P_code ids are `id="u-U-foo"` and `id="u-UU-foo"`. P_confirm: live `id="U-foo"` / `id="UU-foo"` or any other non-doubled spelling. P_clear: the doubled ids of P_code. Adversarial-only, but the exact seam the batch-8 guard left.

S4B-16 (sp-u-dash) — a bare `u-` id is non-empty and does not trigger the elision, so it becomes `u-` with no added prefix. Suspicion: live appends a second `u-` or drops the id. P_code is `<span id="u-">x</span>`. P_confirm: a different id attribute or a bare span. P_clear: byte-identical to P_code. Adversarial-only.

S4B-17 (sz-case, sz-upper2) — allowedSizes unit patterns are case-sensitive while the outer span regex carries /i, so an uppercase unit leaves the whole construct literal. Suspicion: live accepts upper/mixed-case units and forms a font-size span. P_code leaves `A [[size 12PX]]X[[/size]] B` and `A [[size 12Em]]Y[[/size]] B` literal. P_confirm: any font-size span. P_clear: literal as P_code. Adversarial-ish.

S4B-18 (sz-dots) — the numeric pattern `[0-9\.]{1,5}` admits an all-dot or multi-dot "number", which the batch-8 recursive-body change did not touch. Suspicion: live rejects those and leaves them literal. P_code emits three spans with font-size:...px, 1.2.3em and .em. P_confirm: any of the three left literal. P_clear: all three spans byte-identical to P_code. Adversarial-only.

S4B-19 (gl-target-leak, gl-link-star) — the batch-8 fix initializes $target='' per row for the star-prefixed source; a starred link attribute and a starred source followed by two ordinary rows are the later-row states beyond the pinned shape. Suspicion: target="_blank" leaks into a later row through either channel. P_code puts target="_blank" on exactly the first row of each gallery (and, for the link-star case, emits href="Target"), with later rows carrying the empty target slot ` >`. P_confirm: a later row also carrying target="_blank". P_clear: target only on the starred row. Reachable: a gallery mixing new-tab and ordinary images.

S4B-20 (gl-link-scheme) — the link branch tests `strpos($attr['link'], '://')` by truthiness, so a scheme marker at offset zero is falsy and falls to the wikilink branch. Suspicion: live recognizes a leading :// as a URL and emits it as a direct href. P_code emits `<a href="://x" >` for the single row. P_confirm: a different href or a JavaScript/onclick surface. P_clear: byte-identical to P_code. Adversarial-only.

S4B-21 (m1-nested-math) — Mathinline's regex is lazy and non-recursive, so a nested `[[$ b $]]` inside a math body closes the outer span at the inner closer and leaves the tail literal; the new source-span side table adds no nesting awareness. Suspicion: live preserves the whole nested body inside one outer math span. P_code is `<span class="math-inline">$a [[$ b$</span> c $]]`. P_confirm: an outer span containing the full `a [[$ b $]] c` body. P_clear: the truncated span of P_code. Adversarial-only but directly on the new mechanism's edge.

S4B-22 (m1-newline) — the suppression set contains Newline, so a wrapped math body is emptied to `$$`; a physical newline in a formula is the most reachable suppression member. Suspicion: live keeps the newline and renders the formula. P_code is `<span class="math-inline">$$</span>`. P_confirm: any non-empty body. P_clear: `$$`. Plausible: a long formula wrapped by an editor.

S4B-23 (m1-code, m1-code-close) — a Code token inside a math body is expanded from its claimed source, which for Code is the whole opener/body/closer; the closer-adjacent variant is the edge where the claimed source might include the math closer `$]]`. Suspicion: live drops the math body, suppresses, or mangles the code source. P_code for both sources is the clean `<span class="math-inline">$[[code]]x[[/code]]$</span>`. P_confirm: any different body. P_clear: byte-identical to P_code. Reachable: a code example cited inside inline math.

S4B-24 (m1-two-rules) — a described Url whose label is a described Email puts two source-claiming rules on one body; the side table keeps one source per token id, so the seam is which claim wins when Mathinline expands. Suspicion: live loses one of the two authored sources. P_code is `<span class="math-inline">$[http://example.com [a@b.com Lab]]$</span>`. P_confirm: any truncation or dropped bracket/text. P_clear: byte-identical to P_code. Adversarial-only.

S4B-25 (m1-suppress-nested) — a Freelink (suppression-set member) sits inside a described Url's claimed source at depth two; the expander checks suppression at every depth, and this is the edge where a nested member might be missed. Suspicion: live renders the outer body instead of suppressing. P_code is `<span class="math-inline">$$</span>`. P_confirm: any non-empty body. P_clear: `$$`. Adversarial-only.

S4B-26 (m1-raw, m1-raw4, m1-image) — controls for the three remaining suppression-set members (Raw, Image and the four-@ composite) at the source-span seam.
