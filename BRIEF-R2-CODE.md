The work, in order:

1. Read the reference and fossil Code parse and render rules and summarize the mechanism in the catalog: what the parse rule matches ([[code]] opener forms and arguments, how the body is delimited and tokenized, what happens to unterminated or stray forms), and what the render rule emits (wrapper markup, escaping of the body, line and whitespace handling, any type or line-number behavior the arguments trigger).
2. Build a differential battery of code-block shapes, aiming for 40 to 80 cases: basic blocks; empty and whitespace-only bodies; tabs and blank-line runs inside the body (the frame rules interact here); nested [[code]] openers; stray [[/code]] closers; unterminated blocks; argument forms (type="..." and anything else the parse rule accepts, plus unknown arguments); bodies containing wikitext, brackets, quotes, and HTML that must stay literal; blocks at line starts and mid-paragraph; several blocks in one page; CRLF input. Run every case through the reference's full render (batch.php render) and through ftml's parse-plus-render. For the ftml side, write a small Rust dumper modeled on the include dumper at /home/roku/.local/state/wikijump/muse-bhl/lean-ftml-g14/rust-dump (an ftml path dependency plus the public parse and render entry points), placed in a scratch directory inside this worktree; run every cargo invocation through /home/roku/.local/state/wikijump/muse-bhl/tools/heavy-build.sh with HEAVY_BUILD_NO_SPLIT=1, as a background job whose output you poll, because foreground bash calls time out at 60 seconds.
3. Classify every reference-vs-ftml disagreement as one of: fossil-era artifact in the reference, reference bug, ftml divergence candidate, or output-shaping surface (wrapper and whitespace differences, which still get corrected to live's shape but are cataloged as surface). Where a classification turns on live behavior, write live probe cases (JSONL, one {"id", "source"} per line) and run them on the sandbox wiki with the probe tool: cd ~/.agents/skills/wikidot-py-operations && scripts/wikidot-python scripts/wikidot-probe create --site sandbox-for-codex --prefix muse-probe-r2code- --from <cases.jsonl> --out <map.json>, then scripts/wikidot-python scripts/wikidot-probe capture --map <map.json> --out <captures.json>. Fetching from live Wikidot is pre-approved; fetch once, keep the pages and the captures, and save both into conformance-refphp/code/ in this worktree. Evidence order when sources disagree: ftml corpus pins first, then frozen captures, then live probes; live behavior wins over the fossil every time.
