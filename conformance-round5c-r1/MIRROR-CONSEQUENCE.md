C-R5C-R1-1 (u--prefixed placeholder id dropped). The mechanism is transcribed. In canonical `lean-ftml/LeanFtml/ContainRules.lean::isolateId` the 0xFF branch at line 531 is `if (litBytes "u-").isPrefixOf v then none else some v`: a u--prefixed placeholder-bearing value takes the `none` arm exactly as the PHP collapse-to-null path does. `divArgs` (line 637) stores that as `omSetOpt acc k none`, and the mirror's own REFCORR9 note records that the process-level empty-value unset then removes it before any claim, so no id pair reaches `renderDiv`. `InteractiveRules.lean::divAttrFragment` (line 986) only clears values that still carry a 0xFF byte, so it cannot reconstruct a cleared id from a dropped key. The mirror would therefore also serve a bare `<div>` where live serves `<div id="">`. The clear arm and the whitespace-shell pin remain correct for their own shapes; the gap is the u--prefixed exception in the isolateId branch.

C-R5C-R1-2 and C-R5C-R1-3 (mixed empty/non-empty Raw around a lone newline). The mechanism is transcribed on both the parse and render sides. `lean-ftml/LeanFtml/NotesRules.lean::footnoteProcess` line 213 stores `if isLoneNewlineRemainder stripped then preStrip else trimBytes stripped`. `isLoneNewlineRemainder` (line 195) drops only space and tab bytes around a single LF, so a remainder still carrying a non-empty Raw placeholder byte fails the predicate and the `trimBytes stripped` arm removes the LF from the stored body. With no inline byte before the newline, the mirror's Newline path cannot emit a `<br />`, reproducing the reference's missing break for both capture shapes. On the separator side, `lean-ftml/LeanFtml/NotesRender.lean::footnoteVisibleBody` strips only empty-Raw placeholders, so the non-empty Raw token remains and `renderFootnoteitem` emits the separator space; for C-R5C-R1-3 that is the opposite of live, which emits `<br />` and no separator space. The REFCORR9 mirror-completion pins `refcorr9_fn_lone_newline_keeps_placeholders`, `refcorr9_footnoteitem_retained_newline_no_sep` and `refcorr9_footnoteitem_nonempty_raw_sep` cover the symmetric empty/empty and literal cases and do not exercise these mixed-order remainders, so they remain valid and the new shapes are genuine uncovered siblings rather than a flip of an existing pin.

No compared token field, option key, token count or DocState field is added by any of these mechanisms; the divergence is in byte values computed by total functions. A correction round can therefore be local to the isolateId u- exception and the footnote lone-newline predicate/separator consumer without touching the wire shape.
