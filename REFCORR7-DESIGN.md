# REFCORR7 design decision — the SUSPECT4 reference and mirror corrections (2026-11-23)

This is the design record for REFCORR7, modelled on REFCORR6-DESIGN.md. All five mechanism units have returned and their CORRECTION records are adopted in the canonical tree, so every function, line and mirrored path below is the adopted one; the exact before/after sha256 pairs are tabulated in REPORT-REFCORR7.md and were re-hashed against the canonical files on disk (edited files and their byte-identical `.before-refcorr7` companions) by this documentation unit. Live Wikidot behavior remains definitional, the evidence order is ftml pins then frozen parity captures then the already-cached single-fetch live probes, and no new probe is fetched. The live rules below are stated from the eleven confirmed shapes in REFCORR7-INTAKE.md; the design is deliberately five independent minimal mechanisms, one per F02 mechanism unit (R7A, R7B, R7C1, R7C2, R7C3), so a rejection or narrowing in one bucket cannot silently move a case owned by another.

The live rules for R7A are the case-classification rules the REFCORR5 battery measured but the reference only partly implemented. Opener and item recognition is case-insensitive, a lowercase or mixed-case opener closes cleanly against an upper- or mixed-case closer of the same tag, a cross-type uppercase closer also closes the lowercase opener (C11), but an uppercase opener paired with [[li]] items forms a list that never closes and drops its attributes (C1/C5/C6), and an uppercase opener whose body has no [[li]] item degrades to bare prose (C10). The reference instead keeps the opener's raw case on its stack, requires strict stack-tag equality after lowercasing only the closer, still runs buildListAttrs for an uppercase opener and still synthesizes an unclosed <ul> with a list-style:none item for the item-less case. The live rule for R7B is that the REFCORR5 batch-5 `_default:` strip tolerates leading ASCII whitespace before the category: `[[[ _default:x]]]` serves href="/x", while a prefix at byte zero, a non-leading prefix and a generic colon prefix behave exactly as the reference already does. The live rules for R7C1 are that a body containing only an empty Raw token, with or without surrounding spaces, counts as empty to Footnoteitem and Bibitem (footer `>1</a>.</div>`, bibitem `1.`), even though Tighten and the Raw renderer both delete the placeholder. The live rule for R7C2 is that a literal U+FFFD immediately before an empty Raw placeholder leaks the whole adjacent placeholder run, so the displayed indices are 3, 4, 1 and 5 rather than the reference's truncated 3 and 4. The live rule for R7C3 is that an include spliced into a module body is consumed there: live re-emits neither the raw span nor the literal closer, serving only the module error block for a nosuchmod module and an empty page-content with the authored text carried in `<style>` for a css module.

The minimal PHP mechanism for R7A is confined to `ref-php/text-wiki/Text/Wiki/Parse/Default/List.php`: normalize the opener tag to lowercase when it is pushed, so the existing lowercased-closer equality check pairs mixed-case and cross-type closers, skip buildListAttrs for an opener whose authored case is not canonical so id, style, class and data-* are dropped, and route an opener with no [[li]] item to prose rather than to the unclosed-list synthesis. The minimal mechanism for R7B is confined to `ref-php/text-wiki/Text/Wiki/Parse/Default/Freelink.php`: tolerate leading whitespace before the `preg_match('/^_default:/i', ...)` strip, for example by ltrim on the prefix candidate or by moving the strip after the trim that `WDStringUtils::toUnixName` performs, while leaving the byte-zero, non-leading and generic-colon cases untouched. The minimal mechanism for R7C1 is confined to `Footnoteitem.php` and `Bibitem.php`: decide emptiness from the post-Raw placeholder-aware string rather than from a raw `!== ''` or `'empty'` flag, so the empty Raw token does not produce the separator space. The minimal mechanism for R7C2 is confined to `Text/Wiki.php::renderLiteralUfffdRecovery`: continue the neighbor walk across the whole adjacent placeholder run after a literal U+FFFD, counting the empty Raw placeholder that Tighten removed from the render stream but that still occupies its index in the parsed token sequence. The minimal mechanism for R7C3 is confined to `Include.php` and `Module.php`: keep an included raw source inside the module body that consumes it and suppress the REFCORR4 delimiter-bearing re-emit and the literal closer paragraph, including the css-module case where the included source is stored as CSS text. The adopted function boundaries and call sites are, per bucket: R7A `Text_Wiki_Parse_List::parseExplicitLists()` with `buildExplicitListBlock()`, `formatExplicitLiItem()` and `finalizeExplicitListBoundaries()` in `ref-php/text-wiki/Text/Wiki/Parse/Default/List.php`, mirrored by `blockCloserAt`/`findPair`/`dissolveNestedUpper`/`degradeRawBody` and friends in `lean-ftml/LeanFtml/ListRules.lean`; R7B `Text_Wiki_Parse_Freelink::process()` lines 190-199 in `Freelink.php`, mirrored by `freelinkProcess` lines 1060-1067 in `lean-ftml/LeanFtml/LinkRules.lean`; R7C1 `Parse/Default/Footnote.php` and `Parse/Default/Bibitem.php`, mirrored by `footnoteProcess`/`bibitemProcess` in `NotesRules.lean` and `bibiPair` in `CoverageNotes.lean`; R7C2 `Text/Wiki.php::renderLiteralUfffdRecovery` (definition line 918, R-UFFFD-1 dispatch line 1151) plus `Tighten.php::parse` lines 95-107, mirrored by `RenderCore.lean`'s `ufffdWalk`/`ufffdLeakRun` and `Inline3Rules.lean`'s `hasUfffdBytes`/`tightenBytes`; and R7C3 `Parse/Default/Module.php::process()` lines 99-108, mirrored by `ModuleRules.lean`'s `moduleTryCands`. These are recorded in coord-units/R7A/UNIT.md through coord-units/R7C3/UNIT.md and the five adopted CORRECTION records; no line number in this design is itself authority for an edit.

The wire-shape preservation argument is the load-bearing constraint for the Lean mirror. The compared state wire shape is the two-element `[rule, options]` token entry serialized verbatim by `state-restricted.php` and emitted by `TokenState.lean::serToken`; REFCORR6 established that adding a field to that entry would move every state record in r43, r44, r45, r46, r48 and CAPSTONE for no live-visible reason, so REFCORR7 must change parse and render decisions only, never the compared entry arity or its option shape. Where a fix needs information the token entry does not carry, it must be kept beside the comparison, as REFCORR6 kept authored source spans in a parallel `Text_Wiki::$tokenSource` table read only by the expansion that needed them, or derived from structural token entries already in hand. The Lean mirror may reconstruct a decision from its structural entries where a reference-style side table would require touching every claim site and several hundred record literals, but that reconstruction must be exact for every reachable rule and its limitation disclosed in `conformance-refcorr7/MIRROR-REFCORR7.md`, exactly as MIRROR-REFCORR6.md disclosed the Mathinline compromise; it must never be presented as a general reference mechanism and must not widen the compared token shape. How each bucket satisfies this, as adopted: R7A keeps every token on `addTok "List"` with the same eight option keys (`type`, `list_type`, `attrs`, `scored`, `lead`, `trail`, `newline`, `lead_nl`) and keeps `isSynth`/`unclosed` as internal control flow; R7B changes only the local `stripped` computation feeding `toUnixName`, keeping the seven Freelink keys; R7C1 changes only the stored `footnotes` body and the Bibitem `empty` flag, with PHP and Lean applying the identical placeholder-strip at the same parse site; R7C2 writes only local recovery HTML digits, with `ufffdLeakRun`/`hasUfffdBytes` total computable helpers touching neither `TokenEntry`, `OptMap` nor `serToken`; and R7C3 changes only residual source bytes while `claimModule` and the compared `[rule, options]` entry stay byte-identical, following the REFCORR6 `tokenSource` precedent. Mirror limitations are disclosed in `conformance-refcorr7/MIRROR-REFCORR7.md` (the included-raw mirror note is already adopted there; the coordinator consolidates the other four bucket notes into that file).

Alternatives rejected: frame-mask or tidy-level post-processing of the divergent bytes cannot fix token-level differences in list pairing, href paths, emptiness flags, index leaks or module consumption, and would only hide them behind the already-owned surfaces; treating the inc-css marker-versus-`<style>` wrapper as the defect is wrong because that wrapper is the documented serving layer, while only the body bytes and the re-emit are reference behavior; adding a compared field to the token entry, changing `state-restricted.php` serialization or changing `TokenState.lean::serToken` is rejected on the REFCORR6 wire-shape ground above; a pre-tokenization or global lowercasing pass would change pipeline order or adopt SpecIntent's symmetric `listCloserMatchesIntent`, which REPORT-REFCORR5 records as not live, and would move cleared list shapes; restoring the wide `]]` described-Url guard from REFCORR6 is rejected because it moved fifteen named r43 cases and was narrowed to `$]` before adoption; excluding or normalizing counter cases, digit runs or the 36-case U+FFFD family is rejected because the programme retires exclusions rather than adding them; the two UNTESTABLE S4A prefilter sub-cases are not clearances and cannot be used as pins or as evidence for a fix. Bucket-specific alternatives the mechanism units actually rejected and recorded are: R7C2's walk-only patch with Tighten unchanged, which yielded `<p>alpha <strong>bold</strong> 345</p>` and was discarded in favour of the two-part patch; R7C1's first stripper draft that compared the token rule to lowercase `'raw'`, which moved no bytes because the real rule name is `Raw`, and was corrected; R7B's widening to other Unicode whitespace, deliberately not admitted because only space and tab are evidenced; and R7C3's treating the css marker-versus-`<style>` wrapper as the defect, rejected as the confirmed serving-layer boundary. The R7A scratch build additionally had to remove the Lean keyword `synthetic` and repair two non-exhaustive matches, one non-terminating recursion and a start-only closer search before the mirror built, but those are implementation corrections rather than alternative mechanisms.
