Placeholder leakage, the Toc NUL-pair neighborhood, the Raw composite's empty token where it meets Tighten and the footnote machinery, token-index reads of neighboring tokens after the composite's extra id, include splices after the REFCORR4 Module and Freelink changes, and Prefilter's padding where it meets the first rule of a family. ## Confirmed divergences

Six shapes are confirmed. Three are one mechanism, the emptiness test on an empty Raw placeholder. One is the U+FFFD neighbor walk. Two are an included raw inside a module.

S1, source `[[footnote]]@@@@[[/footnote]]`, page muse-probe-suspect4c-fn-empty. Raw emits one empty token. Footnote stores the placeholder, which trim does not empty. Footnoteitem emits a separator space because that stored string is not `''`. Tighten then deletes the placeholder and the Raw renderer returns nothing, so the body is blank. Live footer bytes are `<div class="footnote-footer" id="footnote-1"><a href="javascript:;" onclick="WIKIDOT.page.utils.scrollToReference('footnoteref-1')">1</a>.</div>` with no space after the period, the same form as a truly empty note. Reference bytes are the same element with a space: `>1</a>. </div>`. The newline differences elsewhere in the footer are the owned Stage 2 frame, not this seam.

S2, source `[[footnote]]  @@@@  [[/footnote]]`, page muse-probe-suspect4c-fn-ws. The live HTML is byte-identical to S1 (sha256 9a433756f6c93079ca2faf49d827011e130ad08752d11db407983fc244a3c003). Spaces around the run do not survive. The reference still emits the space, because trim leaves the placeholder.

S4, source `[[bibliography]]` newline `: lab : @@@@` newline `[[/bibliography]]`, page muse-probe-suspect4c-bib-empty. Bibitem sets `'empty'` from the post-Raw string, so the placeholder counts as a body and the renderer prints a space. Live bytes are `<div class="bibitem" id="bibitem-1">1.</div>`. Reference bytes are `<div class="bibitem" id="bibitem-1">1. </div>`.

idx-after, source `alpha **bold** ` plus U+FFFD, a blank line, and `@@@@`, page muse-probe-suspect4c-idx-after. renderLiteralUfffdRecovery leaks `id - first + 1` for a placeholder immediately after one literal U+FFFD, and it leaks one further neighbor and then stops. Before Tighten the parsed source ends `<UFFFD>` paragraph-end, blank line, empty-paragraph start, the empty Raw placeholder, empty-paragraph end. Tighten removes the placeholder and every remaining newline, so the recovery sees three adjacent placeholders and prints only the first two, display ids 3 and 4. Live prints the whole run, and the empty Raw placeholder is still in that run, so the digits are 3, 4, 1 and 5. Live bytes are `<p>alpha <strong>bold</strong> 3415</p>`. Reference bytes are `<p>alpha <strong>bold</strong> 34</p>`. This is not the serving layer: both sides are one paragraph, and tidy does not invent the digits 15. The leading-empty and real-raw controls match live at digit 5, and the no-raw baseline matches at digit 2, so the defect is specifically the trailing empty token's neighbor run, not the composite's id shift in general.

S11, includer `[[module nosuchmod]]` newline `[[include muse-probe-suspect4c-inc-raw]]` newline `[[/module]]`, target source `@@hello@@`, page muse-probe-suspect4c-inc-mod. Include runs first and splices the raw into the module body. Raw then tokenizes it, and Module's REFCORR4 path re-emits any body that contains a delimiter, plus the literal closer. The include padding puts the closer in its own paragraph. Live page-content is only the error block: `<div class="error-block">[[module <em>nosuchmod</em>]] No such module, please <a href="https://www.wikidot.com/doc:modules" target="_blank">check available modules</a> and fix this page.</div>`. Reference bytes are that error block, then `<p><span style="white-space: pre-wrap;">hello</span></p>`, then `<p>[[/module]]</p>`.

S14, the same include inside `[[module css]]`, page muse-probe-suspect4c-inc-css. The reference marker-versus-`<style>` wrapper is the serving layer and is not the defect. The defect is the body and the re-emit. Reference body is the urlencoded empty-Raw placeholder `%FF0%FF`, followed by the raw span `hello` and a paragraph `[[/module]]`. Live's `#page-content` is empty. The full anonymous page, cached in conformance-suspect4c/inc-css-style.txt, contains `<style>\n@@hello@@\n</style>` and does not contain the raw span or the literal closer. Include did expand, and live stored the included source as CSS text rather than as a Raw token.
