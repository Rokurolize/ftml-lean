## Mechanism chosen and evidence

The chosen mechanism is alternative (a): carry each token's exact authored source span from addToken onward in a side table on the wiki object, and expand those spans recursively in Mathinline. The decisive evidence is the shape of the addToken call sites. Text/Wiki/Parse.php::parse invokes process($matches) through preg_replace_callback, so every rule using the base parse() receives $matches[0] as the exact full matched source, and the rules that override parse() (Url, Email, Raw and others) invoke their own callbacks with the same array. The claimed span is a group or an expression at the call site, not always $matches[0]: Url::process claims the star plus group 3 and returns group 1 and the lazy trailing bytes outside its token, Newline::process claims only the LF after its prefix group, and Code::process claims the whole match minus its trailing whitespace group. Each call site can therefore pass the precise span it replaced in one line, with no pipeline-order change to any of the sixty-eight rules. Text_Wiki::$tokenSource is parallel to $tokens, keyed by the same id; $tokens itself remains the two-element [rule, options] entry that state-restricted.php serializes and TokenState.lean::serToken emits. Putting the source inside the compared token entry would have moved every state record in every stage gate for no live-visible reason, so the side table is the load-bearing detail.

Mathinline's process now walks each placeholder with PREG_OFFSET_CAPTURE, checks the four-rule suppression set {Freelink, Raw, Newline, Image} before substitution, recursively expands the source span of the token it finds, leaves unknown placeholders and cycles literal, and falls back to the former one-level option substitution for a token with no recorded span. A suppression found at any depth empties the whole body to the empty string, which the unchanged render rule frames as `$$`. One additional narrow guard was required by the battery: Url's described pass otherwise consumed the `$]` fragment of the math closer in m1-code, leaving the math opener literal; it now yields such a match to Mathinline. An initial `]]` version of that guard was too wide — it moved fifteen named r43 cases outside this correction — and was narrowed to the `$]` fragment before the final gates.

## Alternatives rejected

Per-rule source-text reconstruction at Mathinline time (b) reproduces the sixteen battery shapes from option values but is an inverse of each rule's parse rather than preservation of authored bytes. It cannot in general recover a described email's exact brackets, an Image attribute order or a Code opener's authored arguments from a normalized option map, and it needs a new reconstruction table whenever a rule's option shape changes. It is used only in the Lean mirror, where token entries are structural and the option values of every rule that reaches Mathinline determine the source exactly; that compromise is disclosed in MIRROR-REFCORR6.md rather than presented as a general reference mechanism. A pre-tokenization capture pass over `[[$ ... $]]` bodies (c) would change pipeline order for all sixty-eight rules and require re-adjudicating every stage gate; the source is already in hand at addToken time, so the battery gives no justification for that cost. A backtrace-based capture inside addToken was also rejected: it still cannot select the claimed group out of $matches, it breaks for scanner-based and custom-pass rules, and it hides a rule-dependent decision inside a shared choke point.
