## Per-rule mechanism and byte-form analysis

All four rules run on the byte-form view (the R3.2 obligation): their patterns' delimiter exclusions are the byte 0xFF, and option values that can span an earlier placeholder (an Email or Interwiki described label, a Mathinline content) cross as OptVal.bytes through textVal, as the reference's byte strings do. Each preg_replace_callback pass is the shared pregScan combinator: a match contributes its replacement and scanning resumes after the consumed match, so a callback that returns its match unchanged (the C5 yield, the Interwiki unknown-site return) still advances past the whole match, as preg_replace_callback does.

Url runs the described pass, then the inline pass. Both patterns are deterministic once PCRE's search order is made explicit, and the mirror reproduces that search rather than approximating it. In the strict body, a segment is a maximal run of segment bytes followed by a slash: giving segment bytes back can never expose a slash, so the segment decomposition at each level is forced, and the only backtracking is the segment count (a deeper segment path is tried before the tail at a shallower level, which is the recursion's own order in urlBodyEnd) and the tail length (urlTailEnd takes the largest tail whose following byte is in the final class). This is a first-parse depth-first search in the R3.10 sense, but with at most one candidate per level, so no subsumption question arises and no exponential shape exists. The liberal body of the described form is likewise forced (maximal segments, then the maximal liberal tail run), and its continuation (a space, a text run of [^\]DELIM]+, a closing bracket) can be satisfied by no other decomposition, since any shorter tail or dropped segment ends the href at a byte that is not the required space; the #anchor and /path alternatives follow in pattern order. The inline pass's prefix group is (^|[^A-Za-z]): the mirror tries the caret alternative (an empty prefix) at position zero before the scan, and the scan's matcher consumes one non-letter byte as the prefix everywhere, the process returning that byte verbatim before its token. Correction C4 is transcribed literally: the URL is cut at its first [[ (one byte earlier when a pipe immediately precedes the opener), the cut tail rejoins the output after the token, and no revalidation of the truncated URL happens. Correction C5 is likewise literal: a described label containing [[$ returns the whole match unchanged.

Email runs the described pass, then the standalone pass. The address grammar (a local atom chain, @, a domain atom chain with at least one dot group) has a unique maximal parse at any start position, and no shorter parse can be followed by the @ or by the described continuation, both of which sit outside the atom classes, so maximal-or-fail (atomChainLen plus the dot-group check in emailMatchLen) is the regex's own behavior; the plus-addressing shape falls out of the class (the local run stops before +, and the address is found starting after it), as the R2 section recorded live doing.

Mathinline's lazy body ends at the first $]] with no newline intervening (mathEndScan); its process trims the body with PHP's trim (the shared trimBytes), then applies correction C1's resolution: placeholder occurrences are collected once from the trimmed content in occurrence order (placeholdersOf, duplicates included), and folded over the evolving content; a placeholder naming no token is left in place, a Newline or Raw token suppresses the whole content to the empty string and stops the fold, and any other token contributes its text option if string-valued, else its href if string-valued, else the empty string, substituted for every occurrence of that placeholder at once (replaceAllBytes, PHP str_replace semantics: non-overlapping, left to right, inserted text not rescanned). String-valuedness is PHP's is_string (optStringBytes): a plain string contributes its UTF-8 bytes and a $bytes value its bytes; an integer or map option under text or href is not a string and the lookup falls through exactly as the reference's does.

Interwiki runs the standalone pass before the described pass. The site and page runs are forced-maximal (iwHead): no shorter site can be followed by the colon, and no shorter page by the closing bracket or the described space; the page's first byte is barred from being a colon by the pattern's lookahead, while later page bytes may be colons. The standalone form claims only for a configured site, compared case-sensitively as written, with text the page (the part of the site:page group after its first colon, which is the page, the site class barring colons); an unconfigured site returns the whole match literally, consuming it. The described form lowercases the site (ASCII strtolower) and checks nothing.

One mirror defect was caught by the fuzz differential and fixed in the model, with the oracle validated first as the stage protocol requires. The first draft read the Email and Interwiki described texts as a class-bounded run ending at the first closing bracket; seed 7's fz-iw-058 showed the reference claiming a described Interwiki whose text is "] [google:P~1 Label", spanning two bracket pairs, because a lazy .+? can itself contain ] bytes and closes at the first ] at distance at least one, a ] in the first position being content. The PHP record itself carried that spanning claim, so the oracle stood and the model was wrong: the run-based tail is now used only for Url's genuinely class-bounded text, and Email and Interwiki use lazyTail, a scan that closes at the first ] at distance at least one and fails on any intervening newline. After the fix the corpus and both fuzz seeds are green in full.
