# REPORT-SUSPECT-BLOCK: suspicion hunt in Blockquote, Iftags and Comment

This lane re-read the working reference PHP for Blockquote, Iftags and Comment, both parse and render, as inherited code to be distrusted, and tested every suspicion against fresh saved-page probes on sandbox-for-codex. Live behavior is definitionally correct; the shape of the fossil code is never evidence. Evidence order was the ftml corpus and integration pins, then the frozen R2 parity captures, then fresh live probes; a fresh valid source-matched probe outranks a frozen pin. Twenty suspicions were raised in `conformance-suspect-block/predictions-pre-probe.md` before any page was created, each with two observably different predictions; a further order-sensitive batch was added to that file before its pages were created, and a third batch was added before its pages after coordinator steering named the Antigravity SUSPECT lane's p32/x07 and p28/f08 as leads to verify rather than ground to assume. Two leads came from the coordinator's map and were treated as leads, not givens. Method and naming follow BRIEF-SUSPECT-NOTES with names changed, as BRIEF-SUSPECT-BLOCK directs.

Probe discipline. Fifty-six run-owned pages were created under the permanently kept prefix `muse-probe-suspect-block-`: thirty-four in the first batch (twenty-two untagged through `wikidot-probe create`, twelve published with `tags=["alpha"]` through `site.page.publish` because the probe CLI has no tag subcommand), thirteen in the second batch (ten untagged, three tagged), and nine after coordinator steering (seven untagged and two tagged, one of the latter carrying `tags=["alpha","beta"]`). Every source is LF-only with trailing newline stripped because Wikidot normalizes those on save. Each page was fetched twice with independent anonymous GETs through `wikidot-probe capture`; all fifty-six captures are `valid=true`, `stable=true` and `saved_source_matches=true`, with no failed saves and no failed read-backs. Page sources, fullnames and HTML digests are inventoried in `conformance-suspect-block/probe-pages.txt`; maps, case files, create and capture logs are beside it. The reference side was produced by the tree's own `php ref-php/harness/batch.php render` (and `tokens` for the first batch) over exactly the same sources with the same `tags` arrays, in `ref-input.jsonl`/`ref-render.jsonl` and `ref2-input.jsonl`/`ref2-render.jsonl`, all with empty stderr; the two lead-only runs are in `leads-ref-input.jsonl`/`leads-ref-render.jsonl`. The third batch's sources and reference output are in `ref3-input.jsonl`/`ref3-render.jsonl`, also with empty stderr. The side-by-side output is `compare-report.txt` with the script `compare.py`, which prints raw reference and raw live strings and compares only after inter-tag whitespace and `<br />`/`<br>` normalization; it never decodes numeric entities, because the entity spelling is itself evidence. No ftml file was edited, no reference file was changed, no git identity variable was set and no cargo was run.

## Suspicion ledger

S1 — `>nospace` silently deletes the line (CONFIRMED). Construct: the outer scanner `/\n((\>).*\n)(?!(\>))/Us` at `ref-php/text-wiki/Text/Wiki/Parse/Default/Blockquote.php:54` claims any line beginning with `>`, but the inner line grammar `^(\>+) (.*\n)` at lines 88-93 requires a literal space after the marker run, and lines that fail the inner grammar contribute nothing; the C2 guard at lines 95-110 turns an all-unmatched run into two newlines. Prediction A (code): a page whose only line is `>nospace` renders nothing, and `>nospace\nX` renders only `X`. Prediction B (skeptic): the line survives as literal text or as a quote containing `nospace`. Probes `muse-probe-suspect-block-bq-nospace-only`, `-bq-nospace-then-text`, `-bq-nospace-run` and control `-bq-space-control`: live renders empty, `<p>X</p>`, `<p>X</p>` and a blockquote containing `space` plus `<p>X</p>` respectively, byte-identical at the rule surface to the reference. Verdict CONFIRMED: the line is genuinely deleted, and the earlier R2-BLOCK `nospace-in-run` pin (`> one\n>no\n> two` → one quote with `one<br />two`) describes the in-run form of the same behavior.

S2 — multi-marker no-space lines are dropped whole (CONFIRMED). The same inner regex requires the space after the entire contiguous `>` run. Prediction A: `>>>nospace\nX` renders only `X`, with no three-level container. Prediction B: three nested containers or literal `>>>nospace`. Probe `-bq-multi-nospace` gives `<p>X</p>` on live and the reference. CONFIRMED.

S3 — a space-prefixed quote line ends the run and loses its indentation (CONFIRMED). The outer negative lookahead `(?!(\>))` tests only the byte immediately after the newline, so a line starting with a space is outside the run; Paragraph later trims the residual. Prediction A: `X\n> a\n > b\nY` gives one quote for `a` and a paragraph with literal `&gt; b` and no leading space. Prediction B: a two-level quote or preserved indentation. Probe `-bq-indented-next` saved verbatim (an interior leading space survives Wikidot's save normalization, unlike a leading space at byte zero in the R2-BLOCK lane's failed probe) and live matches the reference exactly. CONFIRMED.

S4 — an all-empty marker run is consumed without a container (CONFIRMED). The C2 guard uses `trim($val[2]) !== ''` over the whole run. Prediction A: a run of only `> ` lines leaves no `<blockquote></blockquote>`; Prediction B: an empty container appears. Already pinned by R2-BLOCK C2 and `muse-probe-r2block-bq-marker-space-before-text`; this lane reaches the same branch through Comment emptied lines in `-bq-comment-only` (only the surrounding paragraphs survive) and checks the sibling distinction in `-bq-empty-in-run`, where one blank marker row among text rows keeps one quote with two paragraphs. CONFIRMED.

S5 — end-token level arithmetic and the mid-run newline asymmetry (CONFIRMED). Start tokens carry `level - 1`, end tokens carry the stack depth after popping, and C3 added a second newline after a mid-run close so the lower-depth line forms a paragraph. Prediction A: a fall from depth two back to one yields `<p>c</p>` inside the outer quote after the inner close; Prediction B: a bare `<br />` or unbalanced tags. Pinned by R2-BLOCK C3 and `muse-probe-r2block-bq-nested-mixed` with `> a`/`>> b`/`> c`; nothing in this lane's captures contradicts it, and `-bq-empty-in-run` exercises the same emission path. CONFIRMED.

S6 — a Comment-emptied quote line still forms a quote if a sibling line has text (CONFIRMED). Comment runs at pipeline position 12, Blockquote at 28; the comment is removed first. Prediction A: `> [!-- hide --]\n> shown` yields one blockquote containing only `shown`. Prediction B: two containers or a literal `> [!-- hide --]` line. Probe `-bq-comment-line` gives one blockquote containing `shown` on both sides. CONFIRMED.

S7 — a whole-line Comment bridges two quote lines into one run (CONFIRMED). Comment's regex includes the preceding newline in its match, so removing a comment-only line makes the two `>` lines adjacent. Prediction A: `> one\n[!-- c --]\n> two` yields one blockquote with `one<br />two`; Prediction B: two blockquotes or ordinary text. Probe `-bq-comment-between` gives one quote on both sides. The contrasting `-cm-quote-bridge-blank` probe, where blank lines surround the comment, gives two quotes, as A predicts. CONFIRMED.

S8 — the C2 empty test is trim-based, so an NBSP-only body is not empty (CONFIRMED with serializer surface). PHP `trim()` removes ASCII whitespace but not U+00A0. Prediction A: `X\n> \u00a0\nY` keeps a blockquote whose body is the non-breaking space; Prediction B: no quote. Live keeps the container and spells the byte `&nbsp;`, while the reference emits the raw UTF-8 byte; both sides agree on the rule decision and on the container shape. CONFIRMED; the spelling difference is the live serializer's character-entity surface, not a rule divergence.

S9 — a quote line emptied by a false Iftags gate is deleted by C2 (CONFIRMED). Iftags runs at position 11, before Blockquote. Prediction A: on a page tagged `alpha`, `> [[iftags +beta]]KEEP[[/iftags]]` drops the body and the quote disappears, leaving only the surrounding paragraphs; Prediction B: an empty container or literal markup. Tagged probe `-bq-if-false-tagged` matches the reference. CONFIRMED.

S10 — spaced markers are level one with a literal marker in the body (CONFIRMED). Prediction A: `X\n> > q\nY` produces one level-one blockquote whose paragraph begins `&gt; q`. Prediction B: two nested containers. Probe `-bq-spaced-marker` matches the reference. CONFIRMED, corroborating the R2-BLOCK section's depth rule.

S11 — the empty-run guard is run-wide, not per-line (CONFIRMED). Prediction A: `> a\n> \n> b` keeps one quote with two paragraphs; Prediction B: one paragraph with breaks. Probe `-bq-empty-in-run` matches the reference. CONFIRMED.

S12 — leading-space quote line behavior (CONFIRMED, no longer merely untestable). Prediction A: the run ends and the leading space is lost in the residual paragraph; Prediction B: a two-level quote or preserved space. Probe `-bq-indented-next` saved verbatim and matches A. CONFIRMED; the R2-BLOCK lane's failure to save a ` > q` source at document start was a serving-layer normalization limit of that shape, not of this one.

S13 — trailing comma in an Iftags spec poisons the required-tag path (CONFIRMED; coordinator lead). `preg_split(';[, ]+;', trim($matches[1]))` at `Parse/Default/Iftags.php:63` keeps the trailing empty field, which the classifier at lines 69-77 sends to `$anyTags`, and the any-tag loop at lines 96-105 requires a page tag equal to the empty string. Prediction A: `[[iftags +alpha,]]KEEP[[/iftags]]` drops the body even on a page tagged `alpha`; Prediction B: the comma is ignored and `KEEP` is kept. The local reference drops it; tagged probe `-if-trail-plus-tagged` and untagged probe `-if-trail-plus-untag` both render only `<p>X</p>`, matching live, while control `-if-plain-plus-tagged` keeps `KEEP`. Variants `-if-trail-space-tagged` (`+alpha, `), `-if-lead-comma-tagged`, `-if-double-comma-tagged`, `-if-trail-minus-tagged` and tagged `-if-trail-forbid-hit-tagged` (`-alpha,`) all drop as the code predicts. CONFIRMED.

S14 — the trailing empty field is harmless after a matching bare tag (CONFIRMED). The any-tag loop returns the body on its first hit. Prediction A: `[[iftags alpha,]]KEEP[[/iftags]]` on a page tagged `alpha` keeps the body; Prediction B: the empty field poisons the spec. Probe `-if-trail-bare-tagged` keeps `KEEP`, matching the reference. CONFIRMED; this asymmetry makes S13 look like an accidental interaction rather than an intentional rule.

S15 — nested Iftags pairs are consumed but never re-evaluated (CONFIRMED). The recursive `(?R)` in the regex at `Iftags.php:29` swallows an inner pair into the returned body, and the parse rule runs once. Prediction A: with tag `alpha` and no `beta`, `[[iftags +alpha]]A[[iftags -beta]]B[[/iftags]]C[[/iftags]]` renders `A[[iftags -beta]]B[[/iftags]]C` with the inner markers literal; Prediction B: the inner gate is evaluated and `B` disappears. Tagged probe `-if-nested-tagged` matches A byte for byte. CONFIRMED.

S16 — a Comment in the Iftags opener spec blocks the gate (CONFIRMED). Iftags runs before Comment and `[^\]]*` cannot cross the `]` inside `[!--x--]`. Prediction A: `[[iftags [!--x--]+alpha]]KEEP[[/iftags]]` loses the comment but leaves the whole gate literal; Prediction B: Comment strips first and the body is kept. Tagged probe `-if-spec-comment-tagged` renders the literal gate with the comment gone, matching the reference. CONFIRMED, consistent with the R2-NEXT M13 fused-head-close finding.

S17 — a Comment hiding a closer does not shield it from Iftags, and a Comment hiding an opener leaves the comment's remains (CONFIRMED, order-sensitive). Prediction A: `[[iftags -beta]]KEEP[!-- [[/iftags]] --]TAIL` on an untagged page gives `KEEPTAIL` with no literal markers, and `[!-- [[iftags +alpha]] --]KEEP[[/iftags]]\nX` gives `[!&#8212;` and `X`; Prediction B: the comment shields the closer or opener. Probes `-if-comment-closer-untag` and `-cm-hides-if-open` match A, reproducing the R2-NEXT X1 seam from both directions. ## Unreachable branches

The `i` modifier on Comment's regex `/(\n)?\[!\-\-(.*?)\-\-\]/si` and the case-sensitive `strpos($source, '[!--')` guard at `Comment.php:59` were examined as a possible divergence. Prediction A: an uppercase near-marker is removed by the regex despite the guard; Prediction B: guard and regex agree on every authored string. The delimiter contains no letters at all, so the `i` modifier is vacuous over both `[!--` and `--]`; there is no authored page source on which the two predictions differ. UNREACHABLE by parse-side argument, not merely untested. The Iftags no-page branch at `Iftags.php:49-57` (`return;` with no value when no page object and no DB page) is likewise unreachable from an authored saved page: the harness injects a page unconditionally and a real saved page always has a page object; Prediction A (whole block deleted) and B (literal or error) differ, but the trigger is outside the authored input space, so UNREACHABLE for this lane with the serving-layer context named as the only possible route. Two render-side smells are also unreachable: `Render/Xhtml/Blockquote.php:59-67` has no branch for a `type` other than `start`/`end` and the parser never emits one, and `Render/Xhtml/Comment.php:40-44` ignores the `text` option of the one Comment token the parser emits; `Parse/Default/Comment.php:110-114`'s `process()` is dead in the normal path. The Iftags renderer's docblock calling itself "Iframe element" is cosmetic, and its `token()` returning empty is never called because the parse rule claims no token. None of these is a divergence and none yields a candidate.
