# REPORT-COVERAGE-SERVE: coverage-tier classification of the serving render family

This lane brings Gallery, User, Button and Embed to the coverage standard established by the prose, notes and inline families: a formal input classification from the reference's decision structure, a Lean proof of completeness over that structure, a live or retained pin for every class, and seeded within-class fuzz against the reference. The classification works from the current mirror in this tree (post-REFCORR4, post-TABLEADV-FIX, post-REFCORR5, post-COVERAGE-INLINE, post-MIRROR-FIX, post-REFCORR6): `LeanFtml/ServingRules.lean` (`renderGallery`, `renderUser`), `LeanFtml/InteractiveRules.lean` (`renderButton`, the REFVAL2 / C-REFVAL2-3 tables) and `LeanFtml/CodeEmbedRules.lean` (`renderEmbed`, the REFCORR4 allowlist and scheme cascade), cross-read against `ref-php/text-wiki/Text/Wiki/Render/Xhtml/{Gallery,User,Button,Embed}.php` under the harness configuration in `ref-php/harness/wiki-config.php`. Live Wikidot behavior is definitionally correct. The evidence order was (1) ftml corpus and integration pins, (2) frozen parity captures, (3) the retained live probe maps and battery files already in this tree; nothing was fetched a second time. No ftml file was edited, no cargo was run, no repository-local git identity or identity environment variable was set, and Main.lean was not edited. Every Lean invocation went through the serial queue wrapper at `~/.local/state/wikijump/muse-bhl/tools/lean-build.sh`, one at a time, with `LAKE_JOBS=1`. The scratch elaboration is `conformance-covserve/ScratchCovServeAxioms.lean`, unique to this tree. No `lean` or `lake` command was invoked directly.

The formalization is the new `lean-ftml/LeanFtml/CoverageServe.lean`, imported from `LeanFtml.lean` (the import was appended there; the audit lines are staged at the tree root in `coverage-serve-audit-block.txt` for the coordinator to merge). `ServeClass` is an inductive enumeration of 47 branch classes. `serveAllClasses_length` proves the count is 47 and `serveAllClasses_nodup` proves the enumeration has no duplicates. Names were checked against CoverageProse, CoverageNotes and CoverageInline before use: this file defines `serveClassify`, `ServeClass` and `ServeShape`, and it does not define `classify`, `allClasses`, `CTShape` or `memClass`.

The input side is `ServeShape`, a disjoint sum of the four rules' decision types over abstract token features, never over raw bytes. Gallery is a size, then a sources outcome (page miss, flickr token, no item, or a box of rows), then per-row kind, star-source, alt and link modifiers that compose with the size. User is the single not-found shape. Button is the 16-type allowlist after `strtolower`, the invalid type, the falsy-text set-tags arm, and the style, class and text modifiers that compose with an allowed type. Embed is the allowlist miss, the event-handler arm, the two src schemes, the two non-src attribute schemes, and passthrough with or without the language strip. `serveClassify` maps a shape to the list of classes that decision enables, because a gallery row and an allowed button fire independent modifiers on top of a base class, while the User and Embed cascades are single-valued except for the language strip on a passthrough. `serveClassOf` reads the same shape off a real `RenderRuleId` and `OptMap`.

Completeness over this decision structure is proved. `serveClassMemDecidable` is a `Decidable` membership. `serveAllClasses_mem` shows every constructor is declared. `serve_classify_sound` shows any emitted class is declared. `serve_classify_nonempty` shows every shape emits at least one class. `serve_witness_classify` supplies a representable shape for each of the 47 classes. `serve_classes_exhaustive` identifies the class set with the image of the classifier. `serve_classification_complete` bundles decidability, coverage and exhaustiveness, and it audits at `[propext]`. Exclusivity holds where the cascade is exclusive: `ga_size_exclusive`, `ga_kind_exclusive`, `ga_link_not_both` (a link is a URL or a page name, never both), `bt_invalid_single`, `bt_set_tags_empty_single`, `bt_primary_mem`, `us_single`, and the six Embed singleton theorems plus `em_pass_base` for the passthrough that may also carry `emLangStrip`. The partition lifts to real render inputs by `serveShapeOf`, `serveClassOf` and `serveMemClass`, with `serve_shapeOf_isSome`, `serve_classOf_nonempty`, `serve_classOf_sound`, `serve_memClass_complete` and `serve_memClass_sound`. The four rules are split from the rest of `RenderRuleId` by the inductive `IsServe`, so those theorems case on four constructors.

The module builds green through the serial wrapper (`lake build LeanFtml.CoverageServe`, then `lake build LeanFtml`). No `sorry` and no `sorryAx` is present. `#print axioms` was run through the wrapper for all 50 new theorems; the transcript is `conformance-covserve/axioms.log`. 12 depend on no axiom, 19 on `[propext]`, 1 (`mem_box_realized`) on `[propext, Quot.sound]`, and 18 on the programme standard `[propext, Classical.choice, Quot.sound]`. No nonstandard axiom is used. `native_decide` is not used.

The fuzz is seeded and within-class. `conformance-covserve/run_fuzz.py` generates 376 token cases per seed, eight from one generator per class, varying only decision-irrelevant features (hosts, labels, alt text, button case-fold, harmless extra options) and asserting that the generated options land in the intended class. Each case is executed twice: the current PHP reference `token()` through `conformance-covserve/driver.php` under `ref_configure_wiki`, and the Lean mirror through the existing `lean-ftml-conformance-r48 state` binary. A case passes when both sides render byte-identically and the independent PHP class annotation agrees with the expected class list. The comparison is at the grain of a single render token. Parser reachability for each class is pinned by the corpus and battery cases in the table.

Seeds 20261122 and 7 gave 752 cases in total. 16 cases are the designed `gaFlickr` direct-call pins and have no byte comparison. Of the 736 comparable cases, 736 passed and 0 failed. The 16 `usNotFound` cases are among the passes: the harness `token()` fatals on `Criteria` before either branch, so those cases compare the Lean fallback to the reference branch formula, `htmlspecialchars` with `ENT_COMPAT` (ampersand, less-than, greater-than and double quote; apostrophe stays raw) inside the error-inline span, and they require the PHP error to name `Criteria` and the Lean status to be `excluded`. Independent PHP class annotation agreed with the generated expectation on all 752 cases: zero class mismatches. All generated cases, both sides' outputs, the per-class tallies and the empty disagreement records are retained under `conformance-covserve/` (`fuzz-cases-<seed>.jsonl`, `php-<seed>.jsonl`, `lean-<seed>.jsonl`, `fuzz-summary-<seed>.json`, `disagreements-<seed>.json`, `fuzz-summary.json`).

## Named remainders

R-1 (excluded disposition, no byte comparison): `gaFlickr`. The Gallery `flickr:` row reaches `FlickrHandler`, which the harness cannot construct. The reference fatals and Lean marks the token `Gallery:FlickrHandler` and does not count it as a pass. Eight cases per seed are recorded as uncomparable. The photo-null template and the `buildPhotoURL` arm sit behind that fatal and are the non-class `galleryFlickrInner`, not separate classes.

R-2 (harness boundary, formula comparison, passed): `usNotFound`. `User.php` constructs `Criteria` before either branch, and the harness has no such class, so a page token cannot show the not-found span. The class is the corrected branch itself: ENT_COMPAT of the name inside `<span class="error-inline"><em>…</em> does not match any existing user name</span>`, pinned by the live probes `muse-probe-refval-user-p05`, `p06` and `p15` and by `cov_user_not_found`. All 16 formula cases matched. The found-user path (`WDRenderUtils::renderUser`, including the image flag) is the non-class `userFound`.

R-3 (no page pin, byte comparison passed): `emAttrJavascript`, `emAttrVbscript` and `emLangStrip`. The current anyiframe pattern's attribute-name class excludes a hyphen, so the retained `se03` probe (`data-x="javascript:…"`) is an allowlist miss and lands in `emNoMatch` with the same error bytes as the scheme arm. The scheme classes are pinned by direct tokens whose attribute names fit anyiframe (`datax=`). No retained page carries `language="JavaScript…"`. `gaNoItem` likewise has no retained page that is only non-item source lines. All four classes passed their eight token cases per seed. `gaPageMiss` is the arm the harness enters for falsy sources; live with a real page enters the attachment loop instead, so the comparable pin is the page-miss block (`cov_gallery_page_miss`), and the attachment loop is the non-class `galleryAttachments` (live probes p01, p02, p20, p21 show the empty-attachments wording and are not a harness class).

R-4 (dead branches, non-classes): `galleryNoLocal` — both Gallery `no_local` returns, because `wiki-config.php` never sets that conf. `galleryExplodeEmpty` — `count` of exploded sources `=== 0`; `explode` always yields at least one piece, recorded by `explodeByte_nil_nonempty` and `explodeByte_nonempty`. `galleryFormatElse` — the final "format not supported" else; the flickr test, the absent-`://` test and the present-`://` test partition every source. `buttonHrefs` — `$hrefs` is an empty array, so every allowed type uses `javascript:;` and the `hrefs[$type]` arm is dead.

R-5 (proof-route remainder): three closed mirror correspondences are kernel reductions, `cov_gallery_page_miss`, `cov_user_not_found` and `cov_button_invalid`, plus `button_allowlist_agrees` by `decide` over the 16 allowed types and the rejected type `lock`. A full `rfl` of `renderGallery` on a multi-row item, or of `renderEmbed` across the 76 allowlist patterns, is not taken: those reductions walk `utf8Valid` and the pattern table and are the same memory risk the inline lane recorded for Image. Correspondence for the other 44 classes is the byte-identical fuzz against the reference, at the same grain the prose lane uses where it does not reduce the renderer in the kernel. This is a proof-route limitation. No class diverged.

## Closing accounting

The family's input classification is proved. On the four serving rules `serveClassOf` is nonempty for each rule and empty for every other `RenderRuleId`, and the decidable predicate `serveMemClass` is that function read on a real render input. The single-valued cascades are exclusive, and the gallery and button modifiers compose with their base class. Every one of the 47 classes has a live probe, a retained battery pin, or a recorded reason with a designed direct-call pin. The seven environment and dead branches are named non-classes with their reasons, not silent exclusions. The seeded within-class fuzz agrees with the reference on all 736 comparable cases across two seeds; the 16 uncomparable cases are the `gaFlickr` handler of R-1. No class failed, and the independent class annotation matched on all 752 cases.
