# REPORT-COVERAGE-CONTAIN: coverage-tier classification of the container family

This lane brings the container family — Div, Blockquote, Collapsible and Tabview, across parse and render — to the coverage standard established by the prose, notes and inline families: a formal input classification from the reference's own decision structure, a Lean proof that the classification is complete, a pin for every class, and seeded within-class fuzz against the reference on seeds 20261122 and 7. The classification works from the current mirror in this tree (post-REFCORR4, post-TABLEADV-FIX, post-REFCORR6): `LeanFtml/ContainRules.lean` (Div, Collapsible and Tabview parse), `LeanFtml/BlockRules.lean` (blockquote parse), `LeanFtml/InteractiveRules.lean` (Div, Collapsible and Tabview render) and `LeanFtml/ProseRules.lean` (blockquote render), cross-read against `ref-php/text-wiki/Text/Wiki/Parse/Default` and `Render/Xhtml` under the harness configuration in `ref-php/harness/wiki-config.php` (`ref_configure_wiki`). Span and Size already stand in `CoverageInline.lean` and stay out of this family except where a container decision consumes them. Live Wikidot behavior is definitionally correct. The evidence order was (1) ftml corpus and integration pins, (2) frozen parity captures, (3) fresh live sandbox probes; evidence was fetched once, cached and reused from the retained probe maps, battery files and reports. No ftml file was edited, no cargo was run, no repository-local git identity or identity environment variable was set, and Main.lean was not edited. Every Lean invocation went through the serial queue wrapper at `~/.local/state/wikijump/muse-bhl/tools/lean-build.sh`, strictly one at a time; scratch files were unique and inside this tree, and no `lean` or `lake` command was invoked directly.

The formalization is the new `lean-ftml/LeanFtml/CoverageContain.lean`. The brief names the file `CoverageContain.lean.lean`; that doubled extension is a typo, and the module follows `CoverageProse.lean`, `CoverageNotes.lean` and `CoverageInline.lean`. The import was appended to `LeanFtml.lean`. The audit lines are staged at the tree root in `coverage-contain-audit-block.txt` for the coordinator to merge. `ContainClass` is an inductive enumeration of 53 branch classes; `containAllClasses_length` proves the count and `containAllClasses_nodup` proves the enumeration has no duplicates. The collision the earlier lanes hit was checked before naming: this file uses `containClassify`, and its shape type `ContainShape` does not collide with `classify`, `CTShape` or `InlineShape`. The constructors avoid the Lean keywords `end`, `open` and `class` (`endTok`, `opened`, and class names that are not a field called `class`).

The input side is `ContainShape`, a disjoint sum of the family's decision points over abstract features, never over raw bytes. A blockquote run is either the C2 deletion or a kept run carrying a dropped-line flag and a shallower-pop flag. A blockquote render is start, end, or any other type. A div parse is the product of body (plain or scored), head (vanished, bare, or ordered) and the empty-trim unset flag. A div render is vanished, a bare start, an escaped start, a cleared start, an end, or any other type. A collapsible parse is the single claim. A collapsible render is the product of fold, show label, hide label, hide location and token type, five groups that the reference computes independently. A tabview parse tab is the product of title kind and title source; a tabview opener is bare, an echoed dropped class, or an echoed kept class. A tabview render is a start whose items each carry a selected flag and a label, or one of panel-shown, panel-hidden, panel-end, end, and any other type. `containClassify` maps a shape to the LIST of classes that decision enables, because a kept blockquote run, a div parse, a collapsible render and a tabview start compose several decisions, while each type cascade is single-valued. Exclusivity for a tabview start is per item: one start token can carry both `tvSelected` and `tvUnselected`.

Completeness over this decision structure is proved, not asserted. `containClassMemDecidable` is a `Decidable` membership from the derived equality on `ContainClass`; `containAllClasses_mem` shows every constructor is declared; `contain_classify_sound` shows any emitted class is declared; `contain_classify_nonempty` shows every shape emits at least one class; `contain_witness_classify` supplies a representable shape for each of the 53 classes; `contain_classes_exhaustive` identifies the class set with the image of the classifier; and `contain_classification_complete` bundles decidability, coverage and exhaustiveness. The exclusive groups are `contain_exclusive_single` together with `bq_render_exclusive`, `div_body_exclusive`, `div_head_exclusive`, `div_render_exclusive`, the five `co_*_exclusive` theorems, `tv_title_kind_exclusive`, `tv_title_source_exclusive`, `tv_label_exclusive` and `tv_selected_exclusive`. The blockquote deletion gate is `bq_deleted_only`, `bq_kept_excludes_deleted`, `bq_line_dropped_iff` and `bq_kept_always_text`: a deleted run is exactly `bqRunDeleted`, and a kept run always emits text, a nest start and a drain, plus a dropped line exactly when the flag says so, plus a nest end exactly when a later line is shallower. `div_vanished_excludes_ordered` records that a vanished head does not also emit the ordered-attribute class. The partition is lifted to real render inputs by `containShapeOf` / `containClassOf` / `containMemClass` for the four render rules, with `contain_shapeOf_isSome`, `contain_classOf_complete`, `contain_classOf_sound`, `contain_classOf_exclusive`, `contain_memClass_complete` and `contain_memClass_sound`. The lift uses the mirror's own tests, which agree with PHP on every value the parsers store.

No `sorry` and no `sorryAx` is present. `#print axioms` was run through the wrapper on the uniquely named scratch `conformance-covcontain/covcontain-axiom-scratch.lean` for all 51 new theorems: 4 depend on no axiom, 21 on `[propext]`, 2 on `[propext, Quot.sound]`, and 24 on the programme standard `[propext, Classical.choice, Quot.sound]`. The fuzz is seeded and within-class. `conformance-covcontain/run_fuzz.py` generates 221 cases per seed. Render classes are one token, executed as the reference `token()` through `conformance-covcontain/driver.php` and as `lean-ftml-conformance-r48 state`. Parse classes are one authored fragment, executed through the same 68-rule pipeline the prose lane uses (`driver.php source` with `RULES_FULL`) and `lean-ftml-conformance-r48 --e2e-r48`. Within a class the generator varies only decision-irrelevant text (the body word, the attribute payload, the label) and asserts, before any execution, that the Python reading of the PHP decision puts the case in the intended class. A case passes when the PHP run has no error, the Lean status is `ok`, and the two outputs are byte-identical; a token case also requires the PHP class annotation to equal the expected list. The five scalar gaps (R-1, R-2, R-3) are generated inside the class tally with `gap: true`. They are classified by PHP semantics, so the annotation matches the expectation, while the mirror's byte and bool tests disagree. The lane's own driver resets `Text_Wiki_Parse_Collapsible::$count` and `Text_Wiki_Parse_Tabview::$_counter` before each source case, so each document starts at 0 the way one Lean e2e document does. The shared harness and the reference were not edited. This is the same kind of per-case isolation `batch.php` already applies to Math's equation array.

Seeds 20261122 and 7 gave 442 cases in total. All 442 are comparable. 432 passed and 10 failed, and the 10 failures are the five gap cases on each seed: `gap-van-int`, `gap-show-int0`, `gap-show-false`, `gap-tab-00` and `gap-panel-00`. Independent PHP class annotation agreed with the generated expectation on all 442 cases: zero class mismatches. No corpus sub-case was dropped or excluded. All generated cases, both sides' outputs, the per-class tallies and the failure records are retained under `conformance-covcontain/` (`fuzz-cases-<seed>.jsonl`, `php-<seed>.jsonl`, `lean-<seed>.jsonl`, `fuzz-summary-<seed>.json`, `disagreements-<seed>.json`, `fuzz-run.log`, `fuzz-summary.json`), so the tallies are reproducible from the two seeds alone.

## Named remainders

R-1 (scalar gap, parser-reachable values agree): `dvRVanished`. `renderDiv` treats vanished as true only for `OptVal.bool true`. PHP `!empty` also treats the integer 1 as vanished and returns the empty string. The gap token `vanished: 1` renders `<div>` on the Lean side and the empty string on the reference, once per seed. The parser stores the boolean `true` (C-STAGE2-2), and the four non-gap cases in the class, plus `cov_div_vanished_start` and `cov_div_vanished_end`, agree. This lane does not edit the mirror.

R-2 (scalar gap, parser-reachable values agree): `coShowAuthored`. `wikidotLabel` stringifies first through `renderOptValBytes` and then takes the default when the bytes are empty or exactly `[48]` (`"0"`). PHP's strict `=== ''` and `=== '0'` leave an integer 0 and a boolean false on the authored path. `gap-show-int0` renders the anchor text `0` on the reference and `+&nbsp;show&nbsp;block` on the Lean side. `gap-show-false` renders an empty anchor on the reference (`htmlspecialchars` of `false` is `""`) and the same default label on the Lean side. The parser stores strings, and the four authored string cases plus the default-label cases agree. This is the same family as the notes lane's `OptVal.bool false` finding. This lane does not edit the mirror.

R-3 (scalar gap, parser-reachable values agree): `tvSelected` and `tvPanelShown`. `tabviewTabItem` treats a missing tabId as selected, an `OptVal.int` as selected exactly when it is 0, and any other value as selected exactly when its bytes are `[48]`. `renderTabview`'s tabStart hides the panel when the tabId bytes are nonempty and not `[48]`. PHP uses loose `== 0`, so the string `"00"` is selected and the panel is shown. `gap-tab-00` omits `class="selected"` on the Lean side. `gap-panel-00` adds `style="display:none"` on the Lean side while the reference emits `<div id="wiki-tab-0-00">`. The parser stores integer tabIds from its counter, and the integer cases in both classes agree. This lane does not edit the mirror.

R-4 (no page pin, designed direct-call): `bqRenderFall`, `dvRFall`, `coFall` and `tvFall`. The parsers emit only `start` and `end` for blockquote, div and collapsible, and only `start`, `tabStart`, `tabEnd` and `end` for tabview, so no saved page enters a foreign type. Each class has a designed token (`type` `other` or `nope`) and four fuzz cases per seed, all of which agree: the reference and the mirror both return the empty string. The same designed-pin pattern covers `dvRStartClear`'s raw `0xFF` value, which a page reaches only after isolate, and which the battery case `attr-id-space` reaches by isolating a whitespace id to `u-` and then clearing it (`cov_div_id_shell_cleared`).

R-5 (proof-route remainder): the closed correspondence uses `rfl` on the short branches listed above. The collapsible start frame and the tabview start and end scripts are pinned by the battery, the live probes and the within-class fuzz, all of which passed, rather than by an `rfl` over the en-dash and the YUI heredoc. This is a proof-route limitation, and the bytes agree.

R-6 (dead branch, non-class): the `[[blockquote]]` block form does not match. `blockquoteMatchAt` requires a newline and then `>`, and `bq_block_form_unmatched` records that. Battery `bq18-block-basic` stays literal. The stored blockquote level is unread at render (`cov_bq_level_unread`); the harness css configuration is null, so a start is `<blockquote>` with no class. The tabview renderer ignores the class the parser stored and hardcodes `yui-navset`; `tvClassKept` and `tvClassDropped` are the parse decision, and the render class is the hardcoded one. Span and Size remain the inline lane's classes.

R-7 (live-versus-reference frame, mirror agrees with the reference): tabview's doubled attribute text. The opener's raw attribute group is concatenated twice (`tvAttrEcho`; live probe `muse-probe-r2contain-tab-p08-view-class`). On the reference the Paragraph rule then wraps that doubled literal in `<p>` and escapes the quotes, which the source fuzz reproduced (`<p>id=&quot;p0&quot; id=&quot;p0&quot;` and the same shape for `class`). The Lean e2e output matched the reference on all four echo cases per seed. Live and ftml emit that doubled literal bare. The difference is the Paragraph frame, and it is not a tabview class bug. The unterminated view (`p09`, `tv34`) stays literal on live and on the reference; the ftml divergence TAB-F1 is outside this mirror.

R-8 (settled live behavior, now a class): blockquote line deletion. The SPEC2 non-deletion statements (`blockquoteIntent_never_deletes_lines` and its companions) were adjudicated false against live. Live deletes a run in which no inner line has trim-nonempty text, and a kept run still drops an unmatched `>nospace` line. `bqRunDeleted` is exclusive with a kept run. The eight deletion cases per seed (nospace and empty payload) and the four dropped-line cases per seed agree with the reference. Blockquote and iftags stay excluded from REFCORR5; this lane classifies the live deletion and does not reopen it as a correction.

## Closing accounting

The family's input classification is proved. `containClassify` is total on `ContainShape`, every one of the 53 classes is reachable, the declared enumeration is exactly the image of the classifier, and each exclusive group collapses to a single class. On the four render rules `containClassOf` is total and `containMemClass` is that function read on a real token. Every class has a live probe, a retained battery pin, a closed theorem, or a recorded reason with a designed direct-call pin. The seeded within-class fuzz agrees with the reference on 432 of 442 cases across two seeds. The 10 disagreements are the three scalar gaps R-1, R-2 and R-3, two seeds each, and the independent class annotation matched on all 442 cases. Live Wikidot behavior remains definitionally correct throughout: the mirror is not edited to hide the scalar gaps, and the SPEC2 non-deletion statements stay the intent errors the adjudication already recorded.
