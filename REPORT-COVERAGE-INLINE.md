# REPORT-COVERAGE-INLINE: coverage-tier classification of the INLINE render family

This lane brings the eight INLINE render rules — Url, Interwiki, Email, Freelink, Image, Span, Size and Colortext — to the coverage standard established by the prose and notes families: a formal input classification from the reference's decision structure, a Lean proof of completeness over that structure, a live or retained pin for every class, and seeded within-class fuzz against the reference. The classification works from the CURRENT mirror in this tree (post-REFCORR4, post-TABLEADV-FIX): `LeanFtml/InlineSimpleRules.lean` (Url, Interwiki, Email, Colortext), `LeanFtml/ServingRules.lean` (Freelink, Image) and `LeanFtml/InteractiveRules.lean` (Span, Size), cross-read against `ref-php/text-wiki/Text/Wiki/Render/Xhtml/*.php` under the harness configuration in `ref-php/harness/wiki-config.php`. Live Wikidot behavior is definitionally correct. The evidence order was (1) ftml corpus and integration pins, (2) frozen parity captures, (3) fresh live probes; evidence was fetched once, cached and reused from the retained probe maps, battery files and reports. No ftml file was edited, no cargo was run, no repository-local git identity or identity environment variable was set, and Main.lean was not edited. Every Lean invocation went through the serial queue wrapper at `~/.local/state/wikijump/muse-bhl/tools/lean-build.sh`; after the coordinator's incident note, every invocation without exception (builds and single-file elaborations alike) was serialized through that wrapper, scratch files were unique and inside this tree, and no `lean` or `lake` command was invoked directly.

The first turn of this lane ended in the incident the coordinator recorded: several parallel single-file elaborations of a shared scratch file exhausted the machine's memory, one orphaned elaboration grew to about 30G and was killed, and the driver process died in the thrash. Work already written to disk stood. From the incident note onward the stricter rules in the preceding paragraph were followed verbatim; this paragraph is the record the note requires. The heavy `rfl` route through `utf8Valid` on a `String.toList`-derived byte string was abandoned after it grew during elaboration: the mirror-correspondence theorems now pass explicit `OptVal.bytes` byte lists so the kernel reduction stays small, and the two Image local/align `rfl`s that still exceeded the memory cap were replaced by battery-and-fuzz correspondence, recorded as R-8 below.

The formalization is the new `lean-ftml/LeanFtml/CoverageInline.lean`, imported from `LeanFtml.lean` (the import was appended there; the audit lines are staged at the tree root in `coverage-inline-audit-block.txt` for the coordinator to merge). `InlineClass` is an inductive enumeration of 38 branch classes, one per decision the eight reference renderers can take on a token under the harness configuration; `inlineAllClasses_length` proves the count and `inlineAllClasses_nodup` proves the enumeration has no duplicates. The collision the notes lane hit was checked before naming: this file uses `inlineClassify`, not `classify`, and its shape type `InlineCTShape` does not collide with `CoverageProse.lean`'s `CTShape`.

The input side is `InlineShape`, a disjoint sum of eight decision types over abstract token-option features, never over raw bytes: three independent modifier booleans for Url; site-table membership for Interwiki; one current shape for Email (the queued escaping branch is named in R-5); a four-way main branch plus two modifiers for Freelink; a five-way source branch, a link modifier and a six-way align group for Image; start/end/fall for Span and Size; and the admission-and-type cross-product for Colortext. `inlineClassify` maps a shape to the LIST of branch classes its decision structure enables, because Url, Freelink and Image fire independent modifiers that compose with an always-present base class, while Interwiki, Span, Size and Colortext are single-valued cascades. The branch conditions are formalized: `urlBranches` keeps the anchor unconditional and the hash/target/footnote modifiers independent; `flBranches` and `imBranches` append the modifiers to a singleton main branch; `ctBranches` is the admission-by-type cross-product; the Image size group is read with the mirror's `imageSizeOk`/`imageExtSuffix` rules and the align group with the five literal suffix arms.

Completeness over this decision structure is proved, not asserted. `inlineClassMemDecidable` is a `Decidable` membership from the derived equality on `InlineClass`; `inlineAllClasses_mem` shows every constructor is declared; `inline_classify_sound` shows any emitted class is declared; `inline_classify_nonempty` shows every shape emits at least one class; `inline_witness_classify` supplies a representable shape for each of the 38 classes; `inline_classes_exhaustive` identifies the class set with the image of the classifier; and `inline_classification_complete` bundles decidability, coverage and exhaustiveness. `inline_exclusive_class_single`, `iw_exclusive`, `span_exclusive`, `size_exclusive`, `ct_exclusive`, `fl_branch_exclusive`, `im_source_exclusive` and `im_align_exclusive` give per-rule exclusivity for the single-valued cascades and the exclusive groups, while `url_link_always` records the Url base that composes with its modifiers. The partition is then lifted to real render inputs by `inlineShapeOf` / `inlineClassOf` / `inlineMemClass`, with `inline_shapeOf_isSome`, `inline_classOf_complete`, `inline_classOf_sound`, `inline_classOf_exclusive`, `inline_memClass_complete` and `inline_memClass_sound`. Dead and excluded branches are recorded as non-classes: the harness-disabled Url image branch, Interwiki's no-`%s` append arm (`interwiki_templates_all_have_percent_s`), the Image Flickr handler and found-`:first` page, and the Freelink `textFromTitle` DB lookup.

The module builds green through the serial wrapper (`lake build LeanFtml`, then `lake build lean-ftml-conformance-r48`, both through `lean-build.sh`). No `sorry` and no `sorryAx` is present. `#print axioms` was run through the wrapper for all 43 new theorems: 2 depend on no axiom, 14 on `[propext]`, 3 on `[propext, Quot.sound]`, and 24 on the programme standard `[propext, Classical.choice, Quot.sound]`; the headline `inline_classification_complete` audits at `[propext, Quot.sound]`. The fuzz is seeded and within-class. `conformance-covinline/run_fuzz.py` generates 292 token cases per seed from one generator per class, varying only decision-irrelevant features (the literal href, label, body, neutral surrounding text and harmless extra options) and asserting that the generated options actually land in the intended class. Each case is executed twice: the current PHP reference `token()` through `conformance-covinline/driver.php` under `ref_configure_wiki`, and the freshly rebuilt Lean mirror through `lean-ftml-conformance-r48 state`. The PHP driver applies the harness wire encoding to the output so an invalid-UTF-8 rendered byte is compared byte-for-byte rather than becoming a JSON `false`. A case passes when both sides render byte-identically and the independent PHP class annotation agrees with the expected class list. The comparison is at the grain of a single render token, which is the grain of a render classification; parser reachability for each class is pinned by the corpus and battery cases in the table, exactly as the NOTES lane's source half pinned its parser-reachable classes.

Seeds 20261122 and 7 gave 584 cases in total. 32 cases are designed direct-call pins with no byte comparison (R-2 and R-3 below); of the 552 comparable cases, 536 passed and 16 failed, every failure in the single `flTarget` class (R-1). Independent PHP class annotation agreed with the generated expectation on all 584 cases: zero class mismatches. No corpus sub-case was dropped or excluded. All generated cases, both sides' outputs, the per-class tallies, the empty mismatch records and the failure records are retained under `conformance-covinline/` (`fuzz-cases-<seed>.jsonl`, `php-<seed>.jsonl`, `lean-<seed>.jsonl`, `fuzz-summary-<seed>.json`, `disagreements-<seed>.json`, `fuzz-run.log`, `fuzz-summary.json`), so the tallies are reproducible from the two seeds alone.

## Named remainders

R-1 (divergence, live/reference correct): `flTarget` — the current mirror's `renderFreelink` URL branch (`ServingRules.lean`) does not emit the authored `target` attribute, while the corrected reference and live emit `target="_blank"` ahead of `href` for a starred external URL (REFCORR3 C-SUSPECT-SERVING-2, `muse-probe-suspect-serving-free-star-url` and its unstarred control). The parse side was corrected (`LinkRules.lean` appends the target option) but the render side was not: an e2e probe of `[[[*https://example.com/|Star]]]` through `lean-ftml-conformance-r48 --e2e-r48` yields `<p><a href=\"https://example.com/\">Star</a></p>`, where the reference serves the target attribute. All 16 occurrences in the fuzz show this exact difference. This lane does not edit other mirrors; the divergence is stated here as a named remainder, classified as it stands (the render branch exists and is pinned), and left for the owning correction lane.

R-2 (unreachable class, no byte comparison): `flSite` — the fossil cross-site branch is unreachable after the R2-LINK parse correction removed the `::` convention. A direct token call with a truthy `site` option makes the reference fatal on the undefined `GlobalProperties` constant while the mirror renders a fossil-shape anchor. Eight cases per seed were generated and recorded as uncomparable, never as passes; the class remains in the partition as a designed direct-call pin.

R-3 (excluded disposition, no byte comparison): `imFlickr` — the Image `FlickrHandler` serving boundary. Lean marks the token `excluded` and the reference fatal; eight cases per seed are recorded as uncomparable. The `:first` branch by contrast is safe (both sides render the empty string) and is pinned by the designed `image_first_empty` token call.

R-4 (no page pin): `urlFootnote` — `Parse/Default/Url.php` never emits `type=footnote`, so no saved page enters the branch. The designed direct-call pins are `renderUrlFootnoteIntent` and `ws2_10_table_and_url_unreachable_specs` (SPEC-PINNED), with mirror theorem `url_footnote_wrap`; the class is exercised by eight token cases per seed. `spFall`, `flNonbr` and `imFirst` likewise have no page pin and carry designed direct-call pins in the inventory.

R-5 (queued correction, branch classified as it stands): Email escaping. REFCORR5 Batch 3 (C-SUSPECT-EMAIL-1/2, 44 fresh probes) will wrap the reversed-and-joined string in `htmlspecialchars(..., ENT_NOQUOTES | ENT_SUBSTITUTE, 'UTF-8')`, so `& < >` escape, quotes stay raw and invalid bytes become U+FFFD. Today's `renderEmail` emits the raw string; `email_current_render_has_no_escaping` records the raw `&` that will move. The `emReversed` class is classified against the current branch and names the queue item in its record rather than waiting for it. Colortext parse-time validation is REFCORR5 Batch 2 and is parse-side, hence outside this render family; the render-side `ctInvalidStart`/`ctInvalidOther` classes stand as they are, and the AGY `p09` divergence is a queued parse correction.

R-6 (dead branch, non-class): Url's image arm is disabled by the harness `images=false` conf, so no authored render input reaches it; the closed `cov_url_link` exhibits the anchor that always replaces it and the SPEC pins `renderUrlImageIntent` / `ws2_10_table_and_url_unreachable_specs` record the same dead branch. Interwiki's no-`%s` append arm is dead because all five registered templates carry exactly one `%s` (`interwiki_templates_all_have_percent_s`).

R-7 (X44 settlement): the interwiki label bound is not a render-class question. X44 settled that the reference's described-form label pattern over-claimed a delimiter byte or an opening bracket and leaked the process-global token index into the label; live leaves the whole bracketed form literal. The corrected parse pattern excludes those bytes, the embedded index was a reference artifact rather than live behavior, and the digit-run normalization was dissolved with the x44 exclusion. `renderInterwiki` needs no change; the `iwKnown` / `iwUnknown` partition is unaffected.

R-8 (proof-route remainder): the closed mirror-correspondence section uses 17 `rfl` computations, one per decisive branch that admits a small kernel reduction. The two Image local/align branches are pinned by battery cases and the within-class fuzz instead of an `rfl`, because reducing `renderImage` through `utf8Valid` on a composed `litBytes` path exceeded the wrapper's memory cap; the correspondence is therefore established at the reference-and-fuzz level for those two branches, exactly as the prose lane carries its correspondence at the battery level for the paths it does not reduce in Lean. This is a proof-route limitation, not a divergence.

## Closing accounting

The family's input classification is proved. On the eight INLINE rules `inlineClassOf` is total and the decidable predicate `inlineMemClass` is that function read on a real render input; the single-valued cascades are exclusive and the modifier groups compose with their unique base class. Every one of the 38 classes has a live probe, a retained battery pin, or a recorded reason with a designed direct-call pin. The seeded within-class fuzz agrees with the reference on 536 of 552 comparable cases across two seeds; the 16 disagreements are the single `flTarget` divergence of R-1, and the 32 uncomparable cases are the two serving/unreachable branches of R-2 and R-3. No other class failed, and the independent class annotation matched on all 584 cases. Live Wikidot behavior remains definitionally correct throughout: the reference is not changed to hide R-1, and no queue item is pre-empted.
