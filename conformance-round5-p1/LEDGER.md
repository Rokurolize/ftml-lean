## L4 — uppercase opener with no item and no closer at all

Why: REFCORR7 degrades an item-less uppercase opener to bare prose by rewriting swallowed [[/ul]] closers in the body; when there is no closer anywhere the rewrite has nothing to consume and the residual-body trimming branch may differ from live. Pre-probe prediction: CONFIRM if live forms an unclosed list or keeps a blank-line break while the reference emits bare prose 'plain' followed by the AFTER paragraph; that is a genuinely new sibling of C-SUSPECT4A-4. Alternative outcome: CLEAR if live also degrades to the same bare prose paragraph as the reference. Source: `[[UL]]\nplain\n\nAFTER`.

## DL1 — narrative body consisting only of an empty Raw placeholder

Why: Deflist::termRendersEmpty strips empty-Raw placeholders only from the term, so a narrative of only @@@@ becomes a <dd> holding a token that renders to nothing; after REFCORR7 made empty-Raw emptiness decisions in Footnoteitem/Bibitem, the narrative half of the same placeholder interaction was not examined. Pre-probe prediction: CONFIRM if live omits the <dd> entirely while the reference emits <dd></dd>; that is a rule-level element difference and a new sibling of the closed empty-Raw footnote/bibitem shapes. Alternative outcome: CLEAR if live also emits the empty <dd> as the reference does. Source: `: term : @@@@`.

## DL2 — term made of a Comment plus an empty Raw placeholder

Why: termRendersEmpty strips both Comment and empty-Raw tokens, so a term built from one of each renders empty and its <dt> is omitted; the composite of two independent placeholder-empty rules is an interaction no author would write deliberately. Pre-probe prediction: CONFIRM if live keeps a <dt> for the composite term while the reference omits it; that is a rule-level element difference. Alternative outcome: CLEAR if live also omits the <dt> and emits only the <dd> as the reference does. Source: `: [!-- hide --] @@@@ : val`.

## DL3 — colon-led first line with no separator followed by a valid item

Why: The inner grammar '/^(: )(.*)?( : )(.*)?$/Ums' requires a ' : ' separator, so a ': term' line that lacks it is silently dropped while a later ': t2 : v2' line still forms the list; the run-wide compiler decides membership per line with no diagnostic. Pre-probe prediction: CONFIRM if live keeps the separator-less line as a <dt> with an empty <dd>, or as literal text, while the reference emits a list containing only t2/v2; that is a rule-level membership difference. Alternative outcome: CLEAR if live also drops the separator-less line and emits the same one-item list as the reference. Source: `: term\n: t2 : v2`.

## T1 — empty Raw placeholder at a color-scope edge

Why: Tighten strips the empty-Raw placeholder before folding spaces and before the color hoist/eject pass; with the placeholder between a color opener and a space the strip, fold, hoist and paragraph-edge trim passes compound, an interaction of four separate mechanisms. Pre-probe prediction: CONFIRM if live keeps the color scope with a leading or trailing space, or omits it, in a way that differs at the rule level from the reference's trimmed bare span; that is a genuine interaction divergence. Alternative outcome: CLEAR if live produces the same trimmed bare color span as the reference. Source: `[[color red]] @@@@ [[/color]]`.

## T2 — two adjacent empty Raw placeholders in prose

Why: Tighten removes every empty-Raw placeholder from the residual stream and then folds the resulting multi-space run to one, so two placeholders collapse the same way as one; the count-independence is an emergent property of str_replace in a loop. Pre-probe prediction: CONFIRM if live emits two spaces or a break between the segments while the reference emits a single space; that is a rule-level whitespace difference. Alternative outcome: CLEAR if live also collapses to one space as the reference does. Source: `a @@@@ @@@@ b`.

## T3 — empty Raw placeholder immediately before a Newline token

Why: Tighten strips the empty Raw, leaving a space before the Newline token, and only then applies the Newline-edge trim; the order makes the space disappear only because the strip ran first, so a different order would leave a visible space before the break. Pre-probe prediction: CONFIRM if live keeps a space before the <br /> while the reference trims it, or vice versa; that is a rule-level whitespace byte difference at a break edge. Alternative outcome: CLEAR if live also trims the space so both sides emit 'a<br />b'. Source: `a @@@@\nb`.
