## What was ledged and probed

Thirteen suspicions were written to conformance-suspect4a/LEDGER-PREPROBE.md before any live probe, each with the construct, why it looks wrong, the live byte that would confirm it and the live byte that would clear it. conformance-suspect4a/make_cases_ledger.py generates the ledger and cases.jsonl from one table, so the probed source identities cannot drift from the ledger prose. The thirty sources were created as saved pages under the muse-probe-suspect4a-* prefix on sandbox-for-codex and captured with wikidot-probe, which fetches each page twice anonymously and verifies the saved source. Twenty-eight captures are valid, stable and source-matching. Two prefilter probes, s4a-p1b (a form-feed-only line) and s4a-p1d (two space-only lines), are invalid because Wikidot's save filter normalized the intended source before storage; saved_source_matches=false, so they are recorded as UNTESTABLE rather than used as clearance or divergence evidence. The pages are kept in place. All thirty sources were then rendered through this tree's ref-php harness with `cd ref-php && php harness/batch.php render < ../conformance-suspect4a/cases.jsonl > ../conformance-suspect4a/ref.jsonl`, exit 0 with empty stderr, and a tokens pass with the same input also exited 0. Confirmed shapes were compared at the byte level against those reference renders after masking only the already-owned Stage 2 frame surface: inter-tag newlines, trailing paragraph newlines and the &nbsp;/U+00A0 spelling.

## CONFIRMED — S4A-L1, the mixed-case nested-list closer (C-SUSPECT4A-1)

The minimal shape is `[[ul]]` / `[[li]]a` / `[[OL]]` / `[[li]]b[[/li]]` / `[[/ol]]` / `[[/li]]` / `[[/ul]]`. Live serves `<ul>\n<li>a<br /></li>\n<li>b</li>\n</ul>\n<br />`; the reference serves `<ul>\n<li>a<br /><ul>\n<li style="list-style: none">[[li]]b</li>\n</ul></li>\n</ul><br />\n`. The lowercase outer opener pairs, the uppercase inner opener is recognized on live and the inner item becomes an ordinary <li>; the reference keeps the inner opener's raw case on its stack while lowercasing the closer, so the pair never matches and the reference synthesizes an unclosed list that leaves [[li]]b literal. The second probe, an uppercase outer UL wrapping a lowercase ol, serves live `<ol>\n<li>a</li>\n</ol>\n<br />` against a reference `<ul>` wrapper with an inline list-item wrapper. The live hash of the first probe equals the frozen muse-probe-refcorr5-lc-sib-nested-lower-ul-upper-ol hash, so the fresh capture reproduces the prior ground and extends the unpinned lowercase-closer variant.

## CONFIRMED — S4A-L2, the cross-type uppercase closer (C-SUSPECT4A-2)

The minimal shape is `[[ol]]` / `[[li]]a[[/li]]` / `[[/UL]]`. Live serves `<ol>\n<li>a</li>\n</ol>\n<br />`, while the reference leaves the whole block literal in `<p>[[ol]]<br />[[li]]a[[/li]]<br />[[/UL]]</p>`. With trailing prose the live bytes are `<ul>\n<li>a</li>\n</ul>\ntrailing` against the reference's literal `<p>` form. REPORT-REFCORR5 batch 1 recorded this C11 classification from the pinned lc-sib-cross-ul-ol-upper capture, but the current closer gate still requires stack tag equality after lowercasing the closer, so a cross-type uppercase closer fails. This is an incomplete implementation of a classification the correction round itself measured, not a new live behavior.

## CONFIRMED — S4A-L3, attributes on an uppercase opener (C-SUSPECT4A-3)

The minimal shape is `[[UL id="x" style="color:red"]]` / `[[LI]]A[[/LI]]` / `[[/uL]]`. Live serves the truncated unclosed-list form `<ul>\n<li>A<br />` with no attributes on the opener; the reference serves `<ul id="u-x" style="color:red">\n<li>A<br />\n<br /></li>\n</ul><br />\n`. The second probe, `[[OL data-x="1"]]...[[/OL]]AFTER`, serves live `<ul>\n<li>aAFTER</li>\n</ul>` against reference `<ul data-x="1">\n<li>a<br />\nAFTER<br />\n<br /></li>\n</ul><br />\n`. Live drops id, style and data-* on an uppercase opener and absorbs the tail into the last item; the reference still runs buildListAttrs for that opener and emits the attributes. This completes the C1/C5/C6 family that the pinned class-only shape had left half measured.

## CONFIRMED — S4A-L4, the degraded item-less uppercase opener (C-SUSPECT4A-4)

The minimal shape is `[[OL]]` / `plain body` / `[[/OL]]` / blank line / `AFTER`. Live serves `<p>plain body<br />\nAFTER</p>`, while the reference serves `<ul>\n<li style="list-style: none">plain bodyAFTER</li>\n</ul><br />\n`. The TitleCase variant serves live `<p>bodyAFTER</p>` against the reference's list wrapper. The presence of the list element and the item body shaping differ; there is no frame surface involved. This is the C10 classification recorded in REPORT-REFCORR5 batch 1 from the pinned degraded-noli capture, still not realized by the current reference.

## Why these are reference defects and not serving-layer differences

All four confirmed families are parse-side: the reference builds the wrong token structure (or no token structure) from the same source, as shown by the render bytes and corroborated by a tokens pass. They are not the module placeholder class S, not the Stage 2 purifyHtml frame, not the +1 token-numbering canonicalization, and not the M72 entity spelling. The earlier correction round's own report states the live classification these shapes should follow, so the mechanism in Parse/Default/List.php (raw-case opener stack, lowercased closer plus strict tag equality, unconditionally computed attributes and degraded-body list synthesis) is what routes to the later correction round; this lane did not edit that file. The mirror consequence for the coordinator is that ListRules.lean's CI recognition and unmatched-uppercase synthesis encode the same partial mechanism, byte-identical to the reference on the divergent rows, so the four candidates carry both sides.
