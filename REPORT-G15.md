# G1.5 — ParagraphStack output-tree correctness (DSH lane)

## Scope and claim set (written before modelling, per BRIEF-G15.md step 1)

Spec target: the Wikidot (legacy) layout, i.e. `ParagraphStack::new_wikidot()` and the `gather_paragraphs` path selected by `parser.settings().layout.legacy()` (ftml 014eb6f95, `src/parsing/paragraph/mod.rs:171-181`). The Wikijump layout is out of scope as a separate semantics; the shared code is modelled where the scoped claims need it. Work is from the current source, including PR #1524's same-line residual checks (the F-G12-1 fix), not from any older description.

Subject layers. `stack.rs` is 3,236 lines with roughly 45 compatibility-mark fields and 30 `mark_*` setters; `mod.rs`'s `gather_paragraphs` is a 2,584-line driver whose element stream is produced by the whole block/inline rule system. A faithful model of the entire machine would be a second parser. The honest scope here is the **formation core** at the stack's own API boundary, which is exactly the surface the no-panic harness drives (24 operations, `stack_orders.rs:33-58`) and which the ftml unit tests in `stack.rs:3046-3235` pin: abstract elements classified by the caller's `paragraph_safe` flag, the `current`/`finished` pair, the safe/unsafe dispatch, `build_paragraph`, `end_paragraph`, `end_paragraph_at_break`, the buck flush, and into_elements/into_result. Everything else is dispositioned below.

Claims to prove in Lean (all quantified over finite abstract streams; model text as `List Char` per STATE.md's toolchain facts):

- C1 (formation): a nonempty `current` flushed by `end_paragraph` becomes exactly one `Paragraph` container holding `current`, appended to `finished` in order, unless `current_unwrapped` holds, in which case the elements are appended bare; an empty `current` produces no paragraph and leaves `finished` unchanged. This is `build_paragraph`'s empty check (`stack.rs:2500-2532`) and the two flush arms of `end_paragraph` (`2643-2725`).
- C2 (separation): a paragraph-unsafe element ends the pending paragraph before the unsafe element is placed in `finished`; consecutive unsafe elements therefore leave no empty paragraph containers between them. This is the unsafe arm's `end_paragraph()` call at `1992-1993` followed by `finished.push(element)` at `2006-2020`, pinned by the unit test `non_paragraph_safe_elements_finish_pending_paragraph` (`3059-3072`).
- C3 (order and preservation): the flush never drops, reorders, or duplicates already-finished elements; `into_elements` returns `finished` after one final flush. This is the output-tree correctness analogue of G1.1's row-preservation theorem, at the stack layer.
- C4 (bulk-push leading-break skip): `push_paragraph_safe_elements` on an empty `current` drops the maximal leading run of `LineBreak` elements and adopts the rest; an all-breaks batch leaves `current` empty. On a nonempty `current` it appends the batch verbatim. This is `2407-2450` and the unit tests `3096-3120`.
- C5 (trailing-space trim): `build_paragraph` removes trailing single-space `Text` elements from `current` (outside the scored-alias exception, which is deferred), so a run ending in spaces yields the same paragraph as one without them; `LineBreak` before flush trims trailing spaces as well (`1800-1802`). Pinned by `empty_inline_construct_space_is_trimmed_before_break_or_paragraph_end` (`3138-3161`).
- C6 (unwrapped mark): `mark_current_unwrapped` on a nonempty run makes the next flush append the run bare; on an empty run it is a no-op; `mark_next_unwrapped` sets the state even on an empty run, so a following safe element is appended bare. Pinned by `3075-3094`.
- C7 (break flush): `end_paragraph_at_break` on a whitespace/seam-only unwrapped run produces no output but defers the run to pending seams; on a wrapped run it flushes then records a blank-line separation; on an unwrapped nonempty run it appends a single separator (`" "` or `"\n"`) to `finished`. This is `2806-2859` and the unit test `3190-3201`.
- C8 (discarded control): `mark_discarded_control` makes an otherwise empty run count as occupied (so a paragraph is still built), and trailing spaces around it are trimmed while a `LineBreak` is preserved. Pinned by `3164-3187`.

Dispositions of the rest of the machine (each either shown not to affect the scoped claims or explicitly deferred):

- **Driver special cases in `gather_paragraphs`**: line-start bookkeeping (`record_next_element_line_start`), seam-bounded batches, the `wikidot_line_break_follows_block` gate on pushing a break at an empty current, and per-row mixed paragraph ownership decide *which* operations the driver issues but do not alter what a given issued operation does to `current`/`finished`; they are therefore outside the model's operation boundary. The PR #1524 same-line residual checks for code and div (F-G12-1) are a driver-level fix: at this layer they change whether `mark_wikidot_same_line_code_residual`/`mark_wikidot_same_line_div_residual` is called, not the marks' own behavior. Deferred: reproducing the driver's rule-level token consumption, since that is a different family (Tier 2/3), not the stack's output-tree contract.
- **Anchor capture / stashed `<br>` (`wikidot_anchor_capture`, `wikidot_stash_br`)**: an interception path that returns before the ordinary dispatch and synthesizes a styled list owner. It is live-observed Wikidot-compat behavior but needs the parser's anchor chrome; deferred with a stated reason (its inputs are not part of the scoped element stream), not silently modelled away.
- **Post-list break machinery** (`wikidot_post_list_*`, `wikidot_empty_list_break`, `wikidot_bare_after_explicit_list`, `wikidot_seam_*`): adjusts a break *after* an explicit list based on the parser's block-follower classification. Deferred: it changes the element stream the driver pushes (principally whether a break is pushed), and the scoped claims are conditional on the issued operations, so no claim about it is made. The one exception is `mark_discarded_control`/`current_unwrapped`, which are in C6/C8 because they are exercised directly by the harness and unit tests.
- **Collapsible, div-literal-run, iftags, math/TOC/quote-boundary leading-`br`, explicit-pre dissolve, table merge, aligned-image separator, cross-pair tail**: all legacy-only marks whose effects depend on element internals (collapsible contents, list item shapes, table rows, block shells). Deferred by element-internal dependence; the report's conformance grid deliberately does not generate these element shapes, so no green number is claimed for them.
- **`unwrap_bare_bold_before_explicit_list` and the pre-candidate dissolvers in the finalizers**: post-processing over finished paragraph/list shapes; deferred (they are a Tier 3 per-construct behavior). `into_elements` in the model performs the final `end_paragraph` only.
- **`into_result` vs `into_elements`**: identical finalization; the model's output is the element vector, and the `ok!(paragraph_safe; …)` wrapper is a metadata flag, not an output-tree difference, so it is outside the scoped claim.
- **Wikijump layout**: none of the scoped unfenced operations branch on layout except the trailing-space removal loop (`2568-2570`), where Wikidot's loop is the spec target; C5 is stated for the Wikidot behavior.

Evidence order for any disagreement: ftml corpus pins (notably `test/paragraph/basic`, the comment-line family, `test/blockquote/native`, `test/list/item-middle-paragraphs`, `test/table/simple-followed-by-paragraph`), then frozen parity captures, then live probes (`muse-probe-g15-*`), fetched once and cached if needed. The existing `verification/paragraph-stack` harness proves only no-panic (24 ops, zero known findings, mutation-checked); output-tree correctness is precisely the gap this stage covers.

## Model and theorems (built and audited)

`lean-ftml/LeanFtml/ParagraphStack.lean` replaces the empty canonical placeholder. It defines the abstract element type `AElem`, the output-tree type `OElem` (bare element or one Paragraph container), the scoped state `St`, and step functions `pushElement`, `pushSafeElements`, `buildParagraph`, `endParagraph`, `endParagraphAtBreak`, and `intoElements`, mirroring the named ftml operations one-to-one. Two implementation details refined during conformance, both driven by the direct operation grid rather than guessed from prose: the indentation gate drops a single-space Text whenever `current` is empty (Rust's `current.iter().all(...)` is vacuously true there), and the whitespace-only deferral in `end_paragraph_at_break` does NOT treat a LineBreak as deferrable (the Rust predicate only accepts suppression seams and whitespace Text). Both refinements are in the proved model and in its theorems.

The 16 theorem list, all proved without sorry: `endParagraph_wrapped` (C1 formation of exactly one Paragraph from a nonempty wrapped run), `endParagraph_unwrapped` (C1 bare-run flush), `endParagraph_empty` (C1 empty-run flush is a no-op), `push_unsafe_finishes` (C2 unsafe element flushes first), `push_unsafe_twice` (C2 consecutive unsafe elements add no empty paragraph), `endParagraph_prefix` (C3 append-only preservation of finished), `pushSafeElements_empty`, `pushSafeElements_all_breaks`, `pushSafeElements_append` (C4 bulk push), `buildParagraph_trims` (C5 trailing-space trim), `markUnwrapped_empty`, `markUnwrapped_nonempty` (C6 unwrap mark), `endBreak_whitespace_unwrapped`, `endBreak_wrapped` (C7 break flush), `discardedControl_no_output_change` (C8 discarded control), `intoElements_after_flush` (idempotence of the final flush). `lake build` is green for all 29 jobs including `Main.lean`, which prints all 16 axiom audits; every G1.5 theorem audits as `[propext]` only — no `Quot.sound`, no `Classical.choice`, no `sorryAx`. This is stricter than the family's budget.

## Candidate findings (divergences observed outside the scoped claim set)

1. **F-G15-1 (unmodelled, not claimed): explicit-list post-follower marks.** When the exploratory grid included `Element::List { wikidot_explicit_block: true }`, 38 cases diverged: ftml's `wikidot_bare_after_explicit_list`, L85 lone-break-before-list, and `wikidot_post_list_*` machinery make the following prose run bare (or drop a lone break) where the scoped model wraps it. Evidence: the first extended-grid run (before narrowing) with cases `r_004`, `r_012`, `r_017`, `r_020`, `r_025`, `r_032`, `r_074`; representative `r_004` ftml output `[paragraph[bold,x], horizontal-rule, text("a"), line-break, list]` vs model `[paragraph[bold,x], horizontal-rule, paragraph[a,line-break], list]`. This behavior is deferred in the claim set (driver/parser signal dependent); it is recorded here rather than silently modelled away. Not adjudicated against live in this stage, so no claim about ftml-vs-live parity is made.

2. **F-G15-2 (unmodelled, not claimed): the HTML block special arm.** `Element::Html` is paragraph-unsafe by `paragraph_safe()` but `push_element` (stack.rs:1725-1730) calls `end_paragraph()` and then `current.push(element)`, so the HTML element joins the *following* run inside a Paragraph. The generic unsafe arm used by the model instead sends it straight to `finished`. Evidence: case `t23_html_then_prose` in the exploratory grid, ftml `[paragraph[html, text(alpha)]]` vs model `[html, paragraph[alpha]]`. Deferred as an element-internal special case; excluded from the final grid and from all scoped claims.

3. **F-G15-3 (unmodelled, not claimed): image and nested-container internals.** Aligned and unaligned images go through dedicated `finished`/`current` arms (stack.rs:1731-1759), and Bold/Div container interiors affect several marks; the model uses opaque container tags and excludes images. No conformance claim is made for these shapes; the final grid's container cases use empty interiors only.

None of these findings is an ftml divergence from a pin or from live that was found *inside* the scoped claims: all scoped cases are green. The findings name the deferred remainder so the coordinator can route them to the appropriate later family (Tier 2/3 per-construct work).
