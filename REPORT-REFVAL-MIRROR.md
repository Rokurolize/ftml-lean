## What changed in the mirrors, and why it matches the corrected reference

**LeanFtml/MiddleRules.lean, Center.** The corrected reference pattern is /^= (.*)$/m and its process returns "\n\n", the start token, trim(body), the end token, "\n\n": the match consumes neither bounding newline, the body is the rest of the line, and PHP trim (byte set space, tab, LF, CR, NUL, VT) is applied to it. centerScan was rewritten to the line-anchored shape the file's own lineScan already uses for the other anchored rules: it now carries an atStart flag (subject start, or previous byte a newline), attempts a match only at a line start on the bytes "= ", takes the body as the run up to the first newline (or the subject end, for an unterminated last line, where the pattern's $ also matches), splices trimBytes body between the start and end tokens with the "\n\n" pair on each side, and resumes scanning at the newline that ended the body, so the next line is attempted on its own and every consecutive Center line claims a pair. trimBytes is the project's existing PHP-trim mirror (ModuleRules.lean), so the trim is byte-for-byte the reference's. centerRule now seeds the scan at a line start. The three pre-existing Center worked examples were updated to the corrected expectations (the doc-start example now demonstrates a match where the fossil pattern could not fire, and the consecutive example demonstrates both lines claiming), and two examples were added: centerScan_trim_example (a space-and-tab-padded body trims to its core) and centerScan_unterminated_example (a Center line on an unterminated last line claims). The header's Center bullet was rewritten to state the corrected semantics and the fossil behavior it replaced, with the settling probes named (muse-probe-refval-center-p08, p10, p11). splitAtByte, used only by the old scanner, remains defined and is now unused by Center; nothing else referenced it.

**LeanFtml/ParaRules.lean, Paragraph.** paraSkipRules gained exactly the two entries the corrected reference's skip list gained, "separator" and "divalign" (the bare form, alongside the four side forms already present), in the reference's own list order; the mirror's process already lowercases the opening token's rule name before the membership test, so a run opening with a Separator or Divalign token is now returned unwrapped, which is the whole mechanism of the correction (live serves the separator block and the aligned div bare). Two worked examples were added (paraProcess_separator_skip_example, paraProcess_divalign_skip_example), and the header's skip-list enumeration and the definition's doc comment record the REFVAL provenance. No other mirror code changed in either file.
