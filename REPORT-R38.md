## The two class-static counters: disposition

Both statics the brief flagged are observable in parse-time token options, and the disposition is mirror-maintained document state, not a compared-state extension and not a harness change. Collapsible's process stores the pre-increment value of Text_Wiki_Parse_Collapsible::$count as the `count` option of both its tokens (the R2 render correction C1 left the option in the stream, unused by the renderer, but present at parse time, which is what this tier compares), and Tabview's process stores the pre-increment value of Text_Wiki_Parse_Tabview::$_counter as the `tabviewId` option of every token it claims (the shared tabStart and tabEnd, each tab's tabStart, and the view's start and end). The mirrors therefore keep the two counters in the DocState fields the R3.1 inventory already provided (collapsibleCount and tabviewCounter), per-document from zero, incremented exactly where the PHP increments them: once per Collapsible process call after both tokens are built, and once per Tabview process call after all its tokens are built. No harness file was edited: state-restricted.php does not reset either static, and the leak across cases inside one driver process is real on both sides (in the combined-corpus restricted run, the collapsible counts run 0..65 and the tabview ids 0..53 in corpus order, so for example c01-basic-line carries count 3 because three earlier cases in the combined corpus claimed collapsibles first, where its per-battery fixture carries 0). Because the raw values carry the process base of every earlier document in the run, the stage's compare.py canonicalizes the two options per document by order of first appearance in the record's token table, keyed by (rule, option) as (Collapsible, count) and (Tabview, tabviewId), top-level integer values only; this is disclosed in compare.py's header as a canonicalization of the same class as the per-document token renumbering R3-SCOPE.md already sanctions, and it is deliberately narrow: Toc's per-call `count` option, the per-tab `tabId` (a per-process-call instance counter, already per-document), and any `count` key nested inside an args map (a string value, as a collapsible may literally carry a count="7" attribute) are not touched, and the fuzz family includes exactly that attribute shape to prove the boundary. The Lean driver needs no change for this stage's counters, since its per-case process always starts from zero, which is the canonical form the comparison maps the PHP side onto.

## Per-rule notes

Span and Div share the recursive lazy body shape the Code mirror established, `((?:(?R)|.)*?)` against a closer, and both rules' parse() overrides repeat the pass while the source changes, so nesting is claimed outside-in across passes: a synthetic probe against the restricted oracle during derivation confirmed that a nested span and a nested div each create the outer token pair in the table before the inner pair. Span's opener group is the one shape in the family whose second byte is an arbitrary `.` byte, and its process keeps the live attribute whitelist (id first with the `u-` prefix, then class, style, role, type and the lower-cased data-* keys in source order, empty values omitted) with the unattributed empty-body elision. Size is the family's inside-out rule: its tempered body (no unit may start a new `[[size\s`) makes the outer match fail wherever an inner opener stands, so the inner pair is claimed in the first pass and the outer in the second, which the same probe series confirmed from the token table order; an invalid value's process returns the whole match unchanged, which ends the repeat loop exactly as in the reference, and the two body corrections (C0 control-byte removal, line-end space/tab run removal) are byte operations that leave placeholder bytes untouched. Div is the family's heaviest process: the scored form's paragraph strip (CR/LF edge trim, then blank-line runs removed entirely, joining the surrounding text), the unscored form's blank-line wrapping with the captured leading newline doubled where the scored form emits it once, the empty-div suppression decided on the pre-unset argument set, and the id isolation with its Unicode-whitespace collapse. The isolation has one genuinely non-byte path: a value that is not valid UTF-8 (in the model, one carrying a placeholder byte) makes the reference's /u replacement return null, and the mirror's isolateId returns none for exactly that case when the value starts with `u-` (the caller records a null, which the process's own empty-value unset then always removes before any claim) and the bare prefix otherwise; no corpus or fuzz case exercises a placeholder-bearing id value, so this path rests on the PHP semantics of the corrected file, recorded here as the one modelling judgement in the stage that the differential evidence does not reach. Collapsible is the base class's single pass with a plain lazy body, so a nested opener is consumed into the outer body by the first-closer discipline and never claimed, the G1.2 discipline restated for this family. Tabview is the family's most intricate mirror: a line-anchored outer match (one or more tab units, then the closer) whose process claims its two shared placeholder tokens before the inner rewrite runs, so the token creation order is shared tabStart, shared tabEnd, per-tab tabStart tokens in region order, then the view's start (carrying the class-only args and the tabs list) and end; the replacement emits the raw attribute group twice before the start token, a fossil shape the corrected reference retains and the battery pins (the tv43-view-class shape), reproduced exactly; the inner tab pattern differs from the outer unit pattern in its trailing run (newlines only, where the outer unit takes the full whitespace class), and the per-tab handler's ff hack (group 1's trim being exactly one quoted pair makes group 1's raw bytes join the argument string and suppresses the title default) was settled by a derivation probe before modelling: on `[[tab title="T" class="c"]]` the tab entry is {"class": "c", "title": "T", "tabId": 0}, the class first because the argument string is built from group 2's content before group 1's pair is appended. All five rules work on the byte-form view, as the R3.3 obligation requires of rules after token-producing rules; the placeholder can appear inside Span, Size, and Div bodies, inside Collapsible bodies and attribute values, and inside tab bodies and titles (where _tabTitle's delimiter test empties a placeholder-carrying title), and the mirrors treat it as an ordinary byte everywhere except the two places the reference itself decodes (the id isolation above, and getAttrs' shared byte behaviour inherited from the earlier stages).

The Anchor-interposition class the brief named as the expectation did not arise on this corpus: the interposed Anchor rule's claims change no CONTAIN claim sequence on any of the 372 cases, which summary C's clean 372/372 and the prefix-vs-restricted agreement jointly show; the exclusions above are recorded instead with their own reason, per the brief's instruction to record the reason for whatever exclusions the check produces.
