# REPORT-REFGAPS: Reference Completeness Gaps Closure (2026-11-21)

This report records the closure of the three reference PHP (`ref-php/`) completeness gaps specified in `PROMPT-ANTIGRAVITY-REFGAPS.md`: Gap 1 (the `Anchor` rule and its `PG-F1` scored `[[a_]]` paragraph hook), Gap 2 (the explicit `[[ul]]` / `[[ol]]` / `[[li]]` list block forms, ledger item `M46`), and Gap 3 (the `Include` missing-page message, class `M`). No shared harness file (`ref-php/harness/`), ftml checkout file, or canonical record file was edited, and no git commits were made.

---

## Gap 1: The Anchor rule (`conformance-refphp/anchor/`)

- **What live does**:
  1. **Named anchors `[[# <name>]]`**: requires `[[#` followed by a horizontal space (` ` or `\t`) and a non-empty single-line name before `]]`. When `<name>` matches `^[-_A-Za-z0-9.%]+$`, live renders `<a name="<name>"></a>` (leaving a third `]` outside on `]]]`, settled by probe `muse-probe-refgaps-anchor-p16` and `test/anchor/basic`). When `<name>` is non-empty and contains characters outside that set (such as internal or extra leading/trailing spaces or `$`), live renders `[<leading-ws><a href="javascript:;"><trimmed-name></a><trailing-ws>]`, except when closed by a non-triple-link residual `]]]` (`[[# apple banana]]]`), which stays literal (`test/anchor/basic`). `[[#durian]]` (no space after `#`) and `[[# ]]` (whitespace-only name) stay literal.
  2. **Block/inline anchors `[[a ...]]...[[/a]]` and scored `[[a_ ...]]...[[/a]]`**: opener and closer tag matching is ASCII case-insensitive (`[[a]]`, `[[A]]`, `[[a_]]`, `[[A_]]`, closed by `[[/a]]` or `[[/A]]`, probe `p10`), while `[[anchor]]...[[/anchor]]`, `[[*a]]...[[/a]]`, `[[a]]...[[/anchor]]`, and a space-only opener argument region (`[[a ]]...[[/a]]`) stay literal (`p09`, `test/anchor/space-only-argument-region`). Attributes are parsed by `Text_Wiki_Parse::getAttrs` (exact `key="value"` syntax; single-quoted, unquoted, or spaced `=` forms are not separate attributes, settled by `p15`, and `"abc="` yields an empty `href`, settled by `test/anchor/href-scheme-normalized`). Attribute keys are case-sensitive lowercase except `data-*`, where the `data-` prefix must be lowercase and the suffix is lowercased (`data-X` -> `data-x`, while `DATA-X`, `CLASS`, `HREF` are dropped). The allowlist is `id` (isolated with `u-`, empty omitted), `class`, `style`, `role`, `type`, `data-*` (in authored order, empty `data-x=""` preserved), `href` (always emitted, defaulting to `href=""`), and `target`, emitted in that exact order (`test/anchor/attribute-allowlist`). Values strip non-whitespace C0 controls and DEL, collapse ASCII whitespace runs to a single space, and trim both ends; an attribute value containing a Raw token delimiter (`\xFF`) normalizes to `""` on `class`/`data-*`/verbatim `href` and to the token digits on non-verbatim `href` (`test/anchor/raw-attribute-value`). For `href`, an optional leading `*` is stripped; if the remainder starts with a verbatim prefix (`#`, `/`, `http://`, `https://`, `ftp://`, `mailto:`, `gopher://`, `news://`, `mms://`, `git://`, `sftp://`, `ssh://`, `svn://`, `telnet://`, `cvs://`), spaces are encoded as `%20`, non-ASCII bytes are uppercase percent-encoded (`p12`), and a leading `*` implies `target="_blank"` unless an explicit `target` was authored (`p11`); otherwise the remainder is normalized into a lowercased page slug with `:` or `-` separators and no implied `target="_blank"` (`test/anchor/href-scheme-normalized`, `p11`). Leading and trailing horizontal spaces inside the body are hoisted outside `<a ...>...</a>` when adjacent to non-whitespace on the same line (`test/anchor/boundary-space-moves-out`). A nested `[[a...]]` opener inside an open `[[a...]]` closes the outer `<a>` before opening the inner `<a>` and consumes a matching trailing `[[/a]]` (`test/anchor/nested-open-empty-pair-space`). Because Anchor runs at pipeline position 24, `href="http://x/a--b"` is tokenized before `Url` (position 54) and `Typography` (position 66) while the anchor body remains in `$this->wiki->source` for `Underline` (`__label__`), `Superscript` (`^^label^^`), and `Newline`, settling all three R2 sightings (`typo69`, `sup59`, `xcf3`). The scored form `[[a_ ...]]...[[/a]]` strips a single leading/trailing newline inside its body, joins adjacent lines across single or double line breaks (`p05`, `p06`, `p22-anchor-element`), and suppresses the outer `<p>` wrapper when the paragraph run ends with the scored anchor (`p03`, `p04`, `p06`, `PG-F1`).

  - `ref-php/text-wiki/Text/Wiki/Render/Xhtml/Anchor.php` (pre-correction copy preserved at `conformance-refphp/anchor/AnchorXhtml.before.php`)
  - `ref-php/text-wiki/Text/Wiki/Parse/Default/Paragraph.php` (pre-correction copy preserved at `conformance-refphp/anchor/Paragraph.php.before.php`, touched only for the `PG-F1` scored-anchor `<p>`-suppression check)

## Gap 2: The `[[ul]]` / `[[ol]]` / `[[li]]` block forms — ledger item M46 (`conformance-refphp/listblocks/`)

- **What live does**:
  1. **Tag and closer syntax**: explicit list blocks `[[ul]]...[[/ul]]` and `[[ol]]...[[/ol]]` (plus scored `[[ul_]]...[[/ul]]` and `[[ol_]]...[[/ol]]`) and item blocks `[[li]]...[[/li]]` use lowercase-only tag names (uppercase `[[UL]]`/`[[LI]]` and scored `[[li_]]` stay literal, settled by `test/list/block-score` and `lb07`). Openers with a space-only argument region (`[[ul ]]`, `[[li ]]`) and closers with internal whitespace (`[[/ul ]]`, `[[/li ]]`) or underscore (`[[/ul_]]`, `[[/li_]]`) fail to match and stay literal (`p15`, `test/list/block-spaced-end`, `test/list/block-score-nested`). `[[ul]]` must close with `[[/ul]]` and `[[ol]]` with `[[/ol]]` (`test/list/block-fail`). Standalone `[[li]]...[[/li]]` outside `[[ul]]`/`[[ol]]` stays literal (`p13`).
  2. **Attributes**: live (`muse-probe-refgaps-listblocks-p06`, `p07`) allows only `id` (isolated with `u-`, empty omitted), `class`, `style`, `role`, `type`, and `data-*` (with lowercase `data-` prefix and lowercased suffix), emitted in the order `id`, `class`, `style`, `role`, `type`, `data-*`. Live strips `title` and `hidden` on `[[ul]]`, `value` on `[[li]]` (`p06`), and `start` and `reversed` on `[[ol]]` (`p07`).
  3. **Body, nesting, table interaction, and degraded forms**: `[[li]]...[[/li]]` trims horizontal edge whitespace (`p03`), strips a single leading newline after `[[li]]`, and converts a trailing newline before `[[/li]]` into `<br />` (`lb08`). A nested `[[ul]]`/`[[ol]]` following an `[[li]]...[[/li]]` directly inside an outer `[[ul]]`/`[[ol]]` attaches inside that preceding `<li>` (`p03`), while a nested `[[ul]]`/`[[ol]]` with no preceding `[[li]]` (`p04`) or a wrapped native line-led `*`/`#` list (`p08`, `y03`, `y04`, `y09`) is wrapped in `<li style="list-style: none; display: inline">\n...\n</li>`. Running explicit list tokenization inside `List::parse()` at pipeline position 42 (right after line-led `List` and before `Table` at position 44 and `Tableadv` at position 45) collapses the multi-line `[[ul]]...[[/ul]]` block into single-line tokens before `Table` runs, so `||[[ul]]\n* one\n* two\n[[/ul]] ||` (`y03` / `lb29`), `||[[ol]]\n* one\n* two\n[[/ol]] ||` (`y04` / `lb30`), and `||[[ul]]\n[[li]]one[[/li]]\n[[li]]two[[/li]]\n[[/ul]] ||` (`p10` / `lb32`), as well as the advanced-table counterparts (`y09` / `lb31`, `p11` / `lb33`), parse as table cells without touching `Table.php` or `Tableadv.php`. Empty `[[ul]][[/ul]]`, `[[ol]][[/ol]]`, and `[[ul]][[li]][[/li]][[/ul]]` dissolve (`p12`). Non-empty `[[ul]]`/`[[ol]]` blocks with no valid `[[li]]...[[/li]]` and no nested list wrap their trimmed body in `<li style="list-style: none">...</li>` (`p13`, `p15`, `test/list/block-score`).
