Every function follows the reference's `Text_Wiki_Render_Xhtml_<Rule>::token()` in `ref-php/text-wiki/Text/Wiki/Render/Xhtml/<Rule>.php` under the harness configuration of `ref-php/harness/wiki-config.php`, which sets no `css` render configuration for any rule of this family, so each `formatConf(' class="%s"', 'css')` below evaluates to the empty string (the classes' own default is `'css' => null`). Where a PHP body falls through without returning (a `type` other than `start` / `end`), PHP concatenates the resulting `null` as the empty string and the mirror returns `[]`.

## 3. Gate procedure

The prefix the family's render comparison needs is the full pipeline's first fifty-four rules, ending at Paragraph. Justification from pipeline positions: the family's twelve rules sit at positions 3 (Delimiter), 12 (Comment), 28 (Blockquote), 31 (Horiz), 32 (Separator), 33 (Clearfloat), 34 (Break), 38 (Divalign), 41 (Note), 52 (Center), 53 (Newline), and 54 (Paragraph), so a prefix ending at the family's last rule contains them all; the parse pipeline is append-only over the token table and no parse rule edits another rule's token options (the invariant `prefix-source.php`'s header records), so a family token's options are final once its own rule has run; and the fourteen rules after Paragraph (Url through Tighten) only claim inline spans inside already-formed paragraph text, so they cannot create, remove, or reshape a prose-core token. This is the same stage-prefix pattern as the pilot's R3.6 prefix. Parse states were generated on WSL (PHP 8.5.4, scratch copy of this worktree's `ref-php/`) with `state-restricted.php` over the fifty-four names in pipeline order; expected renders were generated with `conformance-r42/render-restricted.php` over the same fifty-four names, a disclosed harness addition modeled exactly on `batch.php`'s render branch (fresh `ref_configure_wiki(new Text_Wiki($rules))` per case, Math static reset, footnote / bibliography var resets, RefPage injection with the case's tags, CRLF-to-LF input normalization) with the output carried in the R3.3 `$bytes` wire encoding, the same construction the coordinator's independently written harness used for the pilot (REPORT-R4-VERIFY.md). The full-pipeline gate uses `state-restricted.php` over all sixty-eight rules for states and the same restricted harness over all sixty-eight names for renders; as a cross-check, `batch.php render` was also run over the corpus and its 739 encodable records agree byte-for-byte with the wire-encoded renders, the sole exception being case `ga-24`, whose full render carries non-UTF-8 bytes from the Gallery machinery that plain `json_encode` cannot represent (batch.php emits an empty line there); `ga-24` is excluded in the full gate under Gallery regardless. All comparisons are byte-exact with zero normalization (`conformance-r42/compare_render.py`: driver status `ok` with equal bytes is PASS, status `excluded` is EXCLUDED with its unmirrored rules tallied, anything else is FAIL, and a driver `fatal` against a PHP ProcessException is FATAL-AGREE in the R3 protocol; no case in any run was FATAL-AGREE and no case in any run had missing token keys). Every conformance executable used was built explicitly by name in this tree immediately before the runs, per the lakefile caution.
