The new module is LeanFtml/Middle2Rules.lean, the new pipeline is pipelineR316 (61 rules), and the new driver is ConformanceR316.lean (exe lean-ftml-conformance-r316). All four rules are MIRRORED under the R3-SCOPE definition: the Lean functions build under the axiom discipline and the conformance slice is byte-exact under the canonicalization, at 189/189 corpus cases with zero exclusions, 500/500 fuzz cases on each of seeds 20261121 and 7, and the full R3.1–R3.15 regression green.

The honesty statement comes first, because it bounds the claim: no dedicated R2 live-validation stage ever ran for these four rules. The R2 campaign validated the reference against live Wikidot for the families it staged, and these four were not among them (they have no R2 batteries; the corpus below is assembled from canonical behavior and authored cases, not from live captures). This stage therefore proves Lean == reference for Divprefilter, Divalign, Note, and Gallery, and does NOT prove reference == live for them. Any future live validation of these four rules is a separate stage's work; if it ever corrects the reference, this stage's mirrors and fixtures move with it mechanically.

## Mirror design (LeanFtml/Middle2Rules.lean)

All four mirrors work on the byte form through applyByteRule, like the MiddleRules scanners. None of the four rules reads or writes document state beyond the token table (verified from the rule files and the R3.1 vars inventory: no vars entry, no class static, no superglobal), so this stage adds NO compared-state extension; the protocol is unchanged from R3.15.

Divprefilter (`/\[\[\/div\]\](\s*?)\[\[div/msi`) is a pure source rewrite claiming no tokens, mirrored as divprefilterScan with a dpTail helper that reproduces the lazy whitespace run's trial order (the `[[div` literal tried at the head first, then after each consumed whitespace byte). The replacement is the constant string `[[/div]][[div`, lower-case even for upper-case input (oracle probes dp-08/dp-09), with no closing `]]` required on the opener (dp-14) and any continuation accepted, including a scored `[[div_` (dp-21) and the `[[divx` prefix (dp-42), because the pattern ends at the prefix.

Note (`/(\n)?\[\[note\]\]\n(.*?)\[\[\/note\]\]/msi`) is mirrored as noteScan over noteMatchAt and noteBody. The optional leading-newline group is tried present first (the greedy `(\n)?`); the body runs to the first case-insensitive closer and INCLUDES the newline before it (probe nt-01: the body is "body\n", so three newlines precede the end placeholder in the replacement); the replacement is the group byte doubled, the start placeholder, `"\n\n"`, the body, `"\n\n"`, the end placeholder, and with no leading newline it begins at the start placeholder itself. A nested opener stays literal inside the outer body, which ends at the first closer (nt-11).

Gallery (`/^\[\[gallery(\s[^\]]*?)?\]\](?:((?:\n: [^\n]+)+)\n\[\[\/gallery\]\])?/msi`) is mirrored as galleryScan with the line-start flag threaded through the subject, galleryOpener, galleryLines, galleryBody, and galleryToken. The attribute group's single whitespace byte may be a newline and the group may span lines (ga-43); the lazy non-`]` run is forced to the first `]]`. The body group is tried with the maximal source-line count first, giving back whole lines (within-line backtracking is impossible, since the content class excludes the newline the closer needs). The token's options come from getAttrsBytes over the trimmed group: `size` is present, first, only when its value is PHP-truthy, so both the empty string (ga-14) and `"0"` (ga-15) are absent, and unquoted values never reach getAttrs' quoted form (ga-16); `sources` is always present, the verbatim body text (leading newline included, no trailing newline) or PHP null when the body group does not participate (ga-01, the opener-only claim). The replacement is `"\n\n"`, the placeholder, `"\n\n"`.

Divalign (`/^\[\[(=|<|>|==)\]\]\n((?:(?R)|.)*?)\[\[\/\\1\]\]$/msi`) is the pipeline's second recursive rule after Code, and is mirrored in Code's style: a mutual enumeration (divalignMatch, divalignBody) in PCRE priority order (closer tail first, then recursive units, then single bytes), a one-pass scanner (divalignScan), and the parse() fixpoint (divalignLoop) that repeats the pass until a pass claims nothing, which is how blocks nested inside a claimed body are claimed on a later pass with their tokens appended after the outer pair. The oracle probes settled four semantic points the pattern alone leaves ambiguous. First, the (?R) branch is tried before the char branch and wins even where a shorter char-only parse exists (da-45: the outer body contains the whole inner block plus a trailing line). Second, the body's initial position IS a line start, since it follows the opener's newline, so a recursive unit is available there (da-45/da-46 again). Third, mismatched closers never match (da-05/da-06) and a closer followed by trailing text defeats the match through the `$` anchor (da-12), though such a closer can be absorbed into a body that a later closer closes (da-28). Fourth, the enumeration needs char-step backtracking past a failed recursive unit: in da-34 the outer match succeeds with the inner opener as body text because the recursive unit's own closer was the one the outer match needed. Nested claim order is [outer start, outer end, inner start, inner end] (da-16), reproduced by the loop. Unlike Tableadv, no enumeration-cost problem arose in the compiled mirror (the corpus and fuzz include nesting to depth three and complete instantly); the search is the direct enumeration with codeFuel-bounded depth.

## Theorems and the kernel-reduction limit

Middle2Rules.lean carries 13 worked-example theorems, all proved by rfl and all auditing at [propext, Classical.choice, Quot.sound], none on sorryAx: three for Divprefilter (fire, upper-case-to-lower-case constant, no-fire), three for Note (no-group, group-doubling, nested-first-closer), four for Gallery (opener-only with sources null, body, size present, size "0" absent), and three structural theorems for Divalign's direct pieces (divalignTail accepting a closer at subject end, divalignTail rejecting a closer followed by text, alignName mapping `==` to justify). The grep for sorry over the new and edited Lean files finds none in Middle2Rules.lean, Pipeline.lean, or ConformanceR316.lean (the only matches in Main.lean are two pre-existing prose comments in its header that mention sorryAx).

One limit is stated plainly, with its measurement: Divalign's enumeration does not reduce in the kernel at usable cost. A scanner-level rfl theorem exhausts memory during elaboration, and so does a single divalignMatch on a 14-byte input at the hand-set fuel 8, while the compiled evaluation of the same calls is instant and correct (divalignMatch on the basic example evaluates to exactly the expected singleton, and the body parse count is 1). This is the same wall Code's enumeration met in R3.1, which likewise carries no worked-example theorems, and the same disposition Tableadv took in R3.10: the enumeration's evidence is the exhaustive conformance corpus and the fuzz, and the theorems cover the structural pieces that do reduce.
