## Verdicts

- L1 (quoted deletion): PARITY, both branches. Spaced quoted includes are literal blockquote text on live and pass through ftml unchanged (scanner adjacency: the regex `^(?:[ \t]*>)*\[\[ include\s+` allows no space between the last `>` and `[[`). Unspaced quoted includes are silently deleted by BOTH (live: lines absent from the render entirely; ftml: range consumed, never fetched, pages list empty). The Q1 adjacency condition was added to GRAMMAR-INCLUDE.md; the earlier unqualified statement of Q1/Q2 was incomplete, not wrong about the mechanism.
- L2 (stray brackets): PARITY. Live inlines with substitution ("Value is STRAYOK."); ftml output identical in structure.
- L3 (next-line page ref): ftml accepts and includes. Live save-normalizes the source to the one-line form (captured stored source proves the rewrite), so the split form never reaches live's parser via saved pages. Acceptance stands as specified.
- L4 (uppercase INCLUDE): same shape as L3. Live save-normalizes to lowercase; ftml includes the raw uppercase form.

No finding: no live/ftml divergence in L1-L4, so nothing to route. Still owed for G1.4 PROVEN: the Lean model of the scanner + block grammar + quoted normalization, and the Lean-side fragment differential driver (the Rust half now exists as rust-dump; the grid above is its first 13 cases).

## Addendum 2026-11-20: the fragment differential is GREEN

- Lean side: `lean-ftml/ConformanceG14.lean` (exe `lean-ftml-conformance-g14`), a fragment implementation of `include()` built on the proved model functions (`scanPrefix`, `startsWithCI`, `findIncludeEnd`, `stripGt`, `origOffset`, `parsePageRef`, `parseSiteRef`, `separated`, `splice`) plus driver glue for the parts no theorem covers yet (scanner loop, segment scanning, reference resolution, substitution loop). The Rust dumper's page map was extended to match the driver's `fetchContent` exactly (`other-page`, `empty-page`, `:sandbox:other-page` added).
- Grid: `grid.jsonl` from `gen_grid.py`, 114 cases across opener forms, terminator forms, page references and normalization, argument segments (comments, stray brackets, trims, inert segments, duplicates), quoted includes (spaced/unspaced, depths, continuations, deletions), multiple includes, and padding/CRLF interactions. `compare.py` checks exact equality of output and pages.
- **Verdict: 114/114 cases agree**, with the Lean driver built on the VM and, independently, on WSL (outputs recorded in `lean-out.jsonl`, `lean-out-wsl.jsonl`, `rust-out.jsonl`).

What the differential caught, and how each was settled:

1. **Grammar terminator is wider than the candidate scan.** `[[include T]]\rX`: the block parse succeeds at the `]]` because pest's NEWLINE includes a lone `\r`, while `find_include_end` does not accept one and steps over. First run 98/99, this case the only mismatch. Settled from the grammar + mod.rs control flow (on success the scan resumes at the parsed end); the driver computes the block end with the grammar's terminator (`gramTermEnd`) and keeps `findIncludeEnd` for the resume/bound role. Recorded in GRAMMAR-INCLUDE.md G1.
2. **The model's page class was wrong for colon-bearing names.** IncludeGrammar's `isPageC` excluded `:`, but grammar.pest's `page_name` allows it (only `site_name` excludes it). Fixed in the model: `isSiteC` is the old class, `isPageC` is now the true page class, and `parseSiteRef` was redefined to the real `:site:` shape with a new `parseSiteRef_spec`. Green on VM and WSL; `parsePageRef_spec` [propext], `parseSiteRef_spec` [propext, Quot.sound], no sorry.
3. **Reference resolution is a real layer.** `PageRef:: parse_include` trims, rejects `:foo` / `::page` / empty normalized pages, splits the page at `#`/`/` into an undisplayed extra (`page/edit` fetches `page`), canonicalizes dotted host sites, and slug-normalizes via wikidot-normalize 0.12.0; the Display form `:{site}:{page}` is the includer key. Now specified as GRAMMAR-INCLUDE.md R1–R5 and modelled in the driver for ASCII (`normalizeSlug`).

Fragment bounds (unchanged): argument values in the grid are literal (no `{$...}` references in keys or values; the one duplicate-key case agrees under first-wins for static arguments) — the expansion layer is G1.4b. Page references are ASCII; Unicode NFKC/case folding in `normalize` is modelled only for ASCII inputs.

## Addendum 2026-11-21 (G14B-FIX): segment scanning corrected to live's raw pipe split

The AUDIT lane's live probes (muse-probe-audit-g14b-cmt-pipe, muse-probe-audit-g14b-cmt-unclosed) refuted the comment-aware segment split that both this driver and ftml's parse.rs implemented: live splits the argument tail on raw `|` bytes, a pipe inside a comment splits there, and an unterminated comment is ordinary text that cannot fail the block. The driver's splitSegments is now a plain raw split (GRAMMAR-INCLUDE.md G4/G5 corrected; record REPORT-G14B-FIX.md at the loop root). Grid consequence: 119/119 before, 117/119 after, against ftml at 97bed049d (rust-out-1531.jsonl; outputs lean-before-g14bfix.jsonl and lean-after-g14bfix.jsonl). The two moved cases, arg-comment-pipe and arg-unterminated-comment, are exactly the comment-tail shapes: the Lean side now follows live, so the grid records a two-case Lean/ftml divergence on shapes where live is settled by the audit probes. That is the correction's expected signature, not a regression.
